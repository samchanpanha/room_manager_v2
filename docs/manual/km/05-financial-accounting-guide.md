# ផ្នែក ៥ — ក្រមណែនាំហិរញ្ញវត្ថុ និងគណនី

សរសេរសម្រាប់អនកដែលដំណើរការប្រាក់ — ហើយសម្រាប់ Managers ដែលចង់យល់វា។
មិនត្រូវការផ្ទៃខាងក្រោមផ្នែកគណនីទេ៖ ពាក្យ foreach ត្រូវបានពន្យល់ នៅក្នុងភាសាសាមញ្ញ។

---

## 5.1 គំនិតតែមួយ ក្រោយពីបញ្ជី

រាល់ពេលប្រាក់ផ្លាស់ទី ប្រព័ន្ធសរសេរ **ចំណុចតុល្យពីរ** (double-entry
កំណែ "ស្រាល")។ ក្បួនដែលមិនដែលបំផ្លាញ៖

> **សរុបប្រាក់បង់ (debits) = សរុបប្រាក់ទទួល (credits) ជានិច្ច។** នេះត្រូវបាន
> ព្រមព្រៀង ដោយ database សេវាកូដ និងតេស្តដ្រត្រា។ ការចុះមិនតុល្យ ត្រូវបានបដិសេធ។

បញ្ជី ជា **append-only** — អ្នកមិនអាចធ្វើទំនើបកម្ម លុបចំណុចដែលបានចុះ
(database បង្កលỗi)។ កំហុសត្រូវបានកែតម្រូវ ដោយចំណុច **ការរំលំ (reversal)**
ដែលភ្ជាប់ត្រឡប់ទៅដើម — ដូច្នេះប្រវត្តិពេញលេញ ជានិច្ចនិយាយពិត។

### ពាក្យភាសាសាមញ្ញ
| ពាក្យ | អត្ថន័យនៅទីនេះ |
|---|---|
| **Debit / Credit** | ទ្រង់ទ្រាយទាំងពីរ របស់ចំណុច foreach។ កុំគិត "ល្អ/អាក្រក់" — គិត "ខាងឆ្វេង/ខាងស្តាំ"។ ប្រាក់ចូល vs ប្រាក់ដែលត្រូវ/បានរក។ |
| **គណនី (Account)** | ធលប ដែលប្រព័ន្ធទាញ (Cash, Bank, Rent Receivable, Revenue…)។ |
| **បញ្ជី (Ledger)** | សៀវភៅនៃចំណុចទាំងអស់ ឆ្លងគណនីទាំងអស់។ |
| **Journal** | បញ្ជីលំដាប់ពេលវេលា នៃចំណុច (browser នៅ **Finance → Ledger**)។ |
| **Trial balance** | ការពិនិត្យ ថា debits ទាំងអស់ ស្មើ credits ទាំងអស់ (គួរស្មើសូន្យ)។ |
| **ប្រាក់រង់ចាំ (Receivable)** | ប្រាក់ ដែលសមាជិក**ត្រូវ**អ្នក (ទ្រពយ) រហូតដល់ពួកគេបង់។ |
| **ចំណូល (Revenue)** | ប្រាក់ដែល**បានរក** (ថ្លៃជួល សេវា ទឹកអគ្គិសនី ប្រាក់សោភ័ណ)។ |
| **ចំណាយ (Expense)** | ប្រាក់**ចាយ** ដើម្បីប្រតិបត្តិការ។ |
| **ទ្រព្ (Asset)** | អ្វីដែលអ្នករក្សាទុក (ប្រាក់សាច់ ធនាគារ អ្វីដែលសមាជិកត្រូវ)។ |
| **ប្រាក់រំលង (Liability)** | អ្វីដែលអ្នក**ត្រូវអ្នកផ្សេង** (ប្រាក់កក់ដែលរក្សាទុក ការបង់ម្ចាស់ដែលត្រូវបង់ ពន្ធ)។ |
| **សមាជិកភាព (Equity)** | ការចុះរបស់ម្ចាស់ / ការបំណែងចែករបស់ម្ចាស់។ |

## 5.3 ព្រឹត្តិការណ៍ប្រាក់ foreach ចុះអ្វី

### (a) វិក្កយបត្រត្រូវបាន issue
សមាជិកត្រូវបានគណនាប្រាក់។ ឥឡូវអ្នក**ត្រូវ**ប្រាក់នោះ ហើយអ្នក**បានរក**
ចំណូល៖

| | Debit | Credit |
|---|---|---|
| Rent Receivable (1300) | ↑ ចំនួនគណនា | |
| គណនីចំណូល (4000 rent / 4100 service / 4200 utility / 4300 late fee / 4900 one-time) | | ↑ បានរក |
| Tax Payable (2300) — បើមានពន្ធ | | ↑ ពន្ធ |
| **វិក្កយបត្រប្រាក់កក់** ជំនួសគ្នា credit **Deposit Liability (2100)** — ប្រាក់កក់ *មិនមែន* ចំណូល។ |

```
DR 1300 Rent Receivable      350.00
   CR 4000 Rent Revenue              300.00
   CR 4100 Service Revenue            15.00
   CR 4200 Utility Revenue            35.00
```

### (b) សមាជិកបង់វិក្កយបត្រ
Cash/Bank កើនឡើង; ប្រាក់រង់ចាំ ត្រូវបានសម្អាត៖

```
DR 1100 Cash (or 1200 Bank)  350.00
   CR 1300 Rent Receivable           350.00
```

**ជាភាសាសាមញ្ញ៖** *ប្រាក់សាច់នៅដៃ កើនឡើង; ចំនួនដែលសមាជិក ត្រូវបង់ ថយចុះ។*

### (c) ប្រាក់សោភ័ណអនុវត្ត (បន្ទាប់ពីរការ)
```
DR 1300 Rent Receivable       10.00
   CR 4300 Late Fee Revenue           10.00
```

### (d) ប្រាក់កក់ត្រូវបានប្រមូល
ប្រាក់កក់ ជាប្រាក់ដែលរក្សាទុក (ប្រាក់រំលង) **មិនមែន** ចំណូល៖
```
DR 1100 Cash                 300.00
   CR 2100 Deposit Liability          300.00
```
នៅពេលចាកចេញ ការកាត់ (ខូចខាត/សុប្បកម្ម) ដោះលែងផ្នែក ទៅ **4900 Other Revenue**
ឬសម្អាតប្រាក់រង់ចាំមិនទាន់បង់; ការត្រឡប់ **debit 2100** ហើយ **credit Cash/Bank**។
សម្រាប់កិច្ចសន្យាជួលដែលបានបិទ 2100 របស់កិច្ចសន្យាជួលនោះ ត្រូវស្មើ **0**។

### (e) ចំណាយត្រូវបានកត់ត្រា និងបង់
```
DR 5000 Operating Expenses    80.00
   CR 1100 Cash (or 1200 Bank)        80.00
```

### (f) របាយការណ៍ម្ចាស់ បានអនុម័ត បន្ទាប់មកបង់
ការអនុម័ត រំងល់ចំនួនដែលត្រូវបង់ម្ចាស់៖
```
DR 3900 Owner Distributions   500.00
   CR 2200 Owner Payable              500.00
```
ការបង់ម្ចាស់ សម្អាតប្រាក់ដែលត្រូវបង់៖
```
DR 2200 Owner Payable         500.00
   CR 1100/1200 Cash/Bank             500.00
```
(Owner Payable ស្រងត្រឡប់ទៅតម្លៃពីមុន បន្ទាប់ពីបង់។)

### ការកែតម្រូវ
- **Void ចំណាយ** → ចំណុចការរំលំ (ដើមនៅសល់ ការរំលំ លុបវាចេញ)។
- **Credit note នៅលើវិក្កយបត្រ** → រំលំចំនួនដែលបានគណនា (បញ្ចប់ដ្រត្ានៅសូន្យ)។
- **ត្រឡប់ការទូទាត់** → រំលំប្រាក់សាច់ និងប្រាក់រង់ចាំ (ការអនុម័ត Accountant+)។
- ជួរដែលបានចុះ មិនអាចកែ/លុបបាន ទេ — database បិទវា។

## 5.4 កន្លែងមើលគណនី
- **Finance → Ledger [M08]៖** **journal browser** (ត្រាស់តាមគណនី ហេតុ ការយោង
  អចលនទ្រពយ/សមាជិក) និង **trial balance**។ ការចូល Admin/Accountant។
- **Statement សមាជិក** (`Members → [member] → statement`, ឬ portal)៖
  **ប្រាក់រង់ចាំប្រចាំ** សម្រាប់សមាជិកម្នាក់។ សមាជិកមើលតែផ្ទាល់ខ្លួន។
- **តម្លៃបើក (Opening balances)៖** កំណត់នៅ **Settings → Opening balances**
  ជា `opening` postings ដែលតុល្យ នៅពេលអ្នកចល័តចូលប្រព័ន្ធរបស់អ្នកដំបូង។

> ក្បួនដូចន័យប្រាក់ (ពីគម្រោង): ចំនួនដឺក្រីមិណីម៉ូ មួយរូបិយប័ណ្ណ ក្នុងមួយ
> អង្គភាព, Σ debits = Σ credits, គ្មានការលុប, ការបែងចែកបូកសរុប ស្មើការទូទាត់,
> webhooks ដ៏ដូចគ្នា, និងការកំណត់ហិរញ្ញវត្ថុ អនុវត្ត **ទៅមុខតែ**
> (ប្រវតតិដែលបានចុះ មិនដែលដីវិញ)។

## 5.5 ប្រាក់បៀត និងបាត់ (P&L)

**គោលបំណង៖** បង្ហាញថា អាជីវកម្ម បានប្រាក់បៀត ឬបាត់ នៅក្នុងរយៈពេលមួយ។

```
REVENUE (income accounts 4000–4900)
   Rent + Services + Utilities + Late fees + Other (incl. POS sales)
− EXPENSES (accounts 5000–5100, operating costs)
− OWNER PAYOUTS  (per contract model)
= NET PROFIT / LOSS
```

- រកឃើញ នៅ **Finance → Expenses & P&L [M20]** និងជា **Profit & Loss** របាយការណ៍ [M26]។
- មាន **ក្នុងមួយអចលនទ្រពយ** ឬ **សរុប**។
- វា**អានបញ្ជី** ហើយសមកាល តុល្យ↔បញ្ជី ត្រឹមត្រូវ (សរុប P&L
  ដូចគ្នាទៅនឹងសរុបបញ្ជី តាមរចនាសម្ព័ន្ធ)។
- ប្រៀបធៀប **រយៈពេលបច្ចុប្បន្ vs មុន**; ភ្ជាប់វាជាមួយរបាយការណ៍
  **Expense vs budget** ដើម្បីមើលប្រភេទ លើស/ខ្វះ budget។

**ឧទាហរណ៍សាមញ្ញ (អចលនទ្រពយមួយ ខែមួយ)៖**

| | ចំនួន |
|---|---|
| ចំណូលថ្លៃជួល | 9,000.00 |

## 5.6 Balance Sheet

> 🚫 **មិនបានបញ្ជាក់ ជាអេក្រង់របាយការណ៍ដាច់ដោយឡែក នៅក្នុងបរព័ន្ជាបចចុប្បន្ន។**
> គ្មានមុខ "Balance Sheet" ក្នុងចំណោមរបាយការណ៍ 13។ ទោះយ៉ាងណា **តម្លៃគ្រឹះ
> ទាំងអស់ មាន** ពីបញ្ជី នៅ **Finance → Ledger → Trial balance** ប្រើកូដ
> គណនីថេរ។ អ្នកអាចអាន position balance sheet ពី trial balance ដូចខាងក្រោម៖

```
ASSETS
   1100 Cash            + 1200 Bank           (cash position — also a dashboard KPI)
 + 1300 Rent Receivable (money members owe)
= TOTAL ASSETS

LIABILITIES
   2100 Deposit Liability  (deposits held)
 + 2200 Owner Payable      (owners due)
 + 2300 Tax Payable        (tax collected)
= TOTAL LIABILITIES

EQUITY
   3900 Owner Distributions  (debit-balance equity account)
 + retained earnings (revenue 4xxx − expenses 5xxx to date)
= TOTAL EQUITY

Why it balances: every entry posts equal debits and credits, so
TOTAL ASSETS = TOTAL LIABILITIES + TOTAL EQUITY  — always.
The trial balance nets to zero, which is the same statement.
```

- **Cash position** (1100 + 1200) ជា **KPI dashboard** ពិត។
- **Arrears** នៅលើ dashboard ≈ 1300 Rent Receivable ដែលកំពុងបើក។
- **Deposit Liability (2100)** គួរមានទិសដៅទៅសូន្យ ចំពោះកិច្ចសនយាជួល foreach ដែលបានបិទ។

## 5.7 របាយការណ៍ម្ចាស់ (M24) — ការបង់ម្ចាស់

**គោលបំណង៖** ប្រាប់ម្ចាស់ផ្ទះ foreach ក្នុងមួយខែ ថា បានរកអ្វីពីអគាររបស់ពួកគេ
ហើយពួកគេត្រូវបានបង់អ្វី។

**ការគណនា (ជាភាសាសាមញ្ញ)៖**
1. ចាប់ផ្ដើមពីប្រាក់ **ដែលបានប្រមូលពិត** សម្រាប់គ្រប់គ្រងរបស់ម្ចាស់។
2. អនុវត្តម៉ូឌែលកិច្ចសន្យា៖
   - **REVENUE_SHARE៖** គុណចំនួនដែលបានប្រមូល ដោយ **share %** របស់ម្ចាស់ (ឧ. 60%)។
   - **FIXED_RENT៖** ប្រើ **ថ្លៃជួលម៉ាស្ទ៊រខែ** ដែលបានព្រម។
3. **ដក** **ហាមគ្រប់គ្រង**, **ចំណាយ pass-through** និង
   **ការជួសជុលដែលម្ចាស់សង** (ពីសំបុត្រដែលបញ្ជូនទៅម្ចាស់)។
4. **បូក/ដកការកែសម្រួលដែលបានអនុម័ត** (ត្រាត្រួតពិនិត្យ)។
5. លទ្ធផល = **ការបង់ម្ចាស់សុទ្ធ**។

```
Collected rent for owner's units
   × share %   (or fixed master rent)
 − management fee
 − pass-through expenses
 − owner-borne maintenance
 ± audited adjustments
 = NET OWNER PAYOUT
```

**ដំណើរការ៖** បង្កើត (idempotent ក្នុងមួយកិច្ចសន្យា+ខែ; គោរពថ្ងៃបង់) →
`draft → approved → paid`។ ការអនុម័ត ចុះ DR 3900 / CR 2200; ការបង់ ចុះ
DR 2200 / CR cash|bank។ របាយការណ៍ **PDF** ត្រូវបានរក្សាទុកដ្រតរា ហើយបង្ហាញ
នៅ portal របស់ម្ចាស់។ ការបង្កើត ត្រូវការ **Accountant+ (GLOBAL M24:update)**។

## 5.8 ក្បួនដំណើរការប្រាក់ ដែលត្រូវចងចាំ
1. **កុំលុប** វិក្កយបត្រ ការទូទាត់ ចំណាយ ឬចំណុចបញ្ជី ដែលបានចុះ ទេ — ប្រើ void/refund/reverse។
2. **ប្រាក់កក់មិនមែនជាចំណូល** រហូតដល់ការកាត់ ដោះលែងវាដោយសមរម្យ។
3. **ការបង់លើស ក្លាយជា member credit** មិនមែនជាចំណូលទេ។
4. **វិក្កយបត្រដែលបាន issue ជា immutable** — កែតម្រូវ ដោយ credit notes; តែ Super Admin void (ជាមួយមូលហេតុ)។
5. **ការត្រឡប់ ត្រូវការការអនុម័ត Accountant+** ហើយរំលំបញ្ជី។
6. **ការកំណត់ហិរញ្ញវត្ថុ អនុវត្តទៅមុខតែ** — ការផ្លាស់ប្ដូរ ក្បួនប្រាក់សោភ័ណ/ពន្ធ/ការគណនាប្រាក់ មិនដែលដីវិញ វិក្កយបត្រដែលបានចុះ។
7. នៅពេលលេខ ហាក់ដូចមិនត្រឹមត្រូវ **កុំកែតម្រូវដោយដៃ** — តាមតាមរយៈ **Audit log** និង **Ledger journal** បន្ទាប់មកប្រើការរំលំត្រឹមត្រូវ។
