# ផ្នែក ១ — ទិដ្ឋភាពទូទៅនៃប្រពន្ធ

## 1.1 នាមប្រពន្ធ

កម្មវិធីនេះមានឈ្មោះថា **RentManager** (ឈ្មោះ package `rentmanager`)។ នេះជា
**ប្រពន្ធប្រតិបត្តិការអចលនទ្រព្យជួល និងរួមជីវិត** សម្រាប់មចាស់ផ្ទះ អ្នកគ្រប់គ្រង
អចលនទ្រពយ និងក្រុមរបស់ពួកគេ។

វាដំណើរការជាអនុវត្តកម្ម web (Next.js)។ កម្មករប្រើវាតាម browser មាត់កុំព្យូទ័រ
(back office) ចំណែកអ្នកជួល និងម្ចាស់ប្រើវាតាមទូរស័ព្ទ តាមរយៈ **Tenant Portal**
និង **Owner Portal**។ ក៏មាន **Telegram bot** សម្រាប់ការជូនដំណឹង និងសំណួររហ័សផងដែរ។

## 1.2 គោលបំណង — អ្វីដែលប្រព័ន្ធគ្រប់គ្រង

RentManager ដំណើរការអាជីវកម្មអចលនទ្រព្យជួល / រួមជីវិត **ពីដើមដល់ទីបញ្ចប់** ចាប់ពី
អគាររូបវន្ត រហូតដល់ការបង់ប្រាក់ប្រចាំខែរបស់ម្ចាស់៖

- **សារពត៌មានអចលនទ្រព្យ** — អចលនទ្រព្យ → អគារ → ជាន់ → បន្ទប់ → គ្រែ។
- **មនុស្ស** — សមាជិក (អ្នកជួល/អ្នកសនាក់), ម្ាស់ (landlord), អ្នកប្រើកម្មករ, អ្នកផ្គត់ផ្គង់។
- **កិច្ចសន្យា** — កិច្ចសនយាជួលសមាជិក (កិច្ចសន្យាស្នាក់) និងកិច្ចសន្យាម្ចាស់ (ព្រមព្រៀងគ្រប់គ្រង)។
- **ការគណនាប្រាក់** — វិក្កយបត្រថ្លៃជួល ប្រាក់សេវា និងទឹកអគ្គិសនីប្រចាំខែ ដែលបង្កើតដោយម៉ាស៊ីនគណនាថ្លៃជួល។
- **ការប្រមូល** — ការទូទាត់ដោយប្រាក់សាច់ ការបញ្ជូនប្រាក់នាគារ QR កាត ឬឯកសារ ជាមួយប័ណ្ទូទាត់មានលេខ។
- **ប្រាក់កក់** — ប្រាក់កក់ដែលបានគណនា រក្សាទុក កាត់ និងត្រឡប់វិញ។
- **ប្រតិបត្តិការ** — ការផ្លាស់បន្ទប់ ការត្រួតពិនិត្យ សំបុត្រការជួសជុល ការតវ៉ា ការវត្តមានកម្មករ។
- **ហាង** — ចំណុចលក់ (POS) និងការគ្រប់គរងស្តុក/សម្ភារៈ។
- **ហិរញ្ញវតថុ** — បញ្ជីគណនេយ្យ double-entry ដែលមិនអាចកែប្រែ ចំណាយ ថវិកា ចំណេញ-ខាត (P&L) របាយការណ៍ម្ចាស់។
- **សេវាដោយខ្លួនឯង** — ខ្លោងទ្វារអ្នកជួល (បង់ថ្លៃជួល បងើបសំបុត្រ ូតឯកសារ) និងខ្លោងទ្វារម្ចាស់។
- **ការជូនដំណឹង** — ក្នុងកម្មវិធី ការព្យាបាលផ្ទាំងគ្រប់គ្រង និង Telegram bot (ប័ណ្ ការជ្រើស របាយការណ៍)។
- **ការគ្រប់គ្រង** — សិទ្ធិដោយតួនាទីលើទំព័រ និងការហៅ API រាល់ផ្ទាំង កំណត់ត្រាត្រួតពិនិត្យ 2FA របាយការណ៍។

### អ្នកណាប្រើវា

| អ្នកប្រើ | កន្លែងធ្វើការ | អ្វីដែលពួកគេធ្វើ |
|---|---|---|
| Super Admin / Admin | កុងសូលអ្នកគ្រប់គរង | កំណត់ប្រព័ន្ធូលដ្ឋាន អ្នកបរើ តួនាទី ការកំណត់ សុវត្ថិភាព |
| អ្នកគ្រប់គរងអចលនទ្រព្យ | កុងសូលអ្នកគ្រប់គ្រង | ដំណើរការអចលនទ្រពយដែលបានចែកចាយ៖ បន្ទប់ កិច្ចសនយាជួល ប្រតិបត្តិការ ការអនុម័ត |
| គណនី | កុងសូលអ្នកគ្រប់គរង | ម៉ាស៊ីនថ្លៃជួល វិក្កយបត្រ ការទូទាត់ ប្រាក់កក់ បញ្ជីគណនេយ្យ របាយការណ៍ម្ចាស់ |
| កម្មករ / ធម្មការ / មាត់កម្ម | កុងសូលអ្នកគ្រប់គ្រង (កំណត់ខណ្ឌវិមាត) | ចុះសមាជិក កិច្ចសន្យាជួល គណនាប្រាក់ ប្រមូលប្រាក់ POS សំបុត្រ ការវត្តមាន |
| ម្ចាស់ (landlord) | ខ្លោងទ្វារម្ចាស់ | មើលអគារ ការសណ្ឋាគារ របាយការណ៍ និងឯកសារផ្ទាល់ខ្លួន (អានតែ) |
| សមាជិក (អ្នកជួល) | ខ្លោងទ្វារអនកជួល + Telegram | មើលវិក្កយបត្រ បង់តាម QR បងើបសំណើ ឡូត KYC ស្ថានភាពប្រាក់កក់ |

### បញ្ហាអាជីវកម្មដែលវាដោះស្រាយ

- **គ្មានអវីរំលង** — បន្ទប់ កិច្ចសន្យាជួល វិក្កយបត្រ និងសំបុត្រ ទាំងអស់មានស្ថានភាព និងប្រវតតិ។
- **ថ្លៃជួលត្រូវបានគណនាដ្រត្ា និងត្រឹមត្រូវ** — ការប្រកាន់សម្រាប់ការផ្លាស់ចំកណ្ដាលខែ ប្រាក់សោភ័ណ ការហៅបង់។
- **ប្រាក់តែងតែតាមដានបាន** — វិក្កយបត្រ ការទូទាត់ ការត្រឡប់ និងចំណាយរាល់ផ្ទាំង ចុះបញ្ជី double-entry តុល្យ។ អ្វីដែលបានចុះ មិនអាចលុបបានទេ។
- **ការប្រមូលងាយស្រួលសម្រាប់អ្នកជួល** — បង់តាម QR ខ្លោងទ្វារអ្នកជួល ប័ណ្ Telegram។
- **មចាស់ទទួលបានរបាយការណ៍ប្រចាំខែធម្តា** — ថលៃជួលដែលបានប្រមូល × ភាគហាង (ឬថ្លៃជួលថេរ) ដកហាម និងថ្លៃដើម។
- **មនុស្សត្រូវបានមើលអ្វីដែលត្រូវ** — កម្មករកំណត់ត្រឹមអចលនទ្រព្របស់ពួកគេ។ សមាជិក និងម្ចាស់មើលតែកំណត់រឿងផ្ទាល់ខ្លួន។

## 1.3 ផែនទីម៉ូឌូល (បញ្ជីម៉ូឌូលពិត)

ប្រព័ន្ធសិទ្ធិត្រូវបានសាងសង់ពី **ម៉ូឌូល ៣១** មួយៗមានកូដ។ នេះជា
បញ្ជីពិតដែលប្រើដោយទំព័រ តួនាទី និងសិទ្ធិ និងម៉ឺនុយ។

| កូដ | ម៉ូឌូល | ទំព័រម៉ឺនុយ | គោលបំណងមួយជួរ |
|---|---|---|---|
| M01 | អ្នកប្រើ និង RBDC | **Users**, **Roles & Permissions**, **Audit Log** | គណនីកម្មករ តួនាទីដ្រាម៉ាទិច ក្តារសិទ្ធិ ប្រវត្តិត្រាត្រួតពិនិត្យ |
| M02 | សមាជិក | **Members** | ព័ត៌មានអ្នកជួល/អ្នកស្នាក់ KYC វដ្តជីវិត |
| M03 | ម្ចាស់ | **Owners** | កំណត់រឿងម្ចាស់ផ្ទះ និងវិធីបង់ |
| M04 | អចលនទ្រព្ និងបន្ទប់ | **Properties** | សារពត៌មាន អចលនទ្រព្ → អគារ → ជាន់ → បន្ទប់ → គ្រែ |
| M05 | កិច្ចសន្យាជួល | **Leases** | កិច្ចសន្យាជួលសមាជិក និងកិច្ចសន្យាមចាស់ ការបើកប្រើ ការបញ្ចប់ |
| M06 | ម៉ាស៊ីនថ្លៃជួល | **Rent Engine** | ក្បួនការគណនាប្រាក់ (ផែនការ ប្រាក់សោភ័ណ ពន្ធ ការកាត់) |
| M07 | វិក្កយបត្រ | **Invoices** | ប្រាក់ប្រចាំខែ៖ ថលៃជួល សេវា ទឹកអគ្គិសនី មួយដង |
| M08 | បញ្ជីគណនេយ្យ | **Ledger** | គណនេយ្យ double-entry មិនអាចកែប្រែ (journal, trial balance) |
| M09 | ការទូទាត់ | **Payments** | ប្រមូលប្រាក់ប្រឆាំងវិក្កយបត្រ។ ប័ណ្ទូទាត់។ ការត្រឡប់ |
| M10 | ប្រាក់កក់ | **Deposits** | ប្រាក់កក់៖ គណនា រក្សាទុក កាត់ ត្រឡប់ |
| M11 | ទឹកអគ្គិសនី | **Utilities** | ម៉ែត្រ (អគ្គិសនី/ទឹក/ឧស្ម័ន) ការអាន តារីហ្វ ថ្លៃ |
| M12 | សេវាកម្ម | **Services** | កាតាឡុកបន្ថែម (WiFi ជម្រករថយន្ត បរអប់សម្ាប) ការចែកចាយ ការប្រើ |
| M13 | ការទូទាត់ QR | *(គ្មានម៉ឺនុយ — នៅលើវិក្កយបត្រ foreach + `/pay`)* | ដំណើរការបង់តាម QR និង webhook របស់ payment gateway |
| M14 | POS | **POS**, **POS Catalog** | ការលក់តាមបម្រុង វដ្ដកាស៊ែរ ផលិតផល |
| M15 | ស្តុក | **Stock** | សម្ភារៈ៖ ចលនា ការរាប់ស្តុក អ្នកផ្គត់ផ្គង់ ការវាយតម្លៃ |
| M16 | ការផ្លាស់បន្ទប់ | **Room Moves** | ផ្លាស់សមាជិករវាងបន្ទប់ ជាមួយការកែសម្រួលប្រកាន់ |
| M17 | ឯកសារ | *(ក្នុងសមាជិក ម្ចាស់ វិក្កយបត្រ…)* | វគ្គកំណត់ឯកសារ ការឡូត PDF បង្កើត តំណាញ់ទាញយកមានហត្ថលេខា |
| M18 | ការត្រួតពិនិត្យ | **Inspections** | បញ្ជីផ្ទៀងផ្ទាត់ស្ថានភាពបន្ទប់ ចូល/ចាកចេញ/ប្រចាំរយៈពេល |

## 1.4 របៀបដែលប្រពន្ធប្រតិបត្តិការ — វដ្តជីវិតដើមទៅដល់ទីបញ្ចប់

ព័ត៌មានហូរក្នុងទិសមួយ៖ **ពិភពរូបវន្ត → កិច្ចសន្យា → ការគណនាប្រាក់ →
ប្រាក់ → គណនេយ្យ → របាយការណ៍ → ម្ចាស់**។

```
 Sign in
   │
   ▼
 Dashboard (occupancy, collected vs billed, arrears, cash, alerts)
   │
   ▼
 Property → Building → Floor → Room (set price & status)        [M04]
   │
   ▼
 Owner + Owner Contract (fixed rent OR revenue share %)         [M03, M05]
   │
   ▼
 Member profile + KYC documents (prospect → verified)           [M02, M17]
   │
   ▼
 Lease on a room (draft → active)                               [M05]
   │        ├── room becomes "occupied", member becomes "active"
   │        ├── deposit billed (installment invoices)           [M10]

 Monthly billing job runs                                       [M06, M07]

   │        − discounts + tax + late fees  =  Invoice (issued, gapless number, PDF)
   │

 Member pays (QR in portal / cash / bank / card / cheque)       [M09, M13]

   │        ├── invoice flips to partial_paid → paid
   │        └── overpayment stays as member credit
```

**ក្បួនមាស៖** ប្រាក់ហិរញ្ញវត្ថុមិនត្រូវបានលុបទេ គ្រប់ពេល។ វិក្កយបត្រដែលចេញហើយ
ត្រូវបានកែតម្រូវដោយ **credit note**។ ចំណុចបញ្ជីខុសត្រូវបានរំលំដោយ
**reversal**។ ចំណាយដែលបង់ហើយត្រូវបាន **void** (ដែលរំលំវា)។ នេះរក្សា
ស្ថានភាពគណនេយ្យតុល្យ និងប្រវត្តិពេញលេញអាចត្រាត្រួតពិនិត្យបាន។

## 1.5 ទំនាក់ទំនងសំខាន់រវាងម៉ូឌូល

- **អចលនទ្រព្** មួយមាន **អគារ** ច្រើន។ អគារមួយមាន **ជាន់** ច្រើន។ ជាន់មួយ
  មាន **បន្ទប់** ច្រើន។ បន្ទប់មួយអាចមាន **គ្រែ** ច្រើន។ ប្រហែលអ្វីទាំងអស់
  ផ្សេងទៀត ចាញ់លើអចលនទ្រពយ/បន្ទប់។
- **អគារ** មួយ ជាម្ចាស់របស់ **ម្ចាស់** មួយ ដែលបញ្ជាក់ដោយ **កិច្ចសនយាម្ចាស់** បើកមួយ (`M05`)។
- **សមាជិក** មួយ ចុះហត្ថលេខា **កិច្ចសន្យាជួល** សម្រាប់បន្ទប់/គ្រែ។ ការបើកប្រើ
  កិច្ចសន្យាជួល ផ្លាស់ប្ដូរស្ថានភាពបន្ទប់ទៅ *occupied* និងសមាជិកទៅ *active*។
- **កិច្ចសន្យាជួល** ចល័ត **វិក្កយបត្រ** (តាមរយៈម៉ាស៊ីនថ្លៃជួល) ផ្ទុក **ប្រាក់កក់**
  ហើយអាចមាន **សេវាកម្ម** និង **ម៉ែត្រទឹកអគ្គិសនី** ភ្ជាប់។
- **វិក្កយបត្រ** ត្រូវបានបង់ដោយ **ការទូទាត់** ដែលបែងចែកទៅវិក្កយបត្រ
  (ពីចាស់ទៅថ្មី)។ ទាំងពីរចុះក្នុង **បញ្ជីគណនេយ្យ**។
- **ប្រាក់កក់** ស្ថិតក្នុងគណនីប្រាក់រំលង (មិនមែនចំណូលទេ) រហូតដល់ត្រឡប់
  ឬកាត់ពេលចាកចេញ។
- **សំបុត្រការជួសជុល** **ការត្រួតពិនិត្យ** និង **POS/ស្តុក** ទាំងអស់បំភ្លឺ
  ថ្លៃដើមទៅក្នុង **ចំណាយ** និង **P&L**។ ថ្លៃដើមដែលម្ចាស់សង ហូរទៅក្នុង **របាយការណ៍ម្ចាស់**។
- កំណត់រឿងរាល់ផ្ទាំង **កំណត់ត្រឹមអចលនទ្រព្យ** ហើយការផ្លាស់ប្ដូររាល់ផ្ទាំង បង្កើត
  ក្បួន **កំណត់ត្រាត្រួតពិនិត្យ**។
