# ផ្នែក ៨ — ក្រមណែនាំអ្នកគ្រប់គរង

ផ្នែកនេះសម្រាប់ **Super Admins, Admins, IT និងអ្នកគ្រប់គរងអាជីវកម្ម**។ វា
ប្រើពីការកំណត់ អ្នកបរើ តួនាទី & សិទ្ធិ ម៉ឺនុយ ការចូលរបាយការណ៍
ការកំណត់អាជីវកម្ម និងការថែរក្សា។ អ្នកប្រើមិនត្រូវការនេះ សម្រាប់ការងារប្រចាំថ្ងៃទេ។

> គ្រប់អ្វីនៅទីនេះ មានបង្អួចសិទ្ធិ។ ការគ្រប់គរងភាគច្រើន ត្រូវការ **M01**
> (Users & RBDC) ឬ **M28** (Settings)។ មុខងារសុវត្ថិភាព ត្រូវការ **M27**។

## 8.1 ការគ្រប់គ្រងការចូល យោងតាមតួនាទី ដ៏រស់សកម្ម (RBDC) — សិទ្ធិដំណើរការយ៉ាងម៉េច

ទំព័រ foreach និងការហៅ API foreach ត្រូវបានពិនិត្យ ដោយ resolver ម្ខាង server-side៖

```
can(user, action, module, resource?)
```

- **សិទ្ធិ = ម៉ូឌូល × អំពើ × ជួរ (scope)។**
- **អំពើ ៩៖** `create · read · update · delete · approve · void · refund · export · config`។
- **ជួរ ៣៖**
  - **GLOBAL** — ឆ្លងអចលនទ្រពយទាំងអស់។
  - **PROPERTY** — តែអចលនទ្រព្ ដែលអ្កប្រើ**បានចែកចាយ**។
  - **OWN** — តែកំណត់រឿងផ្ទាល់ខ្លួនរបស់អ្នកបរើ (សមាជិក/ម្ចាស់/កម្មករ ខ្លួនឯង)។
- អ្នកប្រើមាន**តួនាទីមួយ ឬច្រើន** ៖ សិទ្ធិប្រសិទ្ធភាព = **សរុប (union)**។
- អ្នកប្រើទទួលបាន**ការចែកចាយអចលនទ្រព្យ** ដែលកំណត់ចូល PROPERTY-scoped access។
- ការអនុវត្ត ជា **server-side នៅរាល់ endpoint** ៖ UI លាក់អ្វី សម្រាប់ភាពសុទ្ធនិម្មិត ប៉ុន្តែ
  មិនដែលជាអ្នកមានអំណាចទេ។
- កូដសិទ្ធិ មើលដូច `M07:approve` (module:action)។

### តួនាទីលំនាំដើម (seeded)
| តួនាទី | ជួរ | ការពិពណ៌នា |
|---|---|---|
| **Super Admin** | GLOBAL | គ្រប់យ៉ាង រួមទាំង config/delete/void។ **ប្រើបាន — មិនអាចលុបបានទេ។** |
| **Admin** | GLOBAL | គ្រប់គរងអង្គភាព កម្រិត manage (CRU) ឆ្លងម៉ូឌូល គ្មាន full-delete/config |

## 8.2 ការគ្រប់គ្រងអនកប្រើ

**ទីតាំង៖** **Admin → Users [M01]**។

### បង្កើតអ្នកប្រើ
1. **Users → New user**។ បញ្ចូលឈ្មោះ **email** និងពាក្យសម្ងាត់បណ្ដោះអាសន្ន។
2. គណនីត្រូវបានបង្កើតជាមួយ `mustChangePassword = true` ដូច្នេះអ្នកបរើត្រូវ
   **បង្ខំ្យផលាស់ប្ដូរពាក្យសម្ងាត់ នៅពេលចូលដំបូង**។
3. ចែកចាយ**តួនាទី (មួយ ឬច្ើន)**។
4. ចែកចាយ**អចលនទ្រព្យ** (សម្រាប់តួនាទី PROPERTY-scoped ដូចជា Property Manager / Staff)។
5. រក្សាទុក។ អ្នកប្រើឡូវអាចចូលបាន ហើយ Admin+ ក៏ត្រូវបានគេស្នើឱ្យចុះឈ្មោះ **2FA** ផង។

### កែ / បិទ / កំណត់ឡើងវិញ
- **កែ** ឈ្មោះ/email និងការចែកចាយតួនាទី/អចលនទ្រព្យ។
- **បិទ** អ្នកបរើ (`status = disabled`) — ពួកគេមិនអាចចូលបានទៀតទេ។
- **កំណត់ពាក្យសមងាត់ឡើងវិញ** — កំណត់ពាក្យសមងាត់បណដោះអាសន្ថ្មី (កំណត់សញ្ញាតរូវផ្លាស់ប្ដូរ)។
- **2FA admin reset** — បើអ្នកបរើបាត់ authenticator របស់ពួកគេ កំណត់ TOTP របស់ពួកគេឡើងវិញ
  ដើម្បីឱ្យពួកគេចុះឈ្មោះឡើងវិញ (M27)។
- **កាត់បន្ថយ sessions** — បង្ខំឱ្យចាកចេញ ឆ្លងឧបករណ៍ ពីផ្នែកសុវត្ថិភាព/sessions។

### ក្បួន
- ការផ្លាស់ប្ដូរអ្នកប្រើ foreach ត្រូវបាន**ត្រាត្រួតពិនិត្យ**។
- តួនាទីដែល**កំពុងប្រើ មិនអាចលុបបាន** (អ្នកត្រូវដកអ្នកប្រើចេញពីវា ជាមុនសិន)។
- **តួនាទី Super Admin ត្រូវបានប្រើបាន** — វាមិនអាចលុបបាន ធានាថា
  មានគណនី full-access ជានិច្ច។

> គ្មាន email "ភ្លេចពាក្យសម្ងាត់" ដោយខ្លួនង នៅក្នុងការសាងសង់បច្ចុបបន្នទេ —
> admin កំណត់ពាក្យសមងាត់ភ្លេចឡើងវិញ (កំណត់មួយបណ្ដោះអាសន្ន)។

## 8.3 ការគ្រប់គ្រងតួនាទី & សិទ្ធិ

**ទីតាំង៖** **Admin → Roles & Permissions [M01]** (`/roles`, លម្អិតនៅ `/roles/[id]`)។

### បង្កើត ឬកែតួនាទី
1. **Roles → New role** (ឬបើកតួនាទី)។ ឱ្យវាឈ្មោះ/ការពិពណ៌នា។
2. ដាក់ធាង **ក្រាសិទ្ិ**៖ សម្រាប់ foreach **ម៉ូឌូល** ជ្រើស**អំពើ (មួយ ឬច្រើន)** និង
   **ជួរ** (GLOBAL / PROPERTY / OWN)។ ក្រឡាប្រើម៉ូឌែល F/M/R/W/O តែមួយ។
3. រក្សាទុក។ សិទ្ធិរបស់តួនាទី ត្រូវបានរក្សាទុកជាជួរ `role_permissions`
   (`module:action:scope`)។
4. ចែកចាយតួនាទី ដល់អ្នកប្រើ។

### ឧទាហរណ៍ (ពីតេស្តទទួលយកផលិតផល)
បង្កើតតួនាទី **"Cashier"** ដែលមានតែ **M09: W (ការសរសេរប្រតិបត្តិការ payments)** នៅ
ជួរ PROPERTY ។ អ្នកបរើដែលមានតួនាទីនោះ*តែប៉ុណ្ណោះ* អាចកត់ត្រាការទូទាត់ ប៉ុន្តែ
**មិនអាចបើកវិក្កយបត្រ ដើម្បីកែសម្រួល** — API ត្រឡប់ `403` (បានអនុវត្ត និងតេស្ត នៅ CI)។

### ក្បួន & សុវត្ថិភាព
- **តួនាទីលំនាំដើម/ប្រើបាន៖** Super Admin ត្រូវបានប្រើបាន តួនាទីលំនាំដើម ត្រូវបាន seed
  ពីបិទាប។ អ្នកអាចបង្កើតតួនាទីផ្ទាល់ខ្លួន ដោយសេរី។
- **ការលុប៖** តួនាទីដែលកំពុងប្រើ មិនអាចលុបបាន។
- **ការត្រាត្រួតពិនិត្យ៖** ការផ្លាស់ប្ដូរតួនាទី/សិទ្ធិ foreach សរសេរជួរ audit មួយ។ ម៉ាទ្រីស
  សិទ្ធិ ក៏**បាន snapshot-test នៅ CI** ផងដែរ (រួមទាំងតេស្តអវិជ្ជមាន) ដើម្បី
  ឱ្យសិទ្ធិមិនអាចត្រូវបានពង្រីក ដោយគ្មានកម្មវិធីបាន។
- **ការចូលប្រើប្រាស់ប្រសិទ្ធភាព ជាសរុប (union)** នៃតួនាទីទាំងអស់របស់អ្នកបរើ —
  least-privilege ជាលំនាំដើម បន្ថែមតួនាទី ដោយមានការពិចារណា។

### សិទ្ធិរបាយការណ៍
របាយការណ៍ ជា **M26**។ បន្ថែមទៀត របាយការណ៍អាច**បើក និងចែកចាយ** ដាច់ដោយឡែក
នៅក្រោម **Settings → Reports**៖
- **enabledKeys** — របាយការណ៍ណា ដែលមាននៅក្នុងបិទាប។
- **assignments** — តួនាទី/អ្នកបរើណា មើលរបាយការណ៍ណា។
- **designs** — រចនាជួរ/ម៉ាក ក្នុងមួយរបាយការណ៍។
ទិន្ននយរបាយការណ៍ មិនអាចកែបាន ទេ — វានៅតែមានបញ្ជី/query គាំទ្រ។

## 8.4 ការគ្រប់គរងម៉ឺនុយ

Overview · Portfolio · Billing · Finance · Operations · Store · Comms · Insights · Admin · Account។

## 8.6 រចនាសម្ព័ន្ធ ក្រុមហ៊ុន / សាខា
RentManager ជា **multi-property តាំងពីថ្ងៃទីមួយ**។ កំណត់រឿង foreach មាន
ជួរអចលនទ្រព្យ ក្នុងករណីដែលអនុវត្ត។ ឥត្ិភាព ជា **Property → Building → Floor → Room → Bed**។
- **Property** ជាកម្រិតខាងលើ (គិតជា "ទីតាំង" ឬ "គម្រោង")។ គ្មានពាក្យ
  "branch" ដាច់ដោយឡែកទេ — អចលនទ្រពយ ដើរតួជាឯកតាជួរ។
- **ការចែកចាយអចលនទ្រព្** នៅលើអ្នកប្រើ គ្រប់គ្រង អចលនទ្រព្យណា ដែលតួនាទី
  PROPERTY-scoped អាចមើល/គ្រប់គ្រង (ការ demo Property Manager ត្រូវបានចែកចាយ ទៅ
  អចលនទ្រពយមួយ ដោយច្រាស ដើម្បីបង្ហាញការរឹត)។
- អគារ អាចមានកំណត់ទីតាំងផែនទី និង**កាំ geofence** សម្រាប់ការវត្តមាន kiosk ជម្រើស។

## 8.7 Golden path របស់ Admin (លំដាប់រៀបចំដំបូង)

មើល**ផ្នែក 13 §13.2** សម្រាប់ជំហានបន្តិចម្ដង ប៉ុន្តែលំដាប់ ជា៖

1. កំណត់ **company/org** (ឈ្មោះ រូបិយប័ណ្ណ តំបន់ពេលវេលា ភាសា)
2. បង្កើត **properties → buildings → floors → rooms**
3. បង្កើត **roles** & **users**។ ចែកចាយតួនាទី និងអចលនទ្រព្
4. កំណត់ **permissions** (ក្រឡាតួនាទី)
5. កំណត់ផែនការ **rent engine** /ប្រាក់សោភ័ណ/ពន្ធ/ការកាត់
6. កំណត់តម្លៃបើក **accounting** (បើចល័ត)
7. កំណត់ **វិធីទូទាត់** / secrets provider
8. កំណត់ **billing/dunning** និង **rent alerts**
9. តម្កល់ **owners + កិច្ចសន្យាម្ចាស់** និង **វិធីបង់**
10. កំណត់**ការជូនដំណឹង** (templates) និង **Telegram** (token bot ការភ្ជាប់)
11. អនុវត្ត **សុវត្ថិភាព**៖ 2FA សម្រាប់ Admin+ sessions rate limits (ផ្នែក 9)
12. បើក/បិទ **feature flags** និង **reports** តាមអង្គភាព
13. **តេស្ត** golden path ពីដើមទៅចុង (ផ្នែក 13)
14. ពិនិត្យ **audit logs** និងរៀបចំការងារ/runbook **backup**

## 8.9 Audit log (សម្រាប់អ្នកគ្រប់គរង)

**ទីតាំង៖** **Admin → Audit Log [M01/M27]** (`/audit`)។

- **អ្វីដែលត្រូវបានកត់ត្រា៖** ការផ្លាស់ប្ដូរគ្រប់យ៉ាង (create/update/ការផ្លាស់ប្ដូរស្ថានភាព/approve/void/
  refund/login/ការផ្លាស់ប្ដូរសិទ្ធិ…) ជាមួយ **actor** **timestamp** **តម្លៃមុន/បន្ទាប់
  (JSON)** និង **IP**។
- **ស្ថិតក្នុងភាពដែលមើលឃើញការប៉ះប៉ាល់៖** ជួរ audit បង្កើត**ជួរ hash**។ ប្រើ **Settings →
  Security → Verify audit chain** ដើម្បីរកការប៉ះប៉ាល់ណាមួយ។ PII ត្រូវបាន masked នៅក្នុង logs។
- **ការស៊ើបអង្កេត ប្រតិបត្តិការខុស៖** ត្រាស់តាម actor/ហេតុ/entity រក
  អំពើ ប្រៀបធបមុន/បន្ទាប់ បន្ទាប់មកតាម បញ្ជី/វិក្កយបត្រដែលភ្ជាប់ ហើយប្រើ
  **ការរំលំ**ត្រឹមត្រូវ (credit note / void / refund) — កុំកែដោយដៃ ទេ។

កម្មវិធី backfill/jួរ មាន (`scripts/backfill-audit-chain.ts`)។
