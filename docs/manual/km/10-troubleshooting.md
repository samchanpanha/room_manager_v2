# ផ្នែក ១០ — ការដោះស្រាយបញ្ហា

បញ្ហាជួញជុំ មូលហេតុដែលអាចកើត របៀបពិនិត្យ ហើយរបៀបដោះស្រាយឱ្យមាន
សុវត្ថិភាព។ នៅពេលសង្ស័យ **ប្រើ Audit Log និងទំនាក់ទំនងអ្នកគ្រប់គ្រង** ជំនួសការកែ
ទិន្ននយដែលបានចុះ។

ទម្រង់ ក្នុងមួយធាតុ៖ **បញ្ហា → មូលហេតុដែលអាចកើត → របៀបពិនិត្យ → របៀបដោះស្រាយ → នៅពេលណា
ត្រូវរាយការណ៍ឡើងលើ។**

---

## 10.1 ការចូល & ការចូលទទួល

### "ខ្ញុំចូលមិនបាន"
- **មូលហេតុ៖** ពាក្យសម្ងាត់ខុស (បែងចែកអក្សរធំ/តូច) គណនីត្រូវបានបិទ ត្រូវបានកំណត់អត្រា បន្ទាប់ពីព្យាយាមច្រើន ត្រូវការ 2FA។
- **ពិនិត្យ៖** វាយឡើងវិញ ដោយប្រយ័ត្ន។ រង់ចាំមួយនាទី បើអ្នកប៉ះអង្គុយ។ បញ្ជាក់ថាគណនីរបស់អ្នក សកមម។
- **ដោះស្រាយ** ប្រើពាក្យសមងាត់ត្រឹមត្រូវ។ បើ admin កំណត់ ផ្លាស់ប្ដូរវា នៅពេលដែលត្រូវបានសួរ។ សម្រាប់ 2FA ដែលបាត់ សួរ admin ឱ្យ **reset 2FA របស់អ្នក** បន្ទាប់មកចុះឈ្មោះឡើងវិញ។
- **រាយការណ៍ឡើង៖** គណនីត្រូវបានបិទ ឬការបិទចោលម្ដងហើយម្ដងទត → Admin។

### "ខ្ញុំើញ 403 FORBIDDEN / ធាតុម៉ឺនុយបាត់"
- **មូលហេតុ៖** តួនាទីរបស់អ្នក ខ្វះម៉ូឌូល/អំពើនោះ ឬអ្នកមិនទាន់បានចែកចាយ ទៅអចលនទ្រព្យនោះ។
- **ពិនិត្យ៖** ប្រៀបធៀបជាមួយម៉ាទ្រីស (ផ្នែក 8.1)។ បញ្ជាក់**ការចែកចាយអចលនទ្រពយ**របស់អ្ក។
- **ដោះស្រាយ៖** មិនមែនជាកំហុសទេ — ស្នើសិទ្ធិ/ការចែកចាយ ពី Admin។
- **រាយការណ៍ឡើង៖** បើអ្នកជឿថាអ្នកគួរមានការចូល Admin កែតួនាទី/ការចែកចាយរបស់អ្នក។

### OTP សមាជិក ប្រាប់ "ព្យាយាមច្រើនពេក / ត្រូវបានបិទ"
- **ដោះស្រាយ** ស្នើ **OTP ថ្មី** (កូដប្រើម្ដង និងបិទ បន្ទាប់ពី ៥ ដង)។

## 10.2 ការគណនាប្រាក់ & វិក្កយបត្រ

### "ថ្លៃទឹកអគ្គិសនី/សេវា ខ្វះពីវិក្កយបត្រខែនេះ"
- **មូលហេតុ៖** ការអានម៉ែត្រ មិនទាន់បញ្ចូល មុនការបង្កើត។ សេវាមិនទាន់បានចែកចាយ។ ថ្លៃភ្ជាប់ទៅ *រយៈពេលបន្ទាប់*។
- **ពិនិត្យ៖** **Utilities** — មានការអាន សម្រាប់រយៈពេលនោះដែរឬទេ? **Services** — ការចែកចាយ សកមម ដើម្បីកិច្ចសនយាជួលនោះដែរឬទេ?
- **ដោះស្រាយ៖** បញ្ចូលការអាន/ចុះការប្រើ។ វានឹងត្រូវបានគណនា នៅការបង្កើត **បន្ទាប់**។ សម្រាប់រយៈពេលបច្ចុប្បនន អ្កអាចបន្ែមក្បួន one-time/credit ដែលសមរម្យ តាមគោលការណ៍។
- **រាយការណ៍ឡើង៖** គណនី បើត្រូវការការកែតម្រូវ វិក្កយបត្រដែលបាន issue (**credit note**)។

### "ខ្ញុំបានបង្កើតវិក្កយបត្រ ប៉ុន្តែអ្វីៗមិនបង្ហាញ សម្រាប់កិច្ចសន្យាជួលមួយ"
- **មូលហេតុ៖** កិច្ចសន្យាជួលមិន **active** (នៅ draft) ឬរយពេល បានគណនាហើយ (វិក្កយបត្រ live មួយ ក្នុងមួយកិច្ចសនយាជួល-រយៈពេល — ការបង្កើត ជា idempotent)។
- **ពិនិត្យ៖** ស្ថានភាពកិច្ចសនយាជួល = active។ ពិនិត្យរយពេលគណនាប្រាក់ របស់កិច្ចសន្យាជួល។
- **ដោះស្រាយ** បើកបរើកិច្សន្យាជួល។ បើបានគណនាហើយ ការបង្កើតចម្លង មិនកើតឡើង តាមការរចនាទេ។
- **រាយការណ៍ឡើង** គណនី។

### "វិក្កយបត្រដែលបាន issue មានចំនួនខុស"
- **ដោះស្រាយ** កុំ**ព្យាយាម**កែ/លុបវា (វិក្កយបត្រដែលបាន issue ជា immutable)។ ប្រើ **credit note** (≤ ត្រូវបង់ បញ្ចប់ដរត្ានៅសូន្យ)  **void** ដោយ Super Admin ជាមួយមូលហេតុចាំបាច់។
- **រាយការណ៍ឡើង** void = Super Admin តែប៉ុណ្ណោះ។

### "ប្រាក់សោភ័ណ / dunning មិនបានអនុវត្ត"
- **មូលហេតុ៖** នៅក្នុង**ថ្ងៃរការ** មែន។ របៀបប្រាក់សោភ័ណ ជា `none`។ ការងារ billing ប្រចាំថ្ងៃ មិនទាន់បានដំណើរការ។
- **ពិនិត្យ៖** Settings → Billing (រការ) និង Late fee (របៀប)។ ដំណើរការ/បញ្ជាក់ការងារ **billing-daily**។
- **រាយការណ៍ឡើង៖** គណនី/Admin សម្រាប់កាលវិភាគការងារ។

## 10.3 ការទូទាត់

### "អ្នកជួលបានបង់ ប៉ុន្តែតម្លៃដែលនៅសល់ មិនផ្លាស់ប្ដូរ"
- **មូលហេតុ៖** ការទូទាត់នៅ **pending** (QR/gateway មិនទាន់បានបញ្ជាក់)។ ការទូទាត់ត្រូវបានកត់ត្រា ប្រឆាំង**សមាជិក/វិក្កយបត្រខុស**។ webhook មិនទទួល។
- **ពិនិត្យ៖** បើកការទូទាត់ — ស្ថានភាព pending vs confirmed។ ពិនិត្យការយោង gateway និងការផ្ដល់ webhook។ ពិនិត្យ **ការបែងចែក**។
- **ដោះស្រាយ** បញ្ជាក់ការទូទាត់ប្រាក់សាច់/ធាគារ pending។ សម្រាប់ QR បញ្ជាក់ តាមរយៈ webhook gateway (webhook ចម្លង ត្រូវបានមើលរំលង ដោយសុវត្ថិភាព)។ បើវាត្រូវបានកត់ត្រា ប្រឆាំងសមាជិកខុស កុំលុប — ប្រើ **refund/reversal** ហើយកត់ត្រា្យត្រឹមត្រូវ។
- **រាយការណ៍ឡើង៖** គណនី (ការត្រឡប់/ការរំលំ ការពិនិត្យ webhook gateway)។

### "ការទូទាត់ត្រូវបានកត់ត្រាពីរដង"
- **មូលហេតុ៖** ការចូលដៃពីរដង។ ការចម្លង gateway ត្រូវបានមើលរំលងដ្រត្រា (idempotency keys) ដូច្នេះនេះកើតឡើង តែជាមួយការចូលដៃ។
- **ដោះស្រាយ៖** **refund/reverse** ការទូទាត់លើស (Accountant+) ដែលចុះចំណុចបញ្ជីកែតម្រូវ។
- **រាយការណ៍ឡើង៖** គណនី។

### "សមាជិកបានបង់លើស"
- **ឥរិយាបថ (មិនមែនជាកំហុស)៖** ប្រាក់លើស នៅសល់ជា **member credit** (អាចត្រឡប់ ដោយគណនី) — វា**មិនមែន**ជាចំណូល។

## 10.4 កិច្ចសន្យា & កិច្ចសន្យាជួល

### "ខ្ញុំបើកប្រើកិច្ចសនយាជួលមិនបាន"
- **មូលហេតុ៖** បន្ទប់មិនទទេ (មានកិច្ចសន្យាជួលសកម្ម/ដល់ទំហំហើយ)។ KYC សមាជិក មិនពេញលេញ (សមាជិកមិនទាន់ verified)។
- **ពិនិត្យ៖** សថានភាពបន្ទប់ (គួរជា vacant/reserved)។ បញ្ជីផ្ទៀងផ្ទាត់ KYC សមាជិក ពេញលេញ។
- **ដោះស្រាយ៖** ជ្រើសបន្ទប់ទទេ។ បញ្ចប់ការឡូត KYC។ បន្ទាប់មកបើកប្រើ។

### "ខ្ញុំបញ្ចប់/terminate កិច្ចសន្យាជួលមិនបាន"
- **មូលហេតុ៖** **លំណូល** មិនទាន់បានសម្អាត (ឬការសរសេរចេញដែលបានអនុម័ត)។ គ្មាន**ការត្រួតពិនិត្យចាកចេញ** ដែលបានបញ្ចប់។ ប្រាក់កក់ មិនទាន់បានបញ្ចប់។
- **ពិនិត្យ៖** តម្លៃសមាជិក = 0។ ការត្រួតពិនិត្យចាកចេញ បានបញ្ចប់។ បញ្ជីប្រាក់កក់ ធ្វើស្មើសូន្យ។
- **ដោះស្រាយ៖** ប្រមូល/សម្អាតលំណូល បញ្ចប់ការត្រួតពិនិត្យចាកចេញ បញ្ចប់/ត្រឡប់ប្រាក់កក់ (ការកាត់ត្រូវការភស្តុតាង)។
- **រាយការណ៍ឡើង៖** Manager សម្រាប់ការអនុម័តការសរសេរចេញ។ គណនី សម្រាប់ការត្រឡប់ប្រាក់កក់។

### "ស្ថានភាពបន្ទប់ ត្រូវបានចោលនៅ cleaning / maintenance"
- **ដោះស្រាយ៖** ត្រឡប់បន្ទប់ទៅ **vacant** (ឬបញ្ចប់ការជួសជុល) ដើម្បីជួលវាឡើងវិញ។ ការជួសជុល ត្រូវការមូលហេតុ ដើម្បីកំណត់។

## 10.5 ប្រាក់កក់

### "ត្រឡប់/កាត់ប្រាក់កក់មិនបាន"
- **មូលហេតុ៖** ការកាត់ ត្រូវការ**ឯកសារភស្តុតាង + កូដមូលហេតុ**។ ការត្រឡប់ ត្រូវការ**ការអនុម័តគណនី** និងវិធីបង់។
- **ដោះស្រាយ៖** ឡូតភស្តុតាង និងជ្រើសមូលហេតុ។ បញ្ជាក់ថាម្ចាស់/សមាជិក មានវិធីបង់។ ផ្ញើការត្រឡប់ ទៅគណនី។

### "ប្រាក់កក់ បន្តបង្ហាញ បន្ទាប់ពីចាកចេញ"
- **ដោះស្រាយ** សម្រាប់កិច្ចសន្យាជួលដែលបានបិទ **2100 Deposit Liability** ត្រូវធ្វើស្មើសូន្យ — បញ្ចប់ការកាត់ទាំងអស់ + ការត្រឡប់។

---

## 10.6 របាយការណ៍ & លេខ

### "លេខរបាយការណ៍ មិនត្រូវគ្នា ជាមួយអ្វីដែលខ្ញុំរំពឹង"
- **ពិនិត្យ៖** តម្រង (ចន្លោះហេតុ អចលនទ្រពយ)។ ជួរសិទ្ធិរបាយការណ៍ (PROPERTY vs GLOBAL)។ ចងចាំថារបាយការណ៍ អាន**បញ្ជី/ទិន្ននយពិត** — លេខផ្លាស់ប្ដូរ តាមពេលដែលទិន្ននយត្រូវបានចូល។
- **ដោះស្រាយ** លុប/កែសម្រួលតម្រង។ រង់ចាំការចុះដែលពាក់ព័ន្ មកដល់ (ឧ. ការទូទាត់បញ្ជាក់)។ ចូលទៅលម្អិត ទៅប្រភព (វិក្កយបត្រ/បញ្ជី/សំបុត្រ)។
- **រាយការណ៍ឡើង៖** សរុបដែលមិនត្រូវគ្នាពិត → Admin/គណនី + ពិនិត្យ Audit Log។
- ចំណាំ៖ គ្មាន**របាយការណ៍ Balance Sheet ដាច់ដោយឡែក**ទេ — ប្រើ **Ledger → Trial balance** (ផ្នែក 5.6)។

## 10.7 Telegram

### "Bot មិនផ្ញើសារ"
- **មូលហេតុ៖** មិនទាន់បានភ្ជាប់។ toggles ក្នុងមួយអ្នកបរើ បិទ។ នៅក្នុង dev អ្នកផ្ញើ **mocked ទៅ outbox**។ ការងារ dispatch មិនទាន់បានដំណើរការ។ ការភ្ជាប់សមាជិក ត្រូវបានបិទ។
- **ពិនិត្យ៖** Comms → Telegram — chat ដែលបានភ្ជាប់ toggles និង **outbox** (ស្ថានភាព/ខ្លឹមសារ)។ Settings → Telegram (`allowMemberLinking`)។ មាន sealed secret របស់ bot token ឬទេ។
- **ដោះស្រាយ៖** ភ្ជាប់ឡើងវិញ ជាមួយកូដថ្មី។ បើក toggles។ នៅក្នុង demo អានសារ ពី outbox។ បញ្ជាក់ថាការងារ **telegram-dispatch** ដំណើរការ នៅក្នុងការដាក់ប្រើ។
- **រាយការណ៍ឡើង៖** Admin (token bot ការងារ)។

### "Link code មិនដំណើរការ"
- **ដោះស្រាយ៖** កូដជាមួយដង/ខ្លី — ស្នើមួយថ្មី ហើយផ្ញើ `/link <code>` ទៅ bot។

## 10.8 ឯកសារ

### "តំណាញ់ទាញយក ផុតកាល / ប្រាប់ forbidden"
- **មូលហេតុ៖** signed URLs រស់ **120 វិនាទី**។ អ្នកអាចខ្វះសិទ្ធិ (cross-property/own-scope តែប៉ុណ្ណោះ)។
- **ដោះស្រាយ៖** បើកឯកសារ ពីកំណត់រឿង (signed URL ថ្មី ត្រូវបានចេញ)។ កម្មកររបស់អចលនទ្រពយផ្សេង ត្រូវបានបដិសេធ ត្រឹមត្រូវ។
- **រាយការណ៍ឡើង** បើអ្កគួរមានការចូល Admin ពិនិត្យការចែកចាយអចលនទ្រព្យ/សិទ្ធិ។

---

## 10.9 គណនី

### "សៀវភៅមើលដូចខុស / trial balance"
- **ដោះស្រាយ៖** ប្រព័ន្ធបដិសេធនការចុះមិនតុល្យ ដូច្នេះបញ្ហាជាទូទៅ ជាវេលា ឬការបញ្ជាក់ដែលខ្វះ។ តាមតាមរយៈ **Ledger journal** (ត្រាស់តាមគណនី/ការយោង) និង **Audit Log**។ កែតម្រូវ ដោយការរំលំត្រឹមត្រូវ (credit note / void / refund) — **កុំកែជួរបញ្ជីទេ** (database បិទការធ្វើទំនើប/លុប នៅលើជួរដែលបានចុះ)។
- **រាយការណ៍ឡើង៖** គណនី សម្រាប់ការកែតម្រូវ។ Admin សម្រាប់ការពិនិត្យជួរ audit។

---

## 10.10 ការជូនដំណឹង / alerts

### "Rent dues/overdue មិនបង្ហាញ"
- **ពិនិត្យ៖** អ្នកតរូវការ **M33 read**។ alerts គោរពការកំណត់ **ahead/overdue days** (លំនាំដើម 3/1)។
- **ដោះស្រាយ៖** ដំណើរការ/បញ្ជាក់ការងារ **rent-alerts** និង **telegram-dispatch**។ ពិនិត្យ feature flags។
