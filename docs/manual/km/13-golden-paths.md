# ផ្នែក ១៣ — Golden paths & ស្ថានភាពជាក់ស្ដែង

របៀបរហ័សបំផុត ដើម្បីរៀនប្រព័ន្ធ គឺតាម **golden path** — ដំណើរការពីដើមទៅចុង
ធម្មតា។ បន្ទាប់មកប្រើស្ថានភាព ២០ សម្រាប់ការងារជាក់លាក់។

---

## 13.1 Golden path សម្រាប់អ្នកប្រើ (កម្មករថ្មី / អាជីវកម្មបរចាំថ្ងៃ)

> របៀបងាយស្រួលបំផុត សម្រាប់កម្មករថ្មី ដើម្បីរនប្រពន្ធ។

1. **ចូល** (ផ្លាស់ប្ដូរពាក្យសមងាត់បណ្ដោះអាសន្នរបស់អ្នក។ កំណត់ 2FA បើត្រូវបានសួរ)។
2. **ពិនិត្យ Dashboard** — occupancy បានប្រមូល vs បានគណនា លំណូល ប្រាក់សាច់ rent dues។
3. **គ្រប់គ្រងអចលនទ្រពយ & បនទប់** — បញ្ជាក់ថាបន្ទប់ ទទេ/មានតម្លៃ។
4. **ចុះឈ្មោះសមាជិក** — អ្នកត្ដមនិក ៤ ជំហាន + ការឡូត KYC (prospect → verified)។
5. **បង្កើតកិច្ចសនយាជួល** — សមាជិក + បន្ទប់ + ថ្លៃជួល + ប្រាក់កក់ + សេវា។ បើកប្រើ (បន្ទប់ occupied សមាជិក active)។
6. **បន្ថែមសេវាខែ** — WiFi/ជម្រករថយន្ត/បរអប់សម្ុប តាមការអនុវត្ត។
7. **បញ្ចូលការអានម៉ែត្រ** — ទឹកអគ្គិសនី សម្រាប់រយៈពេល។
8. **បង្កើតថ្លៃខែ** — ការបង្កើតវិក្កយបត្រ (idempotent លេខគ្មានរន្ធ)។
9. **Issue វិក្កយបត្រ** — សមាជិកឃើញវា នៅក្នុង portal / ទទួលសារ Telegram។
10. **ទទួលការទូទាត់** — cash/QR/card។ ចេញប័ណ្។ វិក្យបត្រ partial_paid→paid។
11. **បញ្ជីធ្វើទំនើបកម្មដរត្រា** — ចំណុចតុល្យ។ statement សមាជិក បង្ហាញវា។
12. **កត់ត្រាចំណាយ** — ថ្លៃដើមអ្នកផ្គត់ផ្គង់ ជាមួយប័ណ្ណ (អនុម័ត បើលើសអង្គុយ)។
13. **ដោះស្រាយប្រតិបត្តិការ** — ការជួសជុល/ការតវ៉ា/ការត្រួតពិនិត្យ/ការផ្លាស់បន្ទប់ តាមពេលដែលកើតឡើង។
14. **ពិនិត្យ Profit & Loss** — ចំណូល − ចំណាយ = សុទ្ធ។
15. **ពិនិត្យ trial balance** — debits = credits (តាមរយៈ Ledger)។
16. **បង្កើតរបាយការណ៍ម្ាស់** — គណនីបង្កើត។ អនុម័ត។ បង់ម្ចាស់។
17. **ផ្ញើការជូនដំណឹង** — dunning/ការជ្រើស/Telegram (ការងារ ឬការចាប់ផ្ដើមដៃ)។
18. **ដំណើរការរបាយការណ៍** — occupancy collections/លំណូល rent roll P&L ដើម។ នាំចេញ។

បើអ្នកអាចធ្វើជំហាន ២ → ១០ ដោយគ្មានជំនួយ អ្នកអាចដំណើរការមាត់កម្មបាន។

## 13.2 Golden path សម្រាប់ Admin (ការរៀបចំប្រព័ន្ធត្រូវដំបូង)

1. **កំណត់ company/org** — ឈ្មោះ ឈ្មោះបច្ចេក logo template វិក្កយបត្រ (Settings → Org)។
2. **កំណត់ locale** — រូបិយប័ណ្ណ តំបន់ពេលវេលា ភាសាដំបូង (en/km/zh)។
3. **បង្កើត properties → buildings → floors → rooms** (ប្រើអ្នកឧត្មនិកបន្ទប់ដ្រត្រា)។
4. **តម្កល់ owners** — កំណត់រឿង owner + វិធីបង់។ ចែកចាយអគារ។ បង្កើតកិច្ចសន្យាម្ចាស់។
5. **កំណត់តួនាទី** — ពិនិត្យម៉ាទ្រីសលំនាំដើម។ បង្កើតតួនាទីផ្ទាល់ខ្លួន (ឧ. "Cashier")។
6. **កំណត់អ្នកប្រើ** — បង្កើតកម្មករ ជាមួយពាក្យសមងាត់បណ្ដោះអាសន្ន។ ចែកចាយតួនាទី + អចលនទ្រពយ។
7. **កំណត់ rent engine** — ផែនការ ថ្ងៃវដ្ត មូលដ្ឋានប្រកាន់ ប្រាក់សោភ័ណ ពន្ធ ការកាត់។
8. **កំណត់លំនាំដើម billing & dunning** — ថ្ងៃរការ ជួរ dunning ពាក្យគ្រងមុខវិក្កយបត្រ។ បង្អួច rent-alerts។
9. **កំណត់គណនី** — តម្លៃបើក (ការចុះដែលតុល្យ) បើចល្ាត។ ពិនិត្យតារាងគណនី។
10. **កំណត់វិធីទូទាត់ & providers** — secrets provider ដែលបានស្គរ។ បញ្ជាក់ការរៀបចំ QR/webhook។
11. **កំណត់ការជូនដំណឹង** — token bot Telegram (ស្គរ) templates ការភ្ជាប់សមាជិក។
12. **កំណត់ feature flags & របាយការណ៍** — បើក/បិទម៉ូឌូល។ ចែកចាយរបាយការណ៍ ទៅតួនាទី។
13. **អនុវត្តសុវត្ថិភាព** — 2FA សម្រាប់ Admin+ គោលការណ៍ sessions rate limits ការរក្សាទុករង។
14. **កាលវិភាគការងារ** — invoice-generation billing-daily rent-alerts telegram-dispatch sla-sweep attendance-sweep statement-generation retention backup។
15. **តេស្ត golden path** ពីដើមទៅចុង (ការទទួលយក 12-ស្ថានភាព នៅ §13.4)។
16. **ពិនិត្យ audit logs** ហើយដំណើរការ **verify audit chain**។ បញ្ជាក់ថាការរក្សាទុករង ដំណើរការ (តេស្ត restore)។

## 13.3 ប្រតិបត្តិការជាក់ស្ដែង ២០

### ករណី ១ — បង្កើតអចលនទ្រព្យថ្មី
**Portfolio → Properties → New**។ បញ្ចូលកូដ តែមួយគត់ ឈ្មោះ អាសយដ្ឋាន geofence ជម្រើស។ រក្សាទុក។ ឡូវអ្នកអាចបន្ថែមអគារបាន។

### ករណី ២ — បង្កើតឯកតាថ្មី (បន្ទប់)
បើកអចលនទ្រពយ → **បន្ែមអគារ** → **បន្ថែមជាន់** → **បន្ថែមបន្ទប់** (ឬ **បង្កើតដ្រត្ា** បន្ប់ ជាមួយ prefix/ចាប់ផ្ដើម/ចំនួន/គ្រែ/ប្រភេទ/តម្លៃ)។ កំណត់តម្លៃមូលដ្ឋាន និងទំហំ។ បន្ទប់ចាប់ផ្ដើម **vacant**។

### ករណី ៣ — បង្កើតអ្នកជួល (សមាជិក)
**Members → New member** → អ្នកត្ដមនិក៖ ផ្ទាល់ខ្លួន → អចលនទ្រព្/ទំនាក់ទំនងបន្ទាន់ → **ការឡូត KYC** (ប្រភេទឯកសារចាំបាច់ទាំងអស់) → ពិនិត្យ។ សមាជិកជា **prospect**។ KYC ពេញលេញ ផ្លាស់ទៅ **verified**។

### ករណី ៤ — បង្កើតការជួល (កិច្ចសនយាជួល)
**Leases → New** → ជ្រើសសមាជិក + បន្ទប់/គ្រែទទេ → កំណត់ចាប់ផ្ដើម/បញ្ចប់ ថ្លៃជួល ថ្ងៃវដ្ត មូលដ្ឋានប្រកាន់ តម្រូវប្រាក់កក់ → បន្ថែមសេវា → រក្សាទុក **draft** → **Activate**។ បន្ទប់ → occupied។ សមាជិក → active។ ប្រាក់កក់ ត្រូវបានគណនាប្រាក់។ វិក្កយបត្រដំបូង ត្រូវបានកំណត់។

### ករណី ៥ — បង្កើតកិច្ចសនយា
ការបើកប្រើកិច្ចសន្យាជួល **បង្កើតកិច្ចសន្យា PDF សមាជិក** (រក្សាទុកដ្រត្ា ទៅឯកសារ)។ សម្រាប់មចាស់ផ្ទះ បង្កើត **កិច្ចសន្យាម្ចាស់** (FIXED_RENT ឬ REVENUE_SHARE % ហាមគ្រប់គ្រង ថ្ងៃបង់) ហើយ **បើកប្រើ** — វាធ្វើសមកាលម្ចាស់ការអគារ។

### ករណី ៦ — បន្ថែមសេវាខែ
**Billing → Services** → បង្កើតាតុកាតាឡុក។ នៅលើកិច្ចសនយាជួល **ចែកចាយ** សេវា fixed ខែ (WiFi/កន្លែងជម្រករថយន្ត) និងចុះ **ការប្រើ per-use** (បរអប់សម្ុប/ជម្រករថយន្តភញៀវ)។ សេវា fixed ត្រូវបានគណនាប្រាក់ នៅវិក្កយបត្របន្ទាប់។ ការផ្អាកចំកណ្ដាលខែ ត្រូវបានប្រកាន់។

### ករណី ៧ — បង្កើតការគណនាប្រាក់ខែ
បញ្ចូលការអានម៉ែត្រ ដំបូង (**Utilities**) បន្ទាប់មក **Invoices → Generate**។ ការបង្កើត គណនាប្រាក់ កិច្ចសន្យាជួលសកម្ម foreach (ប្រកាន់ catch-up សម្រាប់ការចាប់ផ្ដើមចំកណ្ដាលខែ វិក្កយបត្រមួយ ក្នុងមួយកិច្ចសន្យាជួល-រយៈពេល លេខគ្មានរន្ធ PDFs រក្សាទុក)។ បន្ទាប់មក **Issue** វិក្កយបត្រ។

### ករណី ៨ — ទទួលការទូទាត់អ្នកជួល
**Payments → New** → ជ្រើសសមាជិក → បញ្ចូលចំនួន → ជ្រើសវិធី (cash/bank/qr/card/cheque) → រក្សាទុក។ Cash/bank បញ្ជាក់ភ្លាម។ ប័ណ្ណ `RCP-…` ត្រូវបានរក្សាទុក។ វិក្កយបត្រ ផ្លាស់ទៅ partial/paid។ បញ្ជីចុះ។ អាចផ្ញើប័ណ្ណ Telegram បាន។

### ករណី ៩ — កត់ត្រាការទូទាត់ផ្នែក
ដូចករណី ៨ ប៉ុន្តែបញ្ចូលតិចជាងតម្លៃដែលត្រូវបង់។ ការទូទាត់ត្រូវបានបែងចែក ពីចាស់ទៅថ្មី។ វិក្កយបត្រក្ាយជា **partial_paid** ជាមួយលំណូល នៅតែត្រូវបង់។ ភាគផ្សេង ក្រោយមក ផ្លាស់វាទៅ **paid**។

### ករណី ១០ — ដោះស្រាយការទូទាត់ផុតកាល
បន្ទាប់ពីរយៈពេលរការ ការងារ **billing-daily** សម្គាល់វិក្កយបត្រ **overdue** អនុវត្តប្រាក់សោភ័ណ (បើបានកំណត់) ហើយការជ្រើស dunning ចុះផ្ដើម (+3/+7/+14)។ ប្រើកាត **Rent dues** dashboard → របាយការណ៍ **Overdue & not paid** ដើម្បីតាមបង់។ កត់ត្រាការទូទាត់ នៅពេលដែលទទួល។

### ករណី ១១ — ផ្លាស់ប្ដូរតម្លៃជួល
កុំកែវិក្កយបត្រដែលបានចុះ។ កំណត់តម្លៃថមី នៅលើកិច្ចសនយាជួល/ផែនការថ្លៃជួល ទៅ**មុខ** (ការចុះវិញ/លក្ខខណ្ឌថ្ី)។ ប្ព័ន្ធ្រកាន់ការផ្លាស់ប្ដូរ ចំកណ្ដាលរយៈពេល តាមរយៈដំណើរការដែលសមស្រប (ឧ. ការផ្លាស់បន្ទប់ បង្កើតវិក្កយបត្រកែសម្រួល)។ ការកំណត់ អនុវត្តទៅមុខតែ។

### ករណី ១២ — ចុះវិញកិច្ចសន្យា
នៅពេលបញ្ចប់កិច្ចសន្យាជួល បញ្ចប់/terminate កិច្ចសន្យាជួលចាស់ (បន្ទាប់ពីការសម្អាត + ការត្រួតពិនិត្យ + ការបញ្ចប់ប្រាក់កក់) ហើយបង្កើតកិច្ចសន្យាជួល/លក្ខខណ្ឌបន្ទាប់ — ឬប្រើលក្ខខណ្ឌ auto-renew បើបានកំណត់។ កិច្ចសនយាម្ចាស់ ត្រូវបានបង្កើត/បើកប្រើឡើងវិញ នៅពេលលក្ខខណឌផ្លាស់ប្ដូរ។

### ករណី ១៣ — បញ្ឈប់ការជួល
ផ្ដល់ **notice** → សម្អាតលំណូលទៅ 0 (ឬការសរសេរចេញដែលបានអនុម័ត) → បញ្ចប់ **ការត្រួតពិនិត្យចាកចេញ** → **terminate/complete**។ បន្ទប់ → cleaning។ សមាជិក → moved_out។ បញ្ចប់ប្រាក់កក់ (កាត់ ជាមួយភស្តុតាង + ត្រឡប់)។ ត្រឡប់បន្ទប់ទៅ vacant។

### ករណី ១៤ — កត់ត្រាចំណាយ
**Finance → Expenses & P&L → New** → អ្នកផគត់ផ្គង់ ប្រភេទ (ភ្ជាប់ទៅបញ្ជី 5000/5100) ចំនួន ហេតុ វិធីទូទាត់ ការភ្ជាប់ប័ណ្ណ អចលនទ្រព្យ។ ក្រោម $500 វា auto-approves ហើយចុះ។ លើស គណនី/Manager អនុម័ត។ ចំណាយខុស? **Void** (រំលំ)។

### ករណី ១៥ — ពិនិត្យ Profit & Loss
**Reports → Profit & Loss** (ឬ Expenses & P&L)។ ត្រាស់តាមអចលនទ្រព្យ/រយៈពេល។ អានក្បួនចំណូល (ថ្លៃជួល/សេវា/ទឹកអគ្គិសនី/ប្រាក់សោភ័ណ/ផ្សេង) ដកចំណាយ និងការបង់ម្ចាស់ = សុទ្ធ។ ប្រៀបធបជាមួយ **Expense vs budget**។

### ករណី ១៦ — បង្កើតរបាយការណ៍ម្ចាស់
**Finance → Owner Statements** (Accountant+)។ **បង្កើត** សម្រាប់ខែ — idempotent ក្នុងមួយកិច្ចសន្យា+ខែ។ ពិនិត្យរូបមន្ត (បានប្រមូល × ភាគ ឬថ្លៃជួលថេរ − ហាម − ចំណាយ ± ការកែសម្រួល) → **អនុម័ត** (រំងល់) → **បង់** (សម្អាត Owner Payable)។ PDF ត្រូវបានរក្សាទុក ហើយបង្ហាញ នៅក្នុង portal ម្ចាស់។

### ករណី ១៧ — ផ្ញើឯកសារ តាម Telegram
ឯកសារបង្កើត ដែលធ្វើដំណើរ តាមព្រឹតតិការណ៍ តរូវបានផ្ដល់ដ្រត្រា — ឧ. **ប័ណ្ទូទាត់** នៅ `payment.confirmed` និង **របាយការណ៍ម្ចាស់** នៅពេលអនុម័ត។ បញ្ជាក់ថាអ្នកបរើ **បានភ្ជាប់** ហើយ toggles បើក។ (នៅក្នុង demo មើល outbox នៅអេក្រង់ Telegram)។

### ករណី ១៨ — បង្កើតអ្នកបរើប្រព័ន្ធតថ្មី
**Admin → Users → New** → ឈ្មោះ/email + ពាក្យសម្ងាត់បណ្ដោះអាសន្ន → ចែកចាយតួនាទី + អចលនទ្រព្យ → រក្សាទុក។ អ្នកប្រើត្រូវបានបង្ខំ ឱ្យផ្ាស់ប្ដូរពាក្យសម្ងាត់ នៅពេលចូលដំបូង។ Admin+ ត្រូវចុះឈ្មោះ 2FA។ បិទ/កំណត់ឡើងវិញ ពីអេក្រង់តែមួយ។

### ករណី ១៩ — កំណត់សិទ្ធិតួនាទី
**Admin → Roles & Permissions → New/Edit role** → ដាក់ធាងករឡា **module × action × scope** → រក្សាទុក → ចែកចាយទៅអ្នកបរើ។ ឧទាហរណ៖ "Cashier" ដែលមានតែ M09 ការសរសេរការទូទាត់។ ការផ្លាស់ប្ដូរ ត្រូវបានត្រាតរួតពិនិតយ។ តួនាទីដែលកំពុងប្រើ មិនអាចលុបបាន។ Super Admin ត្រូវបានប្រើបាន។

### ករណី ២០ — ស៊ើបអង្កេតប្រតិបត្តិការខុស
1. បើក **Admin → Audit Log**។ ត្រាស់តាម actor/ហេតុ/entity។
2. អានតម្លៃ **មុន/បន្ទាប់** និងកត់ត្រាកំណត់រឿងដែលភ្ជាប់។
3. បើកប្រភព (វិក្កយបត្រ/ការទូទាត់/ចំណាយ) និង **Ledger journal** សម្រាប់ចំណុចរបស់វា។
4. អនុវត្តការរំលំត្រឹមត្រូវ — **credit note** (វិក្កយបត្រ) **refund** (ការទូទាត់ Accountant+) **void** (ចំណាយ) — កុំកែជួរដែលបានចុះ ដោយដៃ ទេ។
5. បើសង្ស័យការប៉ះប៉ាល់ ដំណើរការ **verify audit chain** (Security) ហើយរាយការណ៍ឡើងលើ។

## 13.4 ដំណើរទៅមើលការទទួលយក ពីដើមទៅចុង (ស្ថានភាព "golden")

នេះជារូបចម្លង តេស្តការទទួលយក របស់ប្រពន្ធកនុងវា — ដំណើរការវា នៅក្នុង demo ដើម្បីមើលគ្រប់អ្វី ភ្ជាប់គ្នា៖

1. Super Admin បង្កើត org (រូបិយប័ណ្ណ តំបន់ពេលវេលា) អចលនទ្រពយ + អគារ + បន្ទប់ 3។ តួនាទី/អ្នកបរើ (PM គណនី Staff)។
2. តម្កល់ Owner មួយ ជាមួយកិច្ចសនយាម្ចាស់ revenue-share (60%) សម្រាប់អគារ។
3. តម្កល់ Member៖ ឯកសារ KYC → កិច្ចសនយាជួល នៅលើបន្ទប់ (ចាប់ផ្ដើមចំកណ្ដាលខែ) ថ្លៃជួល 300/ខែ ប្រាក់កក់ 600 ជា 2 តម្រូវ WiFi 15/ខែ។
4. បង្កើតវិក្កយបត្រ #1៖ ថ្លៃជួលប្រកាន់ + WiFi + ថ្លៃអគ្គិសនី (ការអានម៉ែត្រ) → issued → PDF រក្សាទុក → Telegram/portal។
5. សមាជិកបង់ 50% តាម QR (webhook បញ្ជាក់ម្ដង ចម្លងត្រូវបានមើលរំលង) ហើយភាគផ្សេង ជាប្រាក់សាច់ តាមរយៈ Staff។ ចេញប័ណ្ណ។ បញ្ជីតុល្យ។
6. សមាជិកស្នើការផ្លាស់បន្ទប់ → បានអនុម័ត ជាមួយ +10 ប្រកាន់ → វិក្កយបត្រកែសម្រួលមួយ។ បន្ទប់ទាំងពីរ ផ្លាស់ប្ដូរស្ថានភាព។
7. សមាជិកលើកការតវ៉ា → ប្ដូរទៅសំបុត្រជួសជុល → បានដោះស្រាយ ដោយប្រើធាតុស្តុក 1 → បានបិទ → សមាជិកវាយតម្លៃ។
8. ចុងខែ៖ កត់ត្រាទឹកអគ្គិសនី ចុះចំណាយ បង្កើត P&L។ របាយការណ៍ម្ចាស់ draft → approved → payout បានបង់ → ម្ចាស់មើល PDF នៅក្នុង portal។
9. ពិនិត្យ៖ trial balance ធ្វើស្មើសូន្យ។ របាយការណ៍លំណូល ត្រូវគ្នា។ audit trail ពេញលេញ។ អ្នកប្រើ Staff ត្រូវបានដកហូល ពីការ void វិក្កយបត្រ (តេស្តអវិជ្ជមាន)។

> នៅពេលដែលដំណើរទៅមើលនេះ ដំណើរការដោយរលូន កម្មករ បានមើលវង់
> **ទាំងមូល** នៃអាជីវកម្ម — ពីបន្ទប់ទទេ ទៅម្ចាស់ដែលបានទទួលប្រាក់ —
> ហើយយល់ថា ម៉ូឌូល foreach ចូលទៅម៉ូឌូលបន្ទាប់ យ៉ាងម៉េច។
