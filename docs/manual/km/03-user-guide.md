## 1. ការស្គាល់អត្តសញ្ញាណ និងការចូល

### គោលបំណង
ឱ្យមនុស្សត្ូវបានចូល ាំងមនុស្ផ្សេងចេញ ហើយរក្សាកំណត់រឿងអំពីអ្នកណាធ្វើអ្វី។
កម្មករចូលដោយ **អ៊ីមែល + ពាក្យសមងាត់** (ហើយកូដ 2FA សម្រាប់ Admin+)។
សមាជិកចូលទៅខ្លោងទ្វារអ្នកជួលដោយ **ពាក្យសមងាត់មួយដង (OTP)**។

### អ្នកណាប្រើ
គ្រប់អនកណាមានគណនី។

### របៀបដែលការចូលដំណើរការ
1. បើកទំព័រចូល ហើយបញ្ចូល**អ៊ីមែល** និង**ពាក្យសមងាត់**របស់អ្នក។
2. ប្រសិនបើគណនីរបស់អ្នក**បើក 2FA** (ចាំបាច់សម្រាប់ Admin និង Super Admin)
   បញ្ចូលកូដ ៦ ខ្ទង់បច្ចុប្បន្ ពីកមមវិធី authenticator របស់អ្នក។
3. ចុច **Sign in**។ Cookie សន្និសីនរក្សាអ្នកឱ្យនៅក្នុង។
4. ចូលដំបូងដោយពាក្យសម្ងាត់ដែល admin កំណត់ → អ្នកត្រូវបាន**បង្ខំឱ្យផលាស់ប្ដូរ
   ពាក្យសម្ងាត់** មុនពេលធ្វើអ្វីផ្សេង។ បន្ទាប់ពីផ្លាស់ប្ដូរ សន្និសីនផ្សេង
   របស់អ្នកត្រូវបានត្រឡប់។

> ⚠️ **ច្បារ 2FA សម្រាប់ Admin+៖** Admin/Super Admin ត្រូវបញ្ចប់ការចុះឈ្មោះ
> 2FA មុនពេលសិទ្ធិម៉ូឌូលផ្សេងទៀតដំណើរការ។ រហូតដល់នោះ អ្នកអាចធ្វើតែចុះឈ្មោះ។

### ចាកចេញ សន្និសីន និងឧបករណ៍
- ប្រើ **Sign out** (ផ្នែកខាងលើនៃម៉ឺនុយ / គណនីរបស់ខ្ញុំ)។
- **My Account →** បង្ហាញ**សន្និសីន និងឧបករណ៍**របស់អ្នក ជាមួយពត៌មានឧបករណ៍/IP។ អ្នក
  អាច**ត្រឡប់** សន្និសីណាមួយ។ សន្និសីនមានរយៈពេលថ្ងៃជាក់លាក់ (env
  `SESSION_TTL_DAYS`) បន្ទាប់មកផុតកាលដោយខ្លួនឯង។
- ផ្លាស់ប្ដូរពាក្យសម្ងាត់ផ្ទាល់ខ្លួនរបស់អ្នក គ្រប់ពេលបាន នៅ **My Account → Password**។ ការផ្លាស់ប្ដូរ
  ត្រឡប់សន្និសីនផ្សេង ដើម្បី្យពាក្សម្ងាត់ថ្មីមានប្រសិទ្ធភាពគ្រប់កន្លែង។

### សុវត្ថិភាពការចូល
- ការចូលត្រូវបាន**កំណត់អត្រា** (១០ ដងក្នុងមួយនាទី ក្នុងមួយ IP)។ ការរំខានច្រើន
  ត្រូវបានកម្រិត — រង់ចាំហើយព្យាយាមម្ដងទៀត ឬទំនាក់ទំនង admin។
- កូដ OTP របស់សមាជិក ជា**ប្រើម្ដង** រក្សាទុកជា hashed ហើយ**បិទចោលបន្ទាប់ពី ៥
  ដង** — បន្ទាប់មកអ្នកត្រូវសនើកូដថ្មី។

## 2. ផ្ទាំងគ្រប់គ្រង (Dashboard)

### គោលបំណង
ការជូនដំណឹងព្រឹក និងដំណាក់ចាប់ផ្ដើមរបស់អ្នក៖ សណ្ឋាគារ ប្រាក់ ការព្យាបាល និងតំណាញ់រហ័ស។

### អ្នកណាប្រើ
គ្រប់តួនាទី (លេខត្រូវបានកំណត់ដោយខ្លួនង ត្រឹមអ្វីដែលតួនាទី/អចលនទ្រពយរបស់អ្នកអាចមើល)។

### អ្វីដែលម៉ែត្រ foreach មានន័យ
| ម៉ែត្រ | អត្ថន័យ |
|---|---|
| **សមាមាត្រសណ្ឋាគារ %** | បន្ទប់ដែលមានអ្នកស្នាក់  បន្ទប់សរុប (ឧ. `80%` = បន្ទប់ ៨ ក្នុង ០) |
| **អចលនទ្រព្យ** | ចំនួនអចលនទ្រព្យ ជាមួយចំនួនអគារ |
| **បន្ទប់ / គ្រែ** | បន្ទប់ និងគ្រែសរុបក្នុងសារពត៌មាន |
| **តម្លៃបណ្ណប្រចាំខែ** | បូកបញ្ចូលតម្លៃមូលដ្ឋានបន្ទប់រាល់ផ្ទាំង (លេខយោងរបស់កម្មសិទ្ធ) |
| **អ្នកប្រើ / សមាជិក** | ចំនួនអ្នកប្រើកម្មករ និងសមាជិក (solicitor + អ្នកសនាក់) |
| **បានប្រមូល vs បានគណនា (ខែ)** | ការទូទាត់បានបញ្ជាក់ដែលទទួល ប្រឆាំងវិក្កយបត្រដែលចេញខែនេះ |
| **Arrears (លំណូល)** | ចំនួនសរុបដែលនៅត្រូវបង់ លើវិក្កយបត្រដែលបើក (issued/partial/overdue) |
| **ស្ថានភាពប្រាក់សាច់** | តម្លៃបញ្ជីរបស់គណនីប្រាក់សាច់ (1100) + ធនាគារ (1200) |
| **សំបុត្របើក** | សំបុត្រជួសជុលដែលនៅបើក/បានផ្ដល់/កំពុងធ្វើ |
| **កាត Rent dues (M33)** | វិក្កយបត្រ**ជិតដល់ថ្ងៃ** (ក្នុងចំនួន "ថ្ងៃមុន" ដែលបានកំណត់) និង**ផុតកំណត់** ជាមួយសមាជិក កូដវិក្កយបត្រ និងចំនួន |
| **សកម្មភាពថ្មីៗ** | ចំណុចត្រាត្រួតពិនិត្យចុងក្រោយ (អ្នកណាធ្វើអ្វី) |
| **ចាប់ផ្ដើមរហ័ស** | កាតមួយចុច ទៅម៉ូឌូល foreach ដែលតួនាទីរបស់អ្នកអាចបើក |

### ក្បួនល្អបំផុត
ចាប់ផ្ដើមរាល់ថ្ងៃដោយស្កេន **Rent dues** និង **Arrears** បន្ទាប់មកធ្វើការលើ
បញ្ជីផុតកំណត់។ កាត dues ភ្ជាប់តរង់ទៅរបាយការណ៍ **Overdue & not paid**។

## 3. អចលនទ្រព្យ និងបន្ទប់ (M04)

### គោលបំណង
កំណត់សារពត៌មានរូបវន្ត៖ **អចលនទ្រព្យ → អគារ → ជាន់ → បន្ទប់ → គ្រែ**។
អ្វីផ្សេងទាំងអស់ (កិច្ចសនយាជួល វិក្កយបត្រ សំបុត្រ) ចាញ់លើបន្ទប់។

### អ្នកណាប្រើ
Admin/អ្នកគ្រប់គរងអចលនទ្រព្យ បង្កើត និងកែសម្រួល។ កម្មករអាន។ ម្ចាស់អានអគារផ្ទាល់ខ្លួន។

### មុនពេលចាប់ផ្ដើម
អ្នកត្រូវការចូល `M04` និង (សម្រាប់តួនាទីកម្រិតអចលនទ្រពយ) ការចែកចាយទៅអចលនទ្រព្យ។

### ជំហានបន្តិចម្ដង — បង្កើតឥត្ថិភាព
1. **Portfolio → Properties → New property**។ បញ្ចូល**កូដ** ឈ្មោះ អាសយដ្ឋាន តំបន់ផែនទី/geofence ជម្រើស។
2. បើកអចលនទ្រព្យ ហើយ**បន្ថែមអគារ** (ឧ. "Building A")។ អគារអាចភ្ជាប់ទៅ**ម្ចាស់**។
3. **បន្ថែមជាន់** (ឈ្មោះ + លេខជាន់)។
4. **បន្ថែមបន្ទប់** មួយម្ដង ឬប្រើ**អ្នកត្ដមនិកបង្កើតបន្ទប់ដរត្រា** (prefix លេខចាប់ផ្ដើម ចំនួន គ្រែក្នុងមួយបន្ទប់ ប្រភេទ តម្លៃមូលដ្ឋាន)។
5. នៅលើបន្ទប់ foreach កំណត់៖ **លេខ ប្រភេទ (STANDARD/DELUXE/STUDIO/SUITE) តម្លៃមូលដ្ឋាន ទំហំ កំណត់**។
6. បន្ថែម**គ្រែ** ប្រសិនបើអ្នកជួលបន្ទប់តាមគ្រែ (co-living)។

### ម៉ាស៊ីនស្ថានភាពបន្ទប់ (ព្រមព្រៀងដោយប្រព័ន្ធ)
```
vacant → reserved → occupied → cleaning → maintenance → vacant
```
- **កិច្ចសនយាជួល draft** សម្គាល់បន្ទប់ *reserved*។ **ការបើកប្រើ** កិច្ចសន្យាជួល ធ្វើឱ្យវា *occupied*។
- **ការបញ្ចប់** កិច្ចសន្យាជួល ផ្ញើវាទៅ *cleaning*។ បន្ទាប់មកអ្នកត្រឡប់វាទៅ *vacant* (ឬ *maintenance*)។
- ការកំណត់បន្ទប់ទៅ **maintenance** ត្រូវការមូលហេតុ។ ការផ្លាស់ប្ដូរមិនត្រឹមត្រូវត្រូវបានបដិសេធន (`422`) ហើយការផ្លាស់ប្ដូរ foreach ត្រូវបានត្រាតរួតពិនិតយ។

### ការពន្យល់វាល (បន្ទប់)
| វាល | អត្ថន័យ | ចាំបាច់? | ឧទាហរណ៍ |
|---|---|---|---|
| លេខ | សញ្ញាបន្ទប់ តែមួយគត់លើជាន់ | ✔ | `A-101` |
| ប្រភេទ | ប្រភេទតម្លៃ/សម្ភារៈ | ✔ | `STUDIO` |
| តម្លៃមូលដ្ឋាន | ថ្លៃជួលខែស្តង់ដារ (minor units) | ✔ | `300.00` |
| ទំហំ / គ្រែ | ប៉ុន្មាននាក់ដែលអាចស្នាក់ | ✔ | `1` |
| ស្ថានភាព | ស្ថានភាពបច្ចុប្បន្ (មើលម៉ាស៊ីន) | ប្រព័ន្ធ | `vacant` |
| កំណត់ | អត្ថបទសេរី | ✖ | "ជិតម៉ាស៊ីនចម្រៀង" |

### អំពើ
បង្កើត កែសម្រួល មើល ស្វែងរក/ត្រាស់, **បង្កើតបន្ទប់ដ្រត្ា**, **ផ្លាស់ប្ដូរស្ថានភាព
បន្ទប់** (ជាមួយមូលហេតុ) archive (soft delete)។ អចលនទ្រពយ/បន្ទប់អាច **archive** បាន
តែប្រសិនបើវាគ្មានប្រវត្តិកិច្ចសន្យាជួល — មិនដូច្នេះ វានៅសម្រាប់កំណត់រឿង។

### លទ្ធផល
បន្ទប់បង្ហាញនៅលើក្រាត់បន្ទប់ពិត (ពណ៌តាមស្ថានភាព) ហើយស្ថិតិសណ្ឋាគារ
ធ្វើទំនើបកម្ម នៅលើផ្ទាំងគ្រប់គ្រង និងរបាយការណ៍។

### កំហុសជួញជុំ
- ព្យាយាមលុបបន្ទប់ដែលមានប្រវតតិ → ប្ើ **archive** (ហើយតែនៅពេលដែលអនុញ្ញាត)។
- ភ្លេចត្រឡប់បន្ទប់ពី *cleaning* ទៅ *vacant* → វាមិនអាចជួលឡើងវិញបាន។
- កំណត់តម្លៃនៅលើបន្ទប់ ប៉ុន្តែតម្លៃផ្សេងនៅលើកិច្ចសន្យាជួល — **តម្លៃកិច្ចសនយាជួល ជាអ្វីដែលត្រូវបានគណនា**។

> ✅ **ក្បួនល្អបំផុត៖** ធ្វើស្តង់ដារកូដបន្ទប់ (`Building-Floor-Room`) និងប្រើ
> អ្នកឧត្ដមនិកដ្រត្រាសម្រាប់ជាន់ថ្មី។ រក្សាតម្លៃមូលដ្ឋានឱ្យទំនើប។ វាចូលរបាយការណ៍ និង
> ការប៉ាន់ស្មានតម្លៃ short-stay។

## 4. សមាជិក (M02) និងឯកសារ (M17)

### គោលបំណង
រក្សាកំណត់រឿងពេញលេញរបស់អ្នកជួល/អ្នកសនាក់ foreach — អត្តសញញាណ ទំនាក់ទំនង
ឯកសារ KYC ប្រវត្តិស្នាក់ តម្លៃ និងកំណត់។

### អ្នកណាប្រើ
កម្មករ/Managers បង្កើត និងធ្វើទំនើបកម្ម។ គណនីអាន។ ម្ចាស់អាន (អគារផ្ទាល់ខ្លួន)។ សមាជិកមើលតែផ្ទាល់ខ្លួន។

### វដ្តជីវិតសមាជិក (ព្រមព្រៀងនៅ server-side)
```
prospect → verified → active → notice → moved_out
        (សញ្ញា blacklisted អាចឃាំងគ្រប់អវី)
```
- **prospect → verified** ត្រូវការ**បញ្ជីផ្ទៀងផ្ទាត់ KYC ពេញលេញ** (ប្រភេទ
  ឯកសារចាំបាច់រាល់ផ្ទាំង បានឡូត មិនផុតកាល)។
- **verified → active** កើតឡើងដោយខ្លួនង នៅពេលកិច្ចសនយាជួលតរូវបាន**បើកប្រើ**។
- **notice** = សមាជិកបានផ្ដល់ដំណឹងចាកចេញ។ **moved_out** = កិច្ចសន្យាជួលបញ្ចប់។
- **Blacklist៖** សមាជិកអាចត្រូវបានសម្គាល់ blacklisted (**មូលហេតុចាំបាច់**
  ត្រាត្រួតពិនិត្យ)។ Blacklist ឃាំងការផ្លាស់ប្ដូរវដ្តជីវិតរាល់ផ្ទាំង *និង* កិច្ចសនយាជួលថមីគ្រប់យ៉ាង។ ដកចេញ
  តាមរយៈអំពើ un-blacklist (ត្រាតរួតពិនិតយផងដែរ)។

### ជំហានបន្តិចម្ដង — អ្នកត្ដមនិកតម្កល់ (៤ ជំហាន)
1. **Portfolio → Members → New member**។
2. **ផ្ទាល់ខ្លួន៖** ឈ្មោះ ប្រភេទ (បុគ្គល/ក្រុមហ៊ុន) អ៊ីមែល ទូរស័ព្ទ។
3. **អចលនទ្រព្យ និងទំនាក់ទំនងបន្ទាន់៖** ចែកចាយអចលនទ្រព្។ បន្ថែមអ្នកទំនាក់ទំនងបន្ទាន់។
4. **ការឡូត KYC៖** ឡូត ID/បេសបស្ប៊ា និងប្រភេទឯកសារចាំបាច់ផ្សេងទៀត កំណត់ហេតុអំឡុងពេល។
5. **ពិនិត្យ** ហើយរក្សាទុក។ សមាជិកជា *prospect* រហូតដល់ KYC ពេញលេញ → បន្ទាប់មក *verified*។

### កាត់ព័ត៌មានសមាជិក
- **Profile** — ពត៌មានផ្ទាល់ខ្លួន និងទំនាក់ទំនង ស្ថានភាព សញ្ញា blacklist។
- **Lease** — កិច្ចសន្យាជួលបច្ចុប្បន្/ចាស់ និងបន្ទប់។
- **Ledger / Statement** — តម្លៃប្រាក់រង់ចាំប្រចាំ និងប្រវត្តិវិក្កយបត្រ/ការទូទាត់។
- **Documents** — ឯកសារ KYC PDF បង្កើត សញ្ញាហេតុអំឡុងពេល។
- **Activity** — ជួរពេលវេលា (ការផ្លាស់ប្ដូរស្ថានភាព ការផ្លាស់ ការទូទាត់)។

សមាជិកដែលមានវិក្កយបត្រមិនទាន់បង់ បង្ហាញ**សញ្ញា dues** (ឧ. "$265.00 due")។

### ឯកសារ (M17)
- **ឡូត** ឯកសារ ជ្រើស**ប្រភេទ** របស់វា ភ្ជាប់វាទៅសមាជិក (ឬ
  កិច្ចសនយាជួល/បន្ទប់/ម្ចាស់/កិច្ចសន្យា) ហើយកំណត់**ហេតុអំឡុងពេល**។
- ឯកសារត្រូវបានរក្សាទុក**ឯកជន**។ ការទាញយកធ្វើតាមរយៈ **signed URL មាន
  ប្រសិទ្ធភាព 120 វិនាទី** — អ្នកមិនអាចបើកឯកសារ ដោយត្រឹមតែប៉ាន់ស្មានតំណាញ់របស់វាបានទេ។
- **ការជ្រើសហេតុអំឡុងពេល** ចុះផ្ដើមនៅ ៣០ និង ៧ ថ្ងៃ (តាមព្រឹត្តិការណ៍ Telegram)។
- PDF បង្កើត (វិក្កយបត្រ ប័ណ្ណ កិច្ចសន្យា របាយការណ៍ របាយការណ៍ត្រួតពិនិត្យ)
  ត្រូវបាន**រក្សាទុកដ្រតរា** ចូលក្នុងវគ្គកំណត់។
- ការចូលត្រូវបានពិនិត្យសិទ្ធិ និងអចលនទ្រព្៖ កម្កររបស់អចលនទ្រព្ផ្សេងទទួលបាន
  ការបដិសេធ។ សមាជិក/ម្ចាស់មើលតែផ្ទាល់ខ្លួន។

### អំពើ
បង្កើត កែសម្រួល មើល ស្វែងរក/ត្រាស់ (ស្ថានភាព អចលនទ្រព្យ បណ្ដោះ), ឡូត/ជំនួស
ឯកសារ, ទាញយក (signed), កំណត់ស្ថានភាព, blacklist/unblacklist, មើល statement/QR។

### កំហុសជួញជុំ
- សម្គាល់សមាជិក verified មុនពេល KYC ពេញលេញ (ប្រពន្ធចាញវា)។
- អនុញ្ញាតឱ្យ ID ផុតកាល ដោយមិនឡូតឡើងវិញ — សញ្ញាជ្រើស ២០/៧ ថងៃមុន។
- Blacklist ដោយគ្មានមូលហេតុ (ត្រូវបានឃាំង) — តែងតែកត់ត្រាហេតុអ្វី។

> ✅ **ក្បួនល្អបំផុត៖** បញ្ចប់ KYC នៅពេលតម្កល់។ ឡូត ID ថ្មី មុនពេលចាស់
> ផុតកាល។ តែងតែពិនិត្យសញ្ញា dues មុនពេលយល់ព្រមអ្វីផទាល់ប្រាក់។

## 5. ម្ចាស់ (M03)

### គោលបំណង
កត់ត្រាម្ចាស់ផ្ទះ អគាររបស់ពួកគេ និងរបៀបដែលពួកគេទទួលប្រាក់។

### អ្នកណាប្រើ
Admin/Manager គ្រប់គ្រង។ គណនីអាន។ **តួនាទី Owner មើលតែកំណត់រឿងផទាល់ខ្លួន** (អានតែ)។

### ជំហានបន្តិចម្ដង
1. **Portfolio → Owners → New owner** (ឈ្មោះ អ៊ីមែល ទូរស័ព្ទ)។
2. បន្ថែម**វិធីបង់** — បញ្ជូនប្រាក់នាគារ ប្រាក់ទូរស័ព្ទ ប្រាក់សាច់។ មួយត្រូវបានសម្គាល់
   **primary**។ លេខគណនីត្រូវបានរក្សាទុកជា masked។
3. បង្កើត**ការចូលខ្លោងទ្វារ**របស់ម្ចាស់ (តួនាទី Owner ភ្ជាប់ទៅ party របស់ពួកគេ) ដើម្បីឱ្យ
   ពួកគេអាចចូលបាន។ ការកំណត់ពាក្យសមងាត់ឡើងវិញ មានសម្រាប់ពួកគេ។
4. **ចែកចាយអគារ** ទៅម្ចាស់។ អគារ foreach ភ្ជាប់ទៅ**ម្ចាស់តែមួយ** — ការចែកចាយទៅម្ចាស់ដែលមានវាហើយ/ផ្ទុយ ត្រឡប់ `409`។
5. ធ្វើជាផ្លូវការលក្ខខណ្ឌ ដោយ**កិច្ចសន្យាម្ចាស់** (មើលកិច្ចសនយាជួល)។

### ខ្លោងទ្វារមចាស់ (`/owners/portal`)
បង្ហាញ**អគាររបស់អ្នក** សណ្ឋាគារ ពត៌មានបង់ និងឯកសារថ្មីៗ បន្ថែម
របាយការណ៍ម្ចាស់។ ម្ចាស់**មិនអាចផ្លាស់ប្ដូរទិន្នន័យ** (អានតែ) ហើយមើលមិនឃើញ
អចលនទ្រព្យរបស់ម្ចាស់ផ្សេង — ការអានឆ្លងម្ចាស់ ត្រឡប់ `403`។

### កំហុសជួញជុំ
- ព្យាយាមចែកចាយអគារដែលមានកិច្ចសន្យាមចាស់សកមមហើយ។
- រំពឹងថាម្ចាស់នឹងកែកំណត់រឿង — ពួកគេត្រូវបានព្រមព្រៀងអានតែ។

## 6. កិច្ចសន្យាជួល និងកិច្ចសន្យា (M05)

### គោលបំណង
ព្រមព្រៀងស្នាក់ រវាងសមាជិក និងបន្ទប់/គ្រែ (**កិច្ចសន្យាជួលសមាជិក**) ហើយ
ព្រមព្រៀងគ្រប់គ្រង ជាមួយម្ចាស់ផ្ទះ (**កិច្ចសនយាម្ចាស់**)។

### អ្នកណាប្រើ
Managers/Admin បង្កើត និងប្រតិបត្តិការ។ គណនីអាន។ កម្មករអាន។ សមាជិក/ម្ចាស់មើលផ្ទាល់ខ្លួន។

### កិច្ចសន្យាជួលសមាជិក — វដ្តជីវិត
```
draft → active → notice → terminated | completed
```
- **draft** រក្សាទុកបន្ទប់ (បន្ទប់ → *reserved*)។
- **active** ផ្លាស់ប្ដូរបន្ទប់ → *occupied* សមាជិក → *active* ហើយ**កំណត់វិក្កយបត្រដំបូង**។ **ប្រាក់កក់ត្រូវបានគណនា** (វិក្កយបត្រតមរូវ)។
- **notice** = បានផ្ដល់ដំណឹងចាកចេញ។
- **terminated / completed** ផ្លាស់ប្ដូរបន្ទប់ → *cleaning* សមាជិក → *moved_out* ហើយចាប់ផ្ដើមវដ្ដ**ការបញ្ចប់ប្រាក់កក់**។

### កន្លែងដែលរកវា
កិច្ចសន្យាជួលត្រូវបានឈានដល់ នៅទំព័រ **`/leases`** (បញ្ជី **`/leases/new`** និង
**`/leases/[id]`**) ជាទូទៅបើកពីព័ត៌មានសមាជិក ឬកំណត់រឿងពាក់ព័ន្
(សញ្ញា "Leases" របាររួមមាន ប៉ុន្តែបញ្ជីត្រូវបានបើកពីបរិបទទាំងនោះ)។ ព្រមព្រៀងគ្រប់គរងរបស់ម្ចាស់ ស្ថិតក្រោម **Owners → Owner contracts**
(**`/owner-contracts`**)។

### ជំហានបន្តិចម្ដង — បង្កើតកិច្ចសនយាជួលសមាជិក
1. បើក **Leases → New** (**`/leases/new`**) ឬចាប់ផ្ដើមពីសមាជិក/បន្ទប់។
2. ជ្រើស**សមាជិក** និង**បន្ទប់/គ្រែ**។
3. កំណត់**ហេតុចាប់ផ្ដើម/បញ្ចប់** **ទំហំថ្លៃជួល** **ថ្ងៃវដ្ត** (ថ្ងៃខែដែលគណនា)
   **មូលដ្ឋានប្រកាន់** (calendar = ទំហំខែពិត ឬ 30-day)។
4. កំណត់**លក្ខខណ្ឌប្រាក់កក់** (សរុប + ចំនួនតម្រូវ)។
5. កំណត់**ថ្ងៃដំណឹង** **auto-renew** និងក្បួន**escalation** ណាមួយ។
6. **បន្ថែមសេវាកម្ម** (WiFi ជម្រករថយន្ត ប្រអប់សម្លាប — មើលសេវាកម្ម)។
7. រក្សាទុកជា **draft** ពិនិត្យ បន្ទាប់មក **Activate**។
8. **កិច្ចសន្យា PDF** ត្រូវបានបង្កើតនៅ server-side ហើយរក្សាទុកដ្រត្ា ទៅឯកសារ។

### ក្បួនសណ្ឋាគារ (ព្រមព្រៀង និងបានតេស្ត)
- **កិច្ចសន្យាជួលសកម្មមួយ ក្នុងមួយគ្រែ**។ មិនអាចលើសទំហំបាន។
- គាំទ្រកិច្ចសន្យាជួលគ្រប់បន្ទប់ ប្រឆាំងតាមគ្រែ។ អនុញ្ញាតការផ្លាស់គ្រែទទេ co-living។
- ចាប់ផ្ដើម/បញ្ចប់ចំកណ្ដាលខែ ត្រូវបាន**ប្រកាន់** ដោយខ្លួនង។
- **ការបញ្ចប់កិច្ចសន្យាជួល ត្រូវការការសម្អាត** — លំណូលត្រូវតែសូន្យ (ឬសរសេរចេញ ជាមួយ
  ការអនុម័ត) — ហើយ**ការត្រួតពិនិត្យចាកចេញបានបញ្ចប់** ជាច្បារបង្ខំ មុនពេលបញ្ចប់។

### ការកែសម្រួលកិច្ចសន្យាជួល ឱ្យមានសុវត្ថិភាព
- ខណៈ**draft** កែសម្រួលដោយសេរី។
- ពេល**active** ហើយ អ្នកមិនសរសេរប្រវត្តិឡើងវិញទេ៖ ប្រើការផ្លាស់ប្ដូរដែលគាំទ្រ
  (notice → terminate/complete) **ការចុះវិញ** ឬ**ការផ្លាស់បន្ទប់** (ផ្នែក 3.14)។
  លក្ខខណ្ឌថ្ៃជួលត្ូវបាន**snapshotted** នៅលើកិច្ចសន្យាជួល ដើម្បី្យវិកកយបត្រចាស់មិនផ្លាស់ប្ដូរទេ។

### កិច្ចសនយាម្ចាស់
- វាល៖ ម្ចាស់ អគារ **model = FIXED_RENT** (ថ្លៃជួលម៉ាស្ទ៊រខែ) **ឬ
  REVENUE_SHARE** (ភាគរយម្ចាស់ ១–១០០) បន្ថែម**ភាគរយហាមគ្រប់គ្រង** ហេតុរយៈពេល
  **ថ្ងៃវដ្តបង់** (១–២៨)។
- លេខ `OWC-…`។ កិច្ចសន្យាបើកមួយ ក្នុងមួយអគារ។
- **ការបើកប្រើ ជាប្រភពម្ចាស់ការដែលមានអំណាច** — វាធ្វើសមកាល `Building.ownerId`។ វដ្តជីវិត៖ `draft → active → terminated | expired`។

### អំពើ
បង្កើត កែសម្រួល (draft) មើល **activate** **complete** **terminate** (ជាមួយ
មូលហេតុ) ផ្ដល់ **notice** បន្ថែម/គ្រប់គ្រងសេវាកម្ម បង្កើត/ទាញយកកិច្ចសន្យា PDF។

### កំហុសជួញជុំ
- បើកប្រើកិច្ចសនយាជួល មុនពេលបន្ទប់ទទេ/សមាជិកបាន verified។
- បញ្ចប់កិច្ចសន្យាជួល ជាមួយប្រាក់នៅត្រូវបង់ ឬគ្ានការត្រួតពិនិត្យចាកចេញ (ត្រូវបានាំង)។
- បង្កើតកិច្ចសន្យាជួលពីរ នៅលើគ្រែតែមួយ (ត្រូវបានាំង)។

> ✅ **ក្បួនល្អបំផុត៖** តែងតែបើកប្រើ តែបន្ទាប់ពី KYC + បានកំណត់លក្ខខណឌប្រាក់កក់។
> ឱ្យប្រព័ន្ធប្រកាន់ — កុំគណនាខែផ្នែកដោយដៃ។

## 7. ម៉ាស៊ីនគណនាថ្លៃជួល (M06)

### គោលបំណង
សៀវភៅក្បួន ការគណនាប្រាក់ ដែលប្ដូរកិច្ចសន្យាជួល ទៅជាក្បួនវិក្កយបត្រ។ វាជា
**ក្បួនសុទ្ធ បានតេស្ត** — ប្រាក់មិនផ្លាស់ទីនៅទីនេះទេ។ វាគណនាតែអ្វីដែល*គួរ* ត្រូវបានគណនា។

### អ្នកណាប្រើ
**គណនី** ជាម្ចាស់ (គ្រប់គ្រង)។ Admin គ្រប់គ្រង។ Managers/កម្មករអាន។

### អ្វីដែលអ្នកកំណត់
- **ផែនការថ្លៃជួល** — ទំហំ ថ្ងៃវដ្ត មូលដ្ឋានប្រកាន់ (calendar / 30-day)។
- **ក្បួនប្រាក់សោភ័ណ** — ថ្ងៃរការ បន្ាប់មក **flat** fee ឬ **% នៃលំណូល**
  (ជាមួយកម្រិតក្រោម និងកម្រិតខាងលើ។ មិនដែលលើសចំនួនដែលត្រូវបង់)។
- **ក្បួនពន្ធ** — អត្រាពន្ធ ដែលបង្ហាញនៅលើវិក្កយបត្រ។
- **ក្បួនការកាត់** — ការកាត់ដែលអនុវត្ត ទៅក្បួន។

### របៀបដែលការគណនាប្រាក់ ដំណើរការ
- ការប្រកាន់ ប្រើកត្តាត្រឹមត្រូវ ដែលបង្ហាញនៅលើក្បួន (ឧ. **"17/31"** សម្រាប់ថងៃ ១៧
  នៃខែ ៣១ ថ្ងៃ លើមូលដ្ឋាន calendar)។ ថ្ងៃវដ្តតរូវបានកំណត់ ទៅថ្ងៃ ១–២៨ ដើម្បី្យ
  ខែកុម្ភៈសុវត្ថិ។
- ចំនួនសរុបខែ តែងតែបំពេញ៖ **total = Σ lines − discount + tax** (asserted
  ដោយម៉ាស៊ីន ហើយបិទដោយតេស្ត)។
- សេវាកម្ម ប្រកាន់រួមគ្នា ជាមួយថ្លៃជួល។ ការផ្អាកចំកណ្ដាលខែ ប្រកាន់ការបញ្ឈប់។

## 8. សេវាកម្ម (M12)

### គោលបំណង
Add-on ដែលគណនាប្រាក់ លើសពីថ្លៃជួល៖ **WiFi ជម្រករថយន្ត ប្រអប់សម្លាប សេវាទូទៅ**។

### អ្នកណាប្រើ
Managers/Admin គ្រប់គ្រងកាតាឡុក និងការចែកចាយ។ កម្មករចែកចាយ/ប្រើ។ សមាជិកមើលផ្ទាល់ខ្លួន។

### ម៉ូឌែលតម្លៃ
- **Fixed monthly** — ឃ្លានៅលើម៉ាស៊ីនថ្លៃជួល និងបង្ហាញរាល់ខែ។ ប្រកាន់ នៅ
  ចាប់ផ្ដើម/ផ្អាកចំកណ្ដាលខែ។
- **Per-use** — ឧ. ប្រអប់សម្លាបតាម kg ជម្រករថយន្តភ្ញៀវ — ក្លាយជា**ក្បួនវិក្កយបត្រមួយដង**។
- សេវា **Metered** អាចភ្ជាប់ ទៅការប្រើទឹកអគ្គិសនី។

### ជំហានបន្តិចម្ដង
1. **Billing → Services →** កំណត់ធាតុកាតាឡុក (ឈ្មោះ ម៉ូឌែល តម្លៃ រូបភាពជម្រើស)។
2. **ចែកចាយ** សេវាទៅកិច្ចសន្យាជួល (ហេតុចាប់ផ្ដើម/បញ្ចប់)។ ជម្រករថយន្តចែកចាយ**កន្លែង
   ជាក់លាក់ តែមួយគត់**។ WiFi បង្កើត**គណនី** ដែលបើកប្រើ/ផ្អាក ជាមួយកិច្ចសន្យាជួល។
3. សេវា fixed ហូរទៅវិក្កយបត្រខែ ដ្រត្ា។ ចុះ**ការប្រើ per-use**
   ដើម្បីបង្កើតក្បួនមួយដង។
4. **ផ្អាក** សេវា (ឧ. បោះបង់ជម្រករថយន្ត) — ការផ្អាកចំកណ្ដាលខែ ត្រូវបានប្រកាន់។

### លទ្ធផល
សេវា fixed ដែលបានចែកចាយ បង្ហាញជា `service` lines នៅលើវិក្កយបត្របង្កើតបន្ទាប់
(→ គណនីចំណូល **4100 Service Revenue**)។ ចំណុច per-use បង្ហាញជា
`one_time` lines (→ **4900**)។

### កំហុសជួញជុំ
- ចែកចាយកន្លែងជម្រករថយន្តតែមួយ ទៅកិច្ចសនយាជួលពីរ (ត្រូវបានាំង — កន្ែងតែមួយគត់)។
- ភ្លេចផ្អាកសេវា នៅពេលសមាជិកបោះបង់វា — ពួកគេនៅតែត្រូវបានគណនាប្រាក់។

## 9. ទឹកអគ្គិសនី និងម៉ែត្រ (M11)

### គោលបំណង
ថ្លៃផ្អែកលើម៉ែត្រ សម្រាប់**អគ្គិសនី ទឹក និងឧស្ម័ន**។

### អ្នកណាប្រើ
កម្មករ/Managers បញ្ចូលការអាន។ គណនីអាន។ សមាជិកមើលផ្ទាល់ខ្លួន។

### ជំហានបន្តិចម្ដង
1. បង្កើត**ម៉ែត្រ** សម្រាប់បន្ទប់/អគារ (ប្រភេទ elec/water/gas។ ការអានក្នុង
   milli-units ត្រឹមត្រូវ)។
2. កំណត់**តារីហ្វ** — អត្រាកតា ជមរើស**ប្កបដោយកម្រិត** (អត្រាផ្សេងគ្នា ក្នុងមួយចន្លោះការប្រើ)។
3. រាល់យុគ បញ្ចូល**ការអាន**មួយ៖
   - **Manual** — វាយការអានម៉ែត្រ។
   - **Estimated** — ប្រពន្ធប្រើមធ្យម នៃការអានចុងក្រោយ ៣ (បានសម្គាល់ជា estimated)។
   - **CSV import** — ឆ្លងការអានដ្រតរា។
4. ប្រព័ន្ធគណនា **charge = (ការអានថ្មី − មុន) × តារីហ្វ** (តាមកម្រិត នៅពេលដែលអនុវត្ត)។
5. ថ្លៃ**ភ្ជាប់ដ្រត្រា ទៅយុគវិក្កយបត្របនទាប់**។

### លក្ខណៈសុវត្ថិភាព
- ការអាន**លើស ២ ដងមធ្យម** ត្រូវបានសម្គាល់ជា **anomaly** (អាចជា mis-read)។
- រូបតារាង ប្រវត្តិការប្រើ **SVG** ក្នុងមួយម៉ែត្រ។

### លទ្ធផល
ថ្លៃទឹកអគ្គិសនី បង្ហាញជា `utility` lines នៅលើវិក្កយបត្របន្ទាប់ (→ **4200 Utility
Revenue**)។ គ្មានអ្វីត្រូវបានគណនាប្រាក់ រហូតដល់ការបង្កើតបន្ទាប់។

### កំហុសជួញជុំ
- បញ្ចូលការអានទាបជាងមុន (ការប្រើអវិជ្ជមាន) — ពិនិត្យមកវិញ។
- រំលងការអាន (ប្រព័ន្ធនឹងប៉ាន់ស្មានបាន ប៉ុន្តែការអានពិតល្អជាង)។
- ភ្លេចឆ្លង មុនពេលការគណនាប្រាក់ខែ — បន្ទាប់មកថ្លៃមកដល់យឺតមួយខែ។

> ✅ **ក្បួនល្អបំផុត៖** បញ្ចូលការអាន នៅថ្ងៃជាក់លាក់រាល់ខែ *មុន* ពេល
> ដំណើរការការបង្កើតវិក្កយបត្រ។ ពិនិត្យសញ្ញា spike ណាមួយ មុនពេលគណនាប្រាក់។

## 10. វិក្កយបត្រ និងការគណនាប្រាក់ប្រចាំខែ (M07)

### គោលបំណង
ប្រាក់ប្រចាំខែ ដែលសមាជិក foreach ទទួល៖ ថលៃជួល + សេវា + ទឹកអគ្គិសនី + ថ្លៃ
មួយដង − ការកាត់ + ពន្ធ (+ ប្រាក់សោភ័ណ ពេលផុតកំណត់)។

### អ្នកណាប្រើ
Accountant/Manager បង្កើត និងគ្រប់គ្រង។ កម្មករអាន។ សមាជិក/ម្ចាស់មើលផ្ទាល់ខ្លួន។

### វដ្តជីវិតវិក្កយបត្រ
```
draft → issued → partial_paid → paid
              ↘ overdue            (មួយណាក៏អាច) → void
```
- **draft** — បានបង្កើត មិនទាន់ផ្ញើ។
- **issued** — បានផ្ញើ/ើញដោយសមាជិក។ លេខបានកំណត់។ **immutable**។
- **partial_paid / paid** — កំណត់ដ្រត្រា នៅពេលការទូទាត់មកដល់។
- **overdue** — កំណត់ដោយការងារប្រចាំថ្ងៃ បន្ទាប់ពីថ្ងៃបង់ + ឈរការ។
- **void** — Super-Admin តែប៉ុណ្ណោះ **មូលហេតុចាំបាច់** ត្រាត្រួតពិនិត្យ។

### របៀបដែលថ្លៃបរចាំខែ ត្រូវបានបង្កើត
```
 Rent (prorated if mid-month)
 + Services (fixed monthly, prorated)
 + Utility charges (from meter readings)
 + One-time charges (per-use services, POS room charges, moves)
 − Discounts
 + Tax
 + Late fees (after grace, by the daily job)
 = Total due
```

### ជំហានបន្តិចម្ដង — បង្កើតវិក្កយបត្រខែនេះ
1. បញ្ជាក់ថា ការអានម៉ែត្រ និងចំណុច per-use បានចូល។
2. ទៅ **Billing → Invoices** ហើយចុច **Generate** (ការងារ
   បង្កើតវិក្កយបត្រ) ឬការងារកំណត់ ដំណើរការវា។
3. ការបង្កើត គណនាប្រាក់**កិច្ចសនយាជួលសកម្ម foreach ដែលមានរយៈពេល pending**៖
   - **Catch-up safe** — ការចូលចំកណ្ដាលខែ ដំបូងទទួលវិក្កយបត្រ stub ដែលបានប្រកាន់។
   - **Idempotent** — មានតែ**វិក្កយបត្រ live មួយ ក្នុងមួយកិច្ចសនយាជួល & រយៈពេល**
     (ការដំណើរការពីរដង មិនបង្កើតចម្លង)។
   - **លេខគ្មានរន្ធ** ក្នុងមួយអចលនទ្រពយ-ឆ្នាំ៖ `BLR-2026-0001` (លេខដែលបាន void
     **មិនដែលប្រើឡើងវិញ**)។
4. វិក្កយបត្រ foreach ទទួល**PDF ដែលរក្សាទុកដ្រត្រា** ទៅវគ្គកំណត់ឯកសារ។
5. **Issue** វិក្កយបត្រ (draft → issued) ដើម្បីផ្ញើ (សមាជិកឃើញវានៅ
   ខ្លោងទ្វារ ហើយទទួលសារ Telegram "invoice issued")។

### នៅលើវិក្កយបត្រ អ្នកអាច
- មើល**items** **credit notes** **timeline** និងចំនួនសរុប។
- ទាញយក **PDF** បង្ហាញ **QR** សម្រាប់ការទូទាត់។
- **Issue** draft។
- បន្ថែម **credit note** (≤ ចំនួនដែលត្រូវបង់។ បញ្ចប់ដរត្រានៅសូន្យ) ដើម្បីកែវិក្កយបត្រ issued។
- **Void** (Super Admin ត្រូវការមូលហេតុ)។

### ការកែតម្រូវ — កុំកែវិក្កយបត្រ issued ជាទូទៅ
- **Credit note** សម្រាប់ការកាត់/កំហុស (វិក្កយបត្រ issued ជា immutable)។
- **ប្រាក់សោភ័ណ** ត្រូវបានបន្ថែមដោយការងារប្រចាំថ្ងៃ ពេលបង្អួចឈរការ បានផុត។ **ការជ្រើស
  dunning** ចេញនៅ +3 / +7 / +14 ថ្ងៃ (អាចកំណត់បាន)។

### ឧទាហរណ៍ដែលបានធ្វើ
| ក្បួន | ចំនួន |
|---|---|
| ថ្លៃជួល (ខែ) | 300.00 |
| សេវា WiFi | 15.00 |
| អគ្គិសនី (តាមម៉ែត្រ) | 32.50 |
| មួយដង (ជម្រករថយន្តភ្ៀវ) | 5.00 |
| **ចំនួនរង** | **352.50** |
| ការកាត់ (−) | −2.50 |
| ពន្ធ (+) | 0.00 |
| ប្រាក់សោភ័ណ (ពេលផុតកំណត់) | 0.00 |
| **សរុបដែលត្រូវបង់** | **350.00** |

សមាជិកបង់ 200.00 → វិក្កយបត្រក្លាយជា **partial_paid**, **ចំនួនដែលត្រូវបង់ = 150.00**។
ការបង់ phần rest ផ្លាស់វាទៅ **paid**។

### កំហុសជួញជុំ
- ដំណើរការការបង្កើត មុនពេលការអានម៉ែត្របានចូល → ទឹកអគ្គិសនីរំលងយុគ។
- ព្យាយាមកែ/លុបវិក្កយបត្រ issued — ប្រើ **credit note**។
- រំពឹងថាលេខវិក្កយបត្រដែលបាន void នឹងត្រូវបានប្រើឡើងវិញ (វាមិនដែល — គ្មានរន្ធ តាមការរចនា)។

> ✅ **ក្បួនល្អបំផុត៖** វដ្តខែតែមួយ — ការអានដំបូង បង្កើត ពិនិត្យ
> គំរូ issue បន្ទាប់មកឱ្យការជ្រើស/ប្រាក់សោភ័ណ ដំណើរការដ្រត្រា។

## 11. ការទូទាត់ និងប័ណ្ទូទាត់ (M09)

### គោលបំណង
កត់ត្រាប្រាក់ដែលបានប្រមូល ប្រឆាំងវិក្កយបត្រ ហើយចេញប័ណ្ណទូទាត់។

### អ្នកណាប្រើ
Accountant/Manager គ្រប់គ្រង។ **កម្មករ/ធម្មការ កត់ត្រាការទូទាត់ (operational write)**។
សមាជិកធ្វើផ្ទាល់ខ្លួន នៅខ្លោងទ្វារ។ ម្ចាស់អានរបស់អគាររបស់ពួកគេ។

### វដ្តជីវិតការទូទាត់
```
pending → confirmed → refunded
        ↘ failed
```

### ជំហានបន្តិចម្ដង — ទទួលការទូទាត់
1. **Billing → Payments → New payment** (ឬពីវិក្កយបត្រ/សមាជិក)។
2. ជ្រើស**សមាជិក**។ ប្រពន្ធបង្ហាញវិក្កយបត្របើករបស់ពួកគេ ជាបញ្ជី។
3. បញ្ចូល**ចំនួនការទូទាត់** និងជ្រើស**វិធី**
   **cash · bank_transfer · qr · card · cheque**។
4. រក្សាទុក។ ការទូទាត់ប្រាក់សាច់/ធនាគារ **confirmed** ដោយផ្ទាល់។ QR/gateway ចាប់ផ្ដើម
   **pending** ហើយបញ្ជាក់តាម webhook។
5. នៅពេលបញ្ជាក់៖
   - ប្រាក់ត្រូវបាន**បែងចែកទៅវិក្កយបត្រ ពីចាស់ទៅថ្មី** (ថ្ងៃបង់ បន្ទាប់មករយៈពេល)។
   - វិក្កយបត្រផ្ាស់ទៅ **partial_paid** ឬ **paid**។
   - **ប័ណ្ណទូទាត់មានលេខ** `RCP-2026-0001` PDF ត្រូវបានបង្កើត និងរក្សាទុកដ្រតរា។
   - **ចំណុចបញ្ជីតុល្យ** ចុះ។
   - អាចផ្ញើសារ**ប័ណ្ណ Telegram** ទៅសមាជិក។

### ស្ថានភាពការទូទាត់
| ស្ថានភាព | អ្វីដែលកើតឡើង |
|---|---|
| **ការទូទាត់ផ្នែក** | បែងចែកពីចាស់ទៅថ្មី។ វិក្កយបត្រ = partial_paid។ លំណូលនៅត្រូវបង់ |
| **ការទូទាត់ពេញលេញ** | វិក្កយបត្រ = paid |
| **បង់មុន / បង់លើស** | ការបែងចែកត្រូវតែស្មើការទូទាត់។ អ្វីដែលនៅសល់ រក្សាជា **member credit** (អាចត្រឡប់ ដោយគណនី តាម payout ដែលបានរំលំបញ្ជី) |
| **ការត្រឡប់** | ត្រូវការ**ការអនុម័ត Accountant+**។ រំលំតាមរយៈបញជី |
| **ការទូទាត់ gateway រលំបាត់** | សម្គាល់ failed។ គ្មានផលប៉ះពាល់ប័ណ្ណ/បញ្ជី |
| **webhook gateway ចម្លង** | ត្រូវបានមើលរំលង តាមរយៈ idempotency keys — មិនដែលចុះពីរដង មិនចេញប័ណ្ណពីរដង |

### ការពន្យល់វាល
| វាល | អត្ថន័យ | ចាំបាច់? |
|---|---|---|
| សមាជិក | អ្នកណាបង់ | ✔ |
| ចំនួន | សរុបដែលទទួល (minor units) | ✔ |
| វិធី | cash / bank_transfer / qr / card / cheque | ✔ |
| ការបែងចែក | វិក្កយបត្រណា ដែលវារង (លំនាំដើមពីចាស់ទៅថ្មី) | ប្រព័ន្ធ/កែសម្រួល |
| Gateway ref | ការយោងការទូទាត់ខាងក្រៅ (QR/card) | សម្រាប់ gateway |

### អំពើ
បង្កើត/កត់ត្រាការទូទាត់ **confirm** **fail** **refund** (អនុម័ត) មើល
ទាញយក **receipt PDF** ស្វែងរក/ត្រាស់។

### កំហុសជួញជុំ
- កត់ត្រាការទូទាត់ ប្រឆាំងសមាជិកខុស — តែងតែបញ្ជាក់អត្តសញ្ញាណ និងវិក្កយបត្រ។
- ព្យាយាមលុបការទូទាត់បានបញ្ជាក់ — ប្រើ **refund** (រំលំបញ្ជី)។
- រំពឹងថាការបង់លើសនឹង "បាត់" — វាក្លាយជា **member credit**។

> ✅ **ក្បួនល្អបំផុត៖** ចេញប័ណ្ទៅសមាជិកភ្លាម។ សមកាល
> ប្រាក់សាច់ នៅវដ្ដ/ចុងថ្ងៃ។ ឱ្យការបែងចែកពីចាស់ទៅថ្មី ដំណើរការ លើកលែងតែមាន
> មូលហេតុ ដើម្បីតម្រង់ទៅវិក្កយបត្រជាក់លាក់។

## 12. ការទូទាត់ QR (M13) និងទំព័រ /pay សាធារណ

### គោលបំណង
"បង់តាម QR" ដោយគ្មានភាពរាំងរិត សម្រាប់សមាជិក រួមទាំងការបង់ ដោយមិនចាំបាច់ចូល។

### របៀបដំណើរការ
- នៅលើវិក្កយបត្របើក foreach (និងនៅខ្លោងទ្វារអនកជួល) គ្រាប់បូតុង **Pay by QR** បង្កើត
  **ការទូទាត់ pending** ហើយបង្ហាញកូដ QR។ **កូដ idempotency ដែលកំណត់បាន**
  មានន័យថា វិក្កយបត្រតែមួយ គឺបង្កើត QR ស្ថិរជានិច្ច។
- QR ដំណើរការជាមួយ provider adapter ដែលបានកំណត់ (ប្រព័ន្ធំនើបប្ើ
  **DevMock**។ ការដាក់ប្រើពិត ភ្ជាប់ UPI / PromptPay / QRIS / តំណាញ់ gateway)។
- ការបញ្ជាក់មកដល់ តាមរយៈ**signed webhook** (`x-webhook-secret` + gateway refs តែមួយគត់)
  ជាមួយ polling ជា fallback។ webhook ចម្លង បញ្ជាក់**តែម្ដងគត់**។
- **កូដ QR របស់សមាជិក** ត្រូវបាន HMAC-signed និងបើកទំព័រ **`/pay`** សាធារណ —
  **កំណត់អត្រា តែចំនួនដែលត្រូវបង់ត្រឹមត្រូវ មិនចាំបាច់ចូល** — ហើយបានបោះពុម្ព លើ
  វិក្កយបត្រ PDF។ តារាង QR ថេរ អនុញ្ញាតការស្វែងរក តាមសមាជិក/បន្ទប់។

### អ្នកណាប្រើ
សមាជិកបង់។ កម្មករ/គណនីអាចបង្ហាញ/បញ្ជាក់។ gateway បញ្ជាក់។

> 🚫 គ្មានម៉ឺនុយ QR admin ដាច់ដោយឡែកទេ — QR ស្ថិតនៅលើវិក្កយបត្រ និង `/pay`។

## 13. ប្រាក់កក់ (M10)

### គោលបំណង
គ្រប់គ្រង**ប្រាក់កក់**ឱ្យត្រឹមត្រូវ វាជាប្ាក់ដែលរក្សាទុក (ប្រាក់រំលង) **មិនមែនចំណូល**។

### អ្នកណាប្រើ
Accountant/Manager គ្រប់គរង។ កមមករអាន។ សមាជិកមើលស្ថានភាពប្រាក់កក់ផ្ទាល់ខ្លួន។

### វដ្តជីវិតប្រាក់កក់ (append-only, ទៅមុខតែ)
```
billed → held → settled (refunded and/or deducted)
```

### របៀបដំណើរការ
- នៅពេលកិច្ចសន្យាជួលត្រូវបានបើកប្រើ ប្រាក់កក់ត្រូវបាន**គណនាដ្រត្ា** ជា
  វិក្កយបត្រតម្រូវ ប្រភេទ `deposit` (ឧ. សរុប 600 ជា ២ តម្រូវ)។
- អ្នកប្រមូលវា តាមរយៈ**វដ្ដការទូទាត់ធម្មតា**។ ការបែងចែកពីចាស់ទៅថ្មី ជ្រើស
  វិក្កយបត្រប្ាក់កក់ជាមុន។
- ប្រាក់កក់ដែលបានប្រមូល ស្ថិតនៅក្នុង**គណនី 2100 Deposit Liability** — *មិនដែល* ជាចំណូល។
- នៅពេល**ចាកចេញ** អ្នកបញ្ចប់
  - **កាត់** សម្រាប់ខូចខាត/ធ្វើសុប្បកម្ម (ត្រូវការ**ឯកសារភស្តុតាងចាំបាច់** +
    កូដមូលហេតុ)។ ការកាត់ខូចខាត/ធ្វើសុប្បកម្ម កលាយជា **other income**។ ការកាត់ថ្លៃជួលមិនទាន់បង់
    **សម្អាតប្រាក់រង់ចាំ**។
  - **ត្រឡប់** លំណូល — ការត្រឡប់ត្រូវការ**ការអនុម័តគណនី** និងប្រើ
    វិធីបង់ដែលបានរក្សាទុក។ វារំលំតាមរយៈបញ្ជី។
- ចំពោះកិច្ចសន្យាជួលដែលបានបិទ គណនីប្រាក់រំលង ត្រូវ**ស្មើសូន្យ** (ប្រាក់កក់ foreach
  ត្រឡប់ កាត់)។

### អំពើ
មើលប្រាក់កក់ កត់ត្រា/កាត់ (ជាមួយភស្តុតាង) **refund** (អនុម័ត) មើល
ប្រតិបត្តិការ/ប្រវត្តិ។

### ប្រាក់កក់ ប្រឆាំង ការទូទាត់ថ្លៃជួល
| | ការទូទាត់ថ្លៃជួល | ប្រាក់កក់ |
|---|---|---|
| អ្វីដែលវាជា | ចំណូលសម្រាប់ខែ | ប្រាក់ដែលអ្នក**រក្សាទុក** ហើយអាចត្រឡប់ |
| គណនីបញ្ជី | ចំណូល (4xxx) | ប្រាក់រំលង (2100) |
| អាចត្រឡប់បាន? | ទេ (វាបានចេញហើយ) | បាន (ដកការកាត់ដែលបានអនុម័ត) |

### កំហុសជួញជុំ
- ចាត់ទុកប្រាក់កក់ជាចំណូល — វាជាប្រាក់រំលង រហូតដល់បញ្ចប់។
- កាត់ដោយគ្មានភស្តុតាង/មូលហេតុ (ត្រូវបានាំង)។
- បិទកិច្ចសន្យាជួល ជាមួយប្រាក់រំលងប្រាក់កក់ នៅតែបង្ហាញ (វាត្រូវតែស្មើសូន្យ)។

## 14. ការផ្លាស់បន្ទប់ (M16)

### គោលបំណង
ផ្លាស់អ្នកសនាក់ ពីបនទប់មួយទៅបន្ទប់ផ្សេង កណ្ដាលកិច្ចសន្យា ហើយកំណត់តម្លៃឡើងវិញឱ្យត្រឹមត្រូវ។

### អ្នកណាប្រើ
Managers/កម្មករ បង្កើត។ ត្រូវការ**ការអនុម័ត**។ សមាជិកអាច*ស្នើ*ពីខ្លោងទ្វារ។

### ដំណើរការ
```
request (portal or staff) → approve → execute
```
1. **ស្នើ** ការផ្លាស់ ជ្រើសបន្ទប់ទីបញ្ចប់ និង**ហេតុមានប្រសិទ្ធភាព**។
2. ប្រព័ន្ធបង្ហាញមុន**ប្រាក់**៖ ថ្លៃជួលថ្មីប្រកាន់ + **ថ្លៃផលាស់** − credit
   សម្រាប់ថ្លៃជួលចាស់មិនទាន់ប្រើ = វិក្កយបត្រ**កែសម្រួល**មួយ (delta ប្រកាន់ត្រឹមត្រូវ)។ បន្ថែម
   delta ប្រាក់កក់ណាមួយ។ ការចាប់ឆ្ងាយការគណនាប្រាក់ ដំណើរការជាមុន ដើម្បី្យ credit ជាប្រាក់គណនាពិត។
3. **អនុម័ត** បន្ទាប់មក **Execute**៖
   - កិច្ចសន្យាជួលចាស់បញ្ចប់។ កិច្ចសន្យាជួលថ្មីចាប់ផ្ដើម។
   - **ស្ថានភាពបន្ទប់ទាំងពីរផ្លាស់ប្ដូរ** (ចាស់ → cleaning ថ្មី → occupied)។
   - **ជួរប្រាក់កក់តាមសមាជិក**។
   - វិក្កយបត្រកែសម្រួលមួយ ផ្ទុក delta សុទ្ធ។
   - ប្រវតតិការផ្លាស់ពេញលេញ បង្ហាញ នៅលើជួរពេលវេលាសមាជិក។
4. ការត្រួតពិនិត្យចាកចេញ/ចូល ជម្រើស អាចភ្ជាប់បាន។
5. សំណើអាច**បោះបង់** មុនពេលអនុវត្ត។

### កំហុសជួញជុំ
- ជ្រើសហេតុមានប្រសិទ្ធភាព នៅក្នុងអតីត ដោយមិនរំពឹងការគណនាប្រាក់ចាប់ឆ្ងាយ។
- ភ្លេចថា បន្ទប់ចាស់ទៅ *cleaning* (មិនទៅ vacant ផ្ទាល់)។

## 15. ការត្រួតពិនិត្យ (M18)

### គោលបំណង
ការពិនិត្យស្ានភាពបនទប់ រចនាសម្ព័ន្ធ៖ **ចូល ចាកចេញ និងប្រចាំរយៈពេល**។

### អ្នកណាប្រើ
កម្មករ/Managers ប្រពរឹត្ត។ សមាជិកមើលផ្ទាល់ខ្លួន។ ម្ចាស់អាន។

### ជំហានបន្តិចម្ដង
1. ជ្រើស**template ត្រួតពិនិត្យ** (ផ្នែក/ធាតុ ក្នុងមួយប្រភេទបន្ទប់)។
2. បង្កើតការត្រួតពិនិត្យ សម្រាប់បន្ទប់ (ប្រភេទ = move_in / move_out / periodic)។
3. ចំពោះធាតុ foreach សម្គាល់ **pass / fail / NA** បន្ថែម**រូបថត** និងកំណត់។ ប្រព័ន្ធ
   គណនា**ពិន្ទុ**។
4. កត់ត្រា**ការរកឃើញ** សម្រាប់ការរាង។ ការរកឃើញ **ចាកចេញ** អាច៖
   - **បើកសំបុត្រការជួសជុល** ឬ
   - **អនុសាសការកាត់ប្រាក់កក់** (អនុម័តក្នុង Deposits, M10)។
5. បញ្ចប់វា — **របាយការណ៍ PDF** ត្រូវបានរក្សាទុកដ្រត្រា ទៅឯកសារ។

### ក្បួនសំខាន់
**ការត្រួតពិនិត្យចាកចេញដែលបានបញ្ចប់ ជាច្បារបង្ខំ** សម្រាប់បញ្ចប់កិច្ចសន្យាជួល។ អ្នក
មិនអាចបញ្ចប់ការចាកចេញ ដោយគ្មានវាបានទេ។

## 16. ការជួសជុល (M19)

### គោលបំណង
តាមដានការជួសជុល ពីការប្រកាច់ ដល់ការបិទបានផ្ទៀងផទាត់ ជាមួយថ្លៃដើម និងផ្នែក។

### វដ្តជីវិតសំបុត្រ
```
open → assigned → in_progress → resolved → verified/closed
```
**គោលដៅ SLA តាមអាទិភាព** (urgent ៤ ម៉ោង … low ១៦៨ ម៉ោង)។ **ការស្កេនបំផ្លាញ**
ប្រចាំថ្ងៃ សម្គាល់សំបុត្រផុតកាល។ ការជូនដំណឹងឡើងកម្រិត ធ្វើតាម Telegram។

### ជំហានបន្តិចម្ដង
1. សំបុត្រត្ូវបានលើក (សមាជិក តាមរយៈ portal/Telegram ឬកម្មករ)៖ បរភេទ អាទិភាព
   បន្ទប់/អគារ ប្រាប់អ្នក។
2. **ផ្ដល់** ទៅបច្ចេកនិក ឬអ្កផ្គត់ផ្គង់។
3. ធ្វើវា (**in_progress**)។ កត់ត្រាថ្លៃដើម**ពំណត់** ហើយ**ប្រើផ្នែកស្តុក**
   (M15) — ថ្លៃផ្នែកហូរទៅសំបុត្រដរត្រា។
4. **Resolve** បន្ទាប់មក **verify/close**។ ថ្លៃដើមត្រូវបានបញ្ជូន ទៅ**ចំណាយ**
   (M20) ឬទៅ **P&L របស់ម្ចាស់** (ម្ចាស់សង → M24 statement)។

### អំពើ
បង្កើត ផ្ដល់ ធ្វើទំនើបកម្មស្ថានភាព ប្រើផ្នែក បន្ថែមថ្លៃដើម resolve verify/close មើល។

> ✅ សមាជិកវាយតម្លៃការដោះស្រាយ ក្នុងករណីដែលអនុវត្ត (តាមរយៈ complaints)។ តាមដាន
> ចំនួន **Open tickets** នៅលើផ្ទាំងគ្រប់គរង និងការបំផ្លាញ SLA។

## 17. ការតវ៉ា (M22)

### គោលបំណង
ដោះស្រាយការរិវល់របស់សមាជិក ជាមួយវិញ្ញាសាច្បាប់ចបាស់។

### វដ្តជីវិត
```
new → acknowledged → in_progress → resolved → closed
```
- ខ្សែស្រួចមតិ រូបថត អាទិភាព ជាមួយ **SLA**។
- **ការប្ដូរមួយចុច** ទៅសំបុត្រការជួសជុល ប្រសិនបើវាជាការជួសជុល។
- សមាជិក**បញ្ជាក់ការដោះស្រាយ និងវាយតម្លៃ ១–៥**។
- ម្ចាស់អាចលើក/សរសេរមតិ លើសំបុត្រផ្ាល់ខ្លួន។

### កំហុសជួញជុំ
- ទុកការតវ៉ានៅ "new" ឆ្លង SLA — ទទួលស្គាល់ឆាប់។ ការបំផ្លាញត្រូវបានស្កេនប្រចាំថ្ងៃ។

## 18. POS (M14)

### គោលបំណង
កាស៊ែរ មាត់កម្ម / ម្ហូប / ហាង៖ លក់ផលិតផល បោះពុម្ពបណ្ណ ទទួលប្រាក់សាច់/QR/កាត
ហើយគណនាទំនិញទិញ ទៅបន្ទប់អ្នកស្នាក់។

### អ្នកណាប្រើ
កម្មករ/ធម្មការ ប្រតិបត្តិការ (operational write)។ Managers គ្រប់គ្រងផលិតផល។ គណនីអាន។

### វដ្ដវិដ្ដកាស៊ែរ
```
open session (opening float) → sales… → close session (count cash → variance)
```
1. **បើកវដ្ដ POS** ជាមួយប្រាក់សាច់ float បើករបស់អ្នក។
2. បន្ថែមផលិតផលទៅការលក់ (ស្កេន**បាល់កូដ/EAN-13** បាច ឬជ្រើសពីកាតាឡុក)។
3. ទទួលការទូទាត់៖ **cash / QR / card** ឬ **គណនាទៅបន្ទប់**៖
   - **គណនាទៅបន្ទប់** ចេញ**វិក្កយបត្រមួយដង**ដ្រត្រា ទៅសមាជិក ហើយចុះ
     ទៅប្រាក់រង់ចាំ។
4. **receipt PDF** ត្រូវបានរក្សាទុកដ្រត្រា។ ការកំណត់បោះពុម្ព thermal (58/80 mm
   auto-print ចម្លង) ស្ថិតនៅ **Settings → Printers**។
5. ការលក់**ដកផ្នែកស្តុកដែលបានភ្ជាប់** (M15)។
6. **បិទវដ្ដ** ប្រាក់សាច់រង់ចាំ = float + Σ ការលក់ប្រាក់សាច់។ បញ្ចូល
   ប្រាក់សាច់ដែលបានរាប់។ ប្រព័ន្ធរកសាទុក**variance**។

### ផលិតផល (POS Catalog)
ផលិតផលភ្ជាប់ទៅផ្នែកស្តុក មានរូបភាព និង**ស្លាកបាល់កូដ**ដែលបានបោះពុម្ព។

### កំហុសជួញជុំ
- លក់ដោយគ្មានវដ្ដបើក។
- ភ្លេចបិទវដ្ដ (variance ប្រាក់សាច់មិនត្រូវបានកត់ត្រា)។
- គណនាទៅបន្ទប់ សម្រាប់ភ្ញៀវដែលគ្មានកិច្ចសន្យាជួល — គណនាទៅបន្ទប់ ត្រូវការសមាជិក។

## 19. ស្តុក និងលិខិតបញ្ជាទិញ (M15, M29)

### គោលបំណង
ការគ្រប់គ្រងសម្ភារៈ ជាមួយ**ថ្លៃដើម moving-average** និង**បញ្ជីចលនា append-only**។

### អ្នកណាប្រើ
កម្មករ/Managers ធ្វើការស្តុកប្រតិបត្តិការ។ គណនីអានការវាយតម្លៃ។ PO ត្រូវការចូល M29។

### ក្បួនមាស
**អ្នកមិនដែលវាយចំនួនដោយផ្ទាល់ទេ។** ការផ្លាស់ប្ដូរ On-hand តាមរយៈ**ចលនា**តែ៖
`purchase · sale · consumption · maintenance_use · adjustment · transfer`។

### ផ្នែកស្តុក និងប្រភេទ
- ផ្នែកស្ថិតក្នុង**ប្រភេទ** មាន**ឯកតា** (បញ្ជីកតា អាចកំណត់បាន នៅ
  Settings) **កម្រិតស្តុកទាប** និងថ្លៃដើម moving-average។
- អ្នកផ្គត់ផ្គង់ត្រូវបានកត់ត្រា។ ការទិញអាចទទួលបាន តាមរយៈ**លិខិតបញ្ជាទិញ**។

### លិខិតបញ្ជាទិញ (M29)
1. បង្កើត PO ទៅអ្នកផ្គត់ផ្គង់ (ក្បួន = ផ្នែក + ចំនួន)។
2. **Place** វា (កត់ត្រាគណនេយ្យតែ — ស្តុកមិនផ្លាស់ប្ដូរនៅឡើយទេ)។
3. **Receive** ផ្នែក — ការទទួល បង្កើតចលនា purchase ហើយ**ផ្លាស់ប្ដូរ on-hand**។
   **ការទទួលផ្នែក** រក្សា PO ជា placed រហូតដល់អ្វីៗមកដល់។

### ចលនាផ្សេងទៀត
- **Sale** (តាមរយៈ POS) **consumption** (ផ្ទៃក្នុង) **maintenance_use** (ផ្នែក នៅលើ
  សំបុត្រ) **transfer** រវាងទីតាំង **adjustment** (តាមរយៈការរាប់ស្តុក)។
- **ការរាប់ស្តុក** រាប់ពិត ប្រឆាំងប្រព័ន្ធ។ variance ចុះ**adjustment** ជាមួយ
  delta ការវាយតម្លៃ។
- **ការព្យាបាលស្តុកទាប** ចុះផ្ដើម (ហើយអាចដល់កម្មករ តាមរយៈ Telegram)។
- **របាយការណ៍ការវាយតម្លៃ** ផ្ដល់តម្លៃ on-hand (moving-average)។

### ឧទាហរណ៍ចំនួនដែលបានធ្វើ
ទិញ 10 → លក់ 3 តាមរយៈ POS → ប្រើ 1 នៅលើសំបុត្រ → **on-hand = 6** ហើយ
របាយការណ៍ការវាយតម្លៃ បញ្ជាក់ថ្លៃដើម moving-average របស់ 6។

### កំហុសជួញជុំ
- ព្យាយាមកែចំនួនដោយផ្ទាល់ (មិនអនុញ្ញាត — ប្រើចលនា/ការរាប់ស្តុក)។
- សម្គាល់ PO ទទួលហើយ ពេលវាត្រឹមតែ placed (ការ place មិនផ្លាស់ប្ដូរអ្វីទេ)។

## 20. ការវត្តមាន (M23)

### គោលបំណង
ការតាមដានពេលវេលាកម្មករ សម្រាប់ប្រាក់កម្ម និងប្រតិបត្តិការ។

### អ្នកណាប្រើ
**កម្មករចុះ/ឡើងផ្ទាល់ខ្លួន** (OWN scope)។ Managers ពិនិត្យ។ គណនីអានសង្ខេប។

### របៀបដែលការចុះ ដំណើរការ
- **Kiosk PIN** ចុះ/ឡើង នៅ terminal រួម (PIN រក្សាទុកជា hashed) — មិនចាំបាច់មានសន្និសីន browser ទេ។
- **Mobile** ចុះ/ឡើង ជម្រើសជាមួយ**geofence** អចលនទ្រព្។ punches នៅករៅកាំ បង្កើត **exception**។
- **Shifts** កំណត់កាលវិភាគ ជាមួយ**បង្អួចឈរការ** និង**ក្បួនការងារលើស** (multipliers សាមញ្ញ)។

### Exceptions (បានដកដោយខ្លួនឯង)
late · early departure · ភ្លេចចុះ-ឡើង · ការងារលើស · លំខ្ទង់ geofence។
**attendance-sweep** ប្រចាំថ្ងៃ សម្គាល់ punches បើកដែលចាស់ ជា ភ្លេចចុះ-ឡើង។
Managers **ដោះស្រាយ** exceptions ជាមួយមូលហេតុ។ ការកែតម្រូវត្រូវបាន**ត្រាត្រួតពិនិត្យ**។

### លទ្ធផល
- **សង្ខេបប្រចាំខែ ក្នុងមួយកម្មករ**។
- **ការនាំចេញប្រាក់កម្ម CSV**។

### កំហុសជួញជុំ
- ភ្លេចចុះ-ឡើង (sweep សម្គាល់វា។ manager ដោះស្រាយវា)។
- ចុះឆ្ងាយពីអចលនទ្រពយ ដោយគមានមូលហេតុ (exception geofence)។

## 21. ការស្នាក់ខ្លី / ការកក់បែបសណ្ឋាគារ (M32)

### គោលបំណង
ជួលបន្ទប់ **តាមម៉ោង ឬថ្ងៃ** ទៅភ្ញៀវ (បែបសណ្ឋាគារ) រួមគ្នាជាមួយកិច្ចសន្យាជួលយូរ។

### អ្នកណាប្រើ
Managers/កម្មករ បង្កើតការកក់ (ប្រតិបត្តិការ)។ គណនីអាន។

### គោលគំនិត
- **Rent modules** កំណត់ផលិតផល៖ ឧ. "hourly" ជាមួយយុទ្ធសាសត្រគណនាប្រាក់
  (**progressive** bucket table ឬ **blended** = bucket + full-day carry)
  រយៈពេលតិចបំផុត/ច្រើនបំផុត លំនាំដើមប្រាក់កក់ ភ្ញៀវតិចបំផុត/ច្រើនបំផុត។ ម៉ូឌូលអាចជា global ឬក្នុងមួយអចលនទ្រព្។
- **Rate rules** កំណត់តម្លៃ ក្នុងមួយម៉ូឌូល/បន្ទប់/រយៈពេល។

### ដំណើរការការកក់
1. បង្កើត**ការកក់**៖ ម៉ូឌូល បន្ទប់ check-in/out ភ្ញៀវ ្មោះ/ទូរស័ព្ទ/ID របស់ភ្ញៀវ
   (ជម្រើសភ្ជាប់ព័ត៌មានសមាជិក) ប្រាក់កក់ជម្រើស។ របៀប **direct** ឬ **tab**។
2. **ការប៉ាន់ស្មានតម្លៃ** គណនាតម្លៃ។ នៅពេលបញ្ជាក់ តម្លៃត្រូវបាន**snapshotted**
   (គណនាឡើងវិញ នៅពេលពង្រីក)។
3. ការកក់ មានលេខ `STY-2026-0001` និងមានស្ថានភាព៖
   `requested → confirmed → checked_in → checked_out` បន្ថែម `no_show / cancelled / void`។
4. ប្រាក់កក់ដែលបានប្រមូលពីមុន **credited នៅពេល check-out**។

> ម៉ូឌូលនេះត្រូវបានបើក ក្នុងមួយអចលនទ្រព្។ សួរអនកគ្រប់គ្រងរបស់អ្នក បើ short stays ជាផ្នែកនៃប្រតិបត្តិការរបស់អ្នក។
