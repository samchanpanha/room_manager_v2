## 1. 身份验证与登录

### 目标
让对的人进来，把其他人挡在外面，并记录谁做了什么。员工用
**邮箱 + 密码**（Admin+ 还需要 2FA 验证码）登录。
会员用**一次性密码（OTP）**登录租户门户。

### 谁在用
所有有账户的人。

### 登录怎么工作
1. 打开登录页，输入你的**邮箱**和**密码**。
2. 如果你的账户**开启了 2FA**（Admin 和 Super Admin 强制），
   输入验证器 App 里当前的 6 位验证码。
3. 点击 **Sign in**。会话 cookie 保持你登录状态。
4. 首次用管理员设置的密码登录 → 你**必须先改密码**
   才能做其他事。改完后，你的其他会话被吊销。

> ⚠️ **Admin+ 的 2FA 闸门：** Admin/Super Admin 必须完成 2FA
> 注册，其他任何模块权限才生效。在此之前你只能注册 2FA。

### 登出、会话与设备
- 用 **Sign out**（菜单顶部 / My Account）。
- **My Account →** 显示你的**会话与设备**（含设备/IP 信息）；你可以
  **吊销**任何会话。会话持续固定天数（环境变量
  `SESSION_TTL_DAYS`）后自动过期。
- 随时在 **My Account → Password** 修改自己的密码。修改会
  吊销其他会话，使新密码在所有地方生效。

### 登录安全
- 登录**限流**（每 IP 每分钟 10 次）。连续失败
  会被节流 — 等一等再试，或联系管理员。
- 会员门户 OTP 码**一次性**、哈希存储、**5 次后锁定** —
  之后必须重新申请验证码。

### 无法登录时
| 症状 | 怎么办 |
|---|---|
| "邮箱或密码无效" | 重新检查拼写；密码区分大小写 |
| 被要求输入你手上没有的 2FA 码 | 联系 Super Admin **重置你的 2FA**（`M27` 管理重置），然后重新注册 |
| "账户已禁用" | 你的账户被管理员禁用了 — 联系他们 |
| 被强制改密码 | 设置新密码（新账户属正常） |
| 多次尝试后被锁 | 等待，或请管理员重置密码 |
| 会员 OTP "尝试次数过多" | 申请新的 OTP 码 |

> 🚫 **当前系统未提供：** 自助"忘记密码"邮件重置链接。密码由管理员
> 重置（设置带必须修改标记的临时密码）或在登录状态下修改。
> 当前版本没有邮件通道（见第 7 部分）。

## 2. 仪表板

### 目标
你的每日简报和发射台：入住率、资金、告警和快捷入口。

### 谁在用
所有角色（数字自动限定在你的角色/物业可见范围内）。

### 各指标的含义
| 指标 | 含义 |
|---|---|
| **入住率 %** | 已住房间 ÷ 总房间（如 `80%` = 10 间住了 8 间） |
| **物业数** | 物业数量，含楼宇数 |
| **房间 / 床位** | 库存中的房间和床位总数 |
| **月度账面价值** | 所有房间基准价之和（组合参考数字） |
| **用户 / 会员** | 员工用户和会员（ prospective + 住户）数量 |
| **已收 vs 已出账（月）** | 本月已确认收款 vs 已开出账单 |
| **欠款（Arrears）** | 未结账单（issued/partial/overdue）尚欠总额 |
| **现金头寸** | Cash（1100）+ Bank（1200）账户的账本余额 |
| **未结工单** | 仍 open/assigned/in progress 的维修工单 |
| **Rent dues（M33）卡** | **即将到期**（在配置的"提前天数"内）和**逾期**账单，含会员、账单号和金额 |
| **近期活动** | 最新审计条目（谁做了什么） |
| **快捷启动** | 一键磁贴，直达你角色能打开的所有模块 |

### 最佳实践
每天从扫描 **Rent dues** 和 **Arrears** 开始，然后处理逾期
清单。dues 卡直接链接到 **Overdue & not paid** 报表。

## 3. 物业与房间（M04）

### 目标
定义物理库存：**物业 → 楼宇 → 楼层 → 房间 → 床位**。
其他一切（租约、账单、工单）都挂在房间上。

### 谁在用
Admin/物业经理 创建和编辑；Staff 查看；Owner 查看自己的楼宇。

### 开始前
你需要 `M04` 权限，以及（对物业级角色）被分配到该物业。

### 分步 — 创建层级
1. **Portfolio → Properties → 新建物业**。输入唯一**代码**和名称、地址、可选地图坐标/geofence。
2. 打开物业，**添加楼宇**（如 "Building A"）。楼宇可关联**业主**。
3. **添加楼层**（名称 + 层号）。
4. 逐个**添加房间**，或用**批量建房向导**（前缀、起始号、数量、每房床位数、类型、基准价）。
5. 每个房间设置：**房号、类型（STANDARD/DELUXE/STUDIO/SUITE）、基准价、容量、备注**。
6. 如果你按床出租（co-living），添加**床位**。

### 房间状态机（系统强制）
```
vacant → reserved → occupied → cleaning → maintenance → vacant
```
- **草稿租约**把房间标为 *reserved*。**生效**租约使其 *occupied*。
- **结束**租约使其进入 *cleaning*；然后你把它恢复 *vacant*（或 *maintenance*）。
- 把房间设为 **maintenance** 需要原因。非法流转被拒绝（`422`），每次流转都留审计。

### 字段说明（房间）
| 字段 | 含义 | 必填? | 示例 |
|---|---|---|---|
| 房号 | 房间标签，楼层内唯一 | ✔ | `A-101` |
| 类型 | 定价/设施分类 | ✔ | `STUDIO` |
| 基准价 | 标准月租（minor units） | ✔ | `300.00` |
| 容量 / 床位 | 可住几人 | ✔ | `1` |
| 状态 | 当前状态（见状态机） | 系统 | `vacant` |
| 备注 | 自由文本 | ✖ | "靠电梯" |

### 操作
创建、编辑、查看、搜索/筛选、**批量建房**、**变更房间状态**
（带原因）、归档（软删除）。物业/房间**只有在没有租约历史时才能归档** —
否则为留档保留。

### 结果
房间出现在实时房间网格（按状态着色），入住率统计
在仪表板和报表上更新。

### 常见错误
- 尝试删除有历史的房间 → 用**归档**（且仅在允许时）。
- 忘记把房间从 *cleaning* 恢复 *vacant* → 无法再出租。
- 房间上一个价、租约上另一个价 — **计费的是租约价**。

> ✅ **最佳实践：** 标准化房间代码（`Building-Floor-Room`），新楼层用
> 批量向导。保持基准价最新；它喂给报表和
> 短住报价。

## 4. 会员（M02）与证件（M17）

### 目标
保存每位租户/住户的完整档案 — 身份、联系方式、
KYC 证件、住宿历史、余额和备注。

### 谁在用
Staff/Manager 创建与更新；Accountant 查看；Owner 查看（自己楼宇）；会员只看自己的。

### 会员生命周期（服务端强制）
```
prospect → verified → active → notice → moved_out
        (blacklisted 标记可阻断一切)
```
- **prospect → verified** 需要**完整 KYC 清单**（所有必填
  证件类型已上传、未过期）。
- **verified → active** 在租约**生效**时自动发生。
- **notice** = 会员已提出退房通知；**moved_out** = 租约已结束。
- **黑名单：** 会员可被标记黑名单（**原因必填**、
  留审计）。黑名单阻断所有生命周期流转*以及*任何新租约。用
  解除黑名单操作移除（同样留审计）。

### 分步 — 入驻向导（4 步）
1. **Portfolio → Members → 新建会员**。
2. **个人信息：** 姓名、类型（个人/公司）、邮箱、电话。
3. **物业与紧急联系人：** 分配物业；添加紧急联系人。
4. **上传 KYC：** 上传身份证/护照和其他必填证件类型，设置到期日。
5. **确认**并保存。会员是 *prospect*，直到 KYC 完成 → 然后 *verified*。

### 会员档案页签
- **Profile** — 个人与联系信息、状态、黑名单标记。
- **Lease** — 当前/历史租约和房间。
- **Ledger / Statement** — 滚动应收余额和账单/收款历史。
- **Documents** — KYC 文件、生成的 PDF、到期徽章。
- **Activity** — 时间线（状态变化、换房、收款）。

有未付账单的会员会显示**欠款徽章**（如 "$265.00 due"）。

### 证件（M17）
- **上传**证件，选择其**类型**，关联到会员（或
  租约/房间/业主/合同），并设置**到期日**。
- 文件**私有**存储；下载走**120 秒有效的签名 URL** —
  你无法仅凭猜链接打开文件。
- **到期提醒**在 30 天和 7 天触发（经 Telegram 事件）。
- 生成的 PDF（账单、收据、合同、对账单、检查报告）
  **自动归档**进登记簿。
- 访问经过权限和物业校验：其他物业的员工会被拒；会员/业主只看自己的。

### 操作
创建、编辑、查看、搜索/筛选（状态、物业、欠费）、上传/替换
证件、下载（签名）、设置状态、拉黑/解除拉黑、查看对账单/QR。

### 常见错误
- 在 KYC 完成前标记会员 verified（系统会拦截）。
- 让证件过期不重传 — 徽章提前 20/7 天预警。
- 无理由拉黑（被拦截）— 始终记录原因。

> ✅ **最佳实践：** 入驻时完成 KYC；旧证到期前上传新证；
> 同意任何财务事项前先看欠款徽章。

## 5. 业主（M03）

### 目标
记录房东、他们的楼宇以及他们如何收款。

### 谁在用
Admin/Manager 管理；Accountant 查看；**Owner 角色只看自己的记录**（只读）。

### 分步
1. **Portfolio → Owners → 新建业主**（姓名、邮箱、电话）。
2. 添加**收款方式** — 银行转账、手机钱包或现金；一个被标为
   **primary**；账号掩码存储。
3. 创建业主的**门户登录**（Owner 角色，关联其 party）以便
   他们登录；可为他们重置密码。
4. **分配楼宇**给业主。每栋楼关联**恰好一个**
   业主 — 分配给已有该楼的业主 / 冲突时返回 `409`。
5. 用**业主合同**（见 Leases）正式化条款。

### 业主门户（`/owners/portal`）
显示**你的楼宇**、入住率、收款信息和近期证件，以及
业主对账单。业主**不能改数据**（只读），也看不到其他
业主的物业 — 跨业主读取返回 `403`。

### 常见错误
- 尝试分配一栋已有生效业主合同的楼。
- 期望业主能编辑记录 — 他们是有意设为只读的。

## 6. 租约与合同（M05）

### 目标
会员与房间/床位之间的入住协议（**会员租约**），
以及与房东之间的管理协议（**业主合同**）。

### 谁在用
Manager/Admin 创建与操作；Accountant 查看；Staff 查看；会员/业主看自己的。

### 会员租约 — 生命周期
```
draft → active → notice → terminated | completed
```
- **draft** 预留房间（房间 → *reserved*）。
- **active** 房间翻为 *occupied*、会员翻为 *active*，并**排定第一张账单**；**押金被开票**（分期账单）。
- **notice** = 已提出退房通知。
- **terminated / completed** 房间翻为 *cleaning*、会员翻为 *moved_out*，并触发**押金结算**流程。

### 在哪里找
租约在 **`/leases`** 页面（列表、**`/leases/new`** 和
**`/leases/[id]`**）打开，通常从会员档案或相关
记录进入（侧边栏有 "Leases" 标签，但列表从这些
上下文打开）。业主的管理协议在 **Owners → Owner contracts**
（**`/owner-contracts`**）下。

### 分步 — 创建会员租约
1. 打开 **Leases → New**（**`/leases/new`**），或从会员/房间开始。
2. 选择**会员**和**房间/床位**。
3. 设置**开始/结束日期**、**租金金额**、**计租日**（每月计租的日期）、
   **折算基准**（calendar = 实际月长，或 30 天）。
4. 设置**押金条款**（总额 + 分期数）。
5. 设置**通知天数**、**自动续租**和任何**递增**规则。
6. **添加服务**（WiFi、停车、洗衣 — 见 Services）。
7. 存为 **draft**，审阅，然后 **Activate**。
8. **合同 PDF** 在服务端生成并自动归档到证件。

### 入住规则（强制且已测试）
- **每床位一个生效租约**。容量不可超。
- 支持整房租与按床租；co-living 空床调换允许。
- 月中开始/结束自动**折算（prorate）**。
- **结束租约需要清账** — 欠款必须为零（或经审批
  核销）— 且**已完成的退房检查**是结束前的硬闸门。

### 安全地修改租约
- 在 **draft** 阶段，随意编辑。
- 一旦 **active**，不要改写历史：用支持的流转
  （notice → terminate/complete）、**续租**或**换房**（第 3.14 节）。
  租金条款在租约上**快照**，旧账单永不改变。

### 业主合同
- 字段：业主、楼宇、**model = FIXED_RENT**（月度总租金）**或
  REVENUE_SHARE**（业主分成 1–100%）外加**管理费 %**、期限日期、
  **付款周期日**（1–28）。
- 编号 `OWC-…`。每栋楼一份未结合同。
- **生效是权威的所有权来源** — 它同步
  `Building.ownerId`。生命周期：`draft → active → terminated | expired`。

### 操作
创建、编辑（draft）、查看、**activate**、**complete**、**terminate**（带
原因）、发出 **notice**、添加/管理服务、生成/下载合同 PDF。

### 常见错误
- 在房间未空置/会员未 verified 前生效租约。
- 带着欠款或没有退房检查就结束租约（被拦截）。
- 在同一床位创建两个租约（被拦截）。

> ✅ **最佳实践：** 只在 KYC + 押金条款设置后才生效；
> 让系统折算 — 别手算部分月。

## 7. 租金引擎（M06）

### 目标
把租约变成账单行的计费规则书。它是一组
**纯的、已测试的规则** — 这里不动钱；它只计算*应该*计什么费。

### 谁在用
**Accountant** 拥有它（管理）；Admin 管理；Manager/Staff 查看。

### 你配置什么
- **租金计划** — 金额、计租日、折算基准（calendar / 30 天）。
- **滞纳金规则** — 宽限天数，然后**固定**费或**欠款 %**
  （有下限和上限；绝不超过应付金额）。
- **税费规则** — 出现在账单上的税率。
- **折扣规则** — 应用于行项目的折扣。

### 计费数学怎么工作
- 折算用行上显示的精确系数（如 31 天月住 17 天、calendar 基准下的
  **"17/31"**）。计租日钳制到 1–28 日，
  二月安全。
- 月度总额恒满足：**total = Σ lines − discount + tax**（引擎断言，
  测试锁定）。
- 服务随租金一起折算；月中停用折算停用段。

> 数值例子见**第 5 部分**。

## 8. 服务（M12）

### 目标
租金之外可计费的项目：**WiFi、停车、洗衣、一般服务**。

### 谁在用
Manager/Admin 管理目录和分配；Staff 分配/使用；会员看自己的。

### 定价模型
- **固定月费** — 随租金引擎走，每月出现；月中开始/停用时折算。
- **按次** — 如洗衣按公斤、访客停车 — 成为**一次性账单行**。
- **计量**服务可关联水电用量。

### 分步
1. **Billing → Services →** 定义目录项（名称、模型、价格、可选图片）。
2. **分配**服务到租约（开始/结束日期）。停车分配**唯一的
   特定车位**；WiFi 创建一个**账户**，随租约激活/停用。
3. 固定服务自动流入月度账单；登记**按次使用**
   生成一次性行。
4. **停用**服务（如放弃停车）— 月中停用会折算。

### 结果
已分配的固定服务在下一张生成的账单上出现为 `service` 行
（→ 收入科目 **4100 Service Revenue**）；按次条目出现为
`one_time` 行（→ **4900**）。

### 常见错误
- 把同一车位分配给两个租约（被拦截 — 车位唯一）。
- 会员放弃服务时忘记停用 — 他们会一直被告费。

## 9. 水电费与电表（M11）

### 目标
基于表计的**电、水、气**收费。

### 谁在用
Staff/Manager 录入读数；Accountant 查看；会员看自己的。

### 分步
1. 为房间/楼宇创建**电表**（类型 elec/water/gas；读数用精确
   milli-units）。
2. 定义**费率表（tariff）** — 单价，可选**阶梯**（不同用量区间不同费率）。
3. 每期录入一个**读数**：
   - **Manual** — 直接输入表读数。
   - **Estimated** — 系统用最近 3 次读数的平均值（标记为 estimated）。
   - **CSV 导入** — 批量导入读数。
4. 系统计算 **charge = (新读数 − 旧读数) × 费率**（阶梯时按档）。
5. 收费**自动挂到下一期账单周期**。

### 安全特性
- 读数**超过平均值 2 倍**会被标为**异常（anomaly）**（可能读错）。
- 每表一张 **SVG 用量历史**图。

### 结果
水电费在下一张账单上出现为 `utility` 行（→ **4200 Utility
Revenue**）。下一轮生成前不计任何费。

### 常见错误
- 录入比上次低的读数（负用量）— 重新核对。
- 跳过读数（系统能估算，但真实读数更好）。
- 月度计费前忘记导入 — 然后收费晚一个月。

> ✅ **最佳实践：** 每月固定一天录入读数，*在*运行
> 账单生成之前；计费前先查任何异常标记。

## 10. 账单与月度计费（M07）

### 目标
每位会员收到的月度账单：租金 + 服务 + 水电 + 一次性费用 − 折扣 + 税（逾期后加滞纳金）。

### 谁在用
Accountant/Manager 生成与管理；Staff 查看；会员/业主看自己的。

### 账单生命周期
```
draft → issued → partial_paid → paid
              ↘ overdue            (以上任一均可) → void
```
- **draft** — 已创建，未发送。
- **issued** — 已发送/对会员可见；编号已分配；**不可变**。
- **partial_paid / paid** — 随收款到达自动设置。
- **overdue** — 到期日 + 宽限后由每日任务设置。
- **void** — 仅 Super Admin，**原因必填**，留审计。

### 月度费用如何生成
```
 Rent (prorated if mid-month)
 + Services (fixed monthly, prorated)
 + Utility charges (from meter readings)
 + One-time charges (per-use services, POS room charges, moves)
 − Discounts
 + Tax
 + Late fees (after grace, by the daily job)
 = Total due
```

### 分步 — 生成本月账单
1. 确认表读数和按次条目已录入。
2. 到 **Billing → Invoices** 点 **Generate**（账单生成
   任务），或让计划任务运行。
3. 该次运行对**所有有未结账期的生效租约**计费：
   - **补算安全（catch-up safe）** — 月中入住先收到一张折算的 stub 账单。
   - **幂等（idempotent）** — 每租约每期**至多一张活账单**
     （跑两次不会重复）。
   - **按物业-年度无缺口编号**：`BLR-2026-0001`（void 的号
     **永不复用**）。
4. 每张账单的 **PDF 自动归档**到证件登记簿。
5. **Issue** 账单（draft → issued）发送（会员在
   门户看到，并收到 Telegram "invoice issued" 消息）。

### 在账单上你可以
- 查看**items**、**credit notes**、**timeline** 和总额。
- 下载 **PDF**，显示支付 **QR**。
- **Issue** 草稿。
- 添加 **credit note**（≤ 应付金额；自动在零处结平）以更正已出账账单。
- **Void**（Super Admin，需原因）。

### 更正 — 绝不编辑已出账账单
- 减项/错误用 **credit note**（已出账账单不可变）。
- **滞纳金**在宽限期过后由每日任务添加；**催收
  提醒**在 +3 / +7 / +14 天发出（可配置）。

### 算例
| 行 | 金额 |
|---|---|
| 租金（月） | 300.00 |
| WiFi 服务 | 15.00 |
| 电费（表计） | 32.50 |
| 一次性（访客停车） | 5.00 |
| **小计** | **352.50** |
| 折扣（−） | −2.50 |
| 税（+） | 0.00 |
| 滞纳金（逾期后） | 0.00 |
| **应付总额** | **350.00** |

会员付 200.00 → 账单变 **partial_paid**，**应付 = 150.00**。
付清剩余翻为 **paid**。

### 常见错误
- 表读数没录入就跑生成 → 水电错过本期。
- 尝试编辑/删除已出账账单 — 用 **credit note**。
- 期望 void 的账单号被复用（永不 — 设计上无缺口）。

> ✅ **最佳实践：** 一个月度节奏 — 先读数、生成、抽查
> 一张、出账，然后让提醒/滞纳金自动运行。

## 11. 收款与收据（M09）

### 目标
记录收到的钱，核销到账单，并出具收款单。

### 谁在用
Accountant/Manager 管理。**员工/收银员登记收款（operational write）**。
会员在门户自助支付。业主查看自己物业的。

### 收款生命周期
```
pending → confirmed → refunded
        ↘ failed
```

### 分步 — 登记一笔收款
1. **Billing → Payments → 新建收款**（或从账单/会员页进入）。
2. 选择**会员**。系统列出其未结账单清单。
3. 输入**收款金额**并选择**方式**：
   **cash · bank_transfer · qr · card · cheque**。
4. 保存。现金/银行转账收款直接 **confirmed**。QR/网关收款先 **pending**，由 webhook 确认。
5. 确认后：
   - 金额**按账单从旧到新分摊**（先到期日，后期间）。
   - 账单变为 **partial_paid** 或 **paid**。
   - 生成**编号收款单** `RCP-2026-0001`（PDF 落盘存储）。
   - **账本分录**记入。
   - 可选**Telegram 推送**收款单给会员。

### 收款状态
| 状态 | 发生什么 |
|---|---|
| **部分收款** | 按旧到新分摊；账单 = partial_paid；剩余待付 |
| **全额收款** | 账单 = paid |
| **预付 / 超额** | 分摊必须等于收款额；剩余转为 **member credit**（可由 ledger 冲销的 payout 退回） |
| **退款** | 需要 **Accountant+ 审批**；通过 ledger 反向分录 |
| **网关收款失败** | 标记 failed；不影响账单/账本 |
| **网关 webhook 重复** | 凭 idempotency key 去重 — 绝不双记、绝不双出单 |

### 字段说明
| 字段 | 含义 | 必填? |
|---|---|---|
| 会员 | 谁付的 | ✔ |
| 金额 | 实收总额（minor units） | ✔ |
| 方式 | cash / bank_transfer / qr / card / cheque | ✔ |
| 分摊 | 抵扣哪些账单（默认旧到新，可调） | 系统/可改 |
| 网关号 | 外部支付引用（QR/卡） | 网关场景 |

### 操作
创建/登记收款 **确认** **失败** **退款**（审批）查看
下载 **收款单 PDF** 搜索/筛选。

### 常见错误
- 收错会员 — 务必核对身份和账单。
- 尝试删除已确认收款 — 用 **refund**（ledger 反向）。
- 以为超额会"丢" — 会变成 **member credit**。

> ✅ **最佳实践**：收款后立即把单发给会员。现金
> 每日/每班对账。除有明确理由定向到特定账单外，
> 让旧到新分摊自动运行。

## 12. QR 收款（M13）与公开 /pay 页

### 目标
让会员"扫一下就能付"，包括**无需登录**即可支付。

### 怎么工作
- 每条未结账单（以及会员门户）上有 **Pay by QR** 按钮，生成
  **pending 收款**并显示 QR 码。**固定幂等键**
  意味着同一账单永远生成同一个稳定 QR。
- QR 走已配置的 provider adapter（开发环境
  **DevMock**。生产接 UPI / PromptPay / QRIS / 你的网关）。

  **只显示应付金额，无需登录** — 并印在
  账单 PDF 上。静态 QR 表支持按会员/房间查询。

### 谁在用
会员支付。员工/会计可查看/确认。网关确认。

> 🚫 没有独立的 QR 管理菜单 — QR 就在账单和 `/pay` 上。

## 13. 押金（M10）

### 目标
正确管理**押金** — 它是留存的负债（代管款），**不是收入**。

### 谁在用
Accountant/Manager 管理。员工查看。会员看自己的押金状态。

### 押金生命周期（append-only，只向前）
```
billed → held → settled (退款和/或扣款)
```

### 怎么工作
- 租约**生效**时，押金被**自动开票**为
  `deposit` 类型账单（如 600 拆成 2 期）。
- 收款走**正常收款流程**。旧到新分摊优先抵扣押金账单。
- 已收押金放在 **2100 押金负债科目** — *绝不*计入收入。
- **退房**时，你
  - **扣除** 损坏/清洁费（需要**强制凭证** +
    原因代码）。损坏/清洁扣款转 **其他收入**。未付租金扣除
    **冲抵应收**。
  - **退还** 余额 — 退款需要**会计审批**，使用
    留存支付渠道。走 ledger 反向分录。
- 对已结租约，押金负债科目必须**归零**（每笔押金
  要么退、要么扣）。

### 操作
查看押金、登记/扣款（带凭证）**退款**（审批）查看
流水/历史。

### 押金 vs 租金
| | 租金收款 | 押金 |
|---|---|---|
| 是什么 | 该月收入的款 | 你**保管**、可能退还的款 |
| 账本科目 | 收入（4xxx） | 负债（2100） |
| 能退吗 | 不能（已入账） | 能（扣掉已批准扣款后） |

### 常见错误
- 把押金当收入 — 它是负债，直到 settle。
- 无凭证/原因就扣（会被拦截）。
- 租约结清时押金负债科目仍挂账（必须归零）。

## 14. 换房（M16）

### 目标
租期中把租户从一个房间换到另一个房间，并正确重算金额。

### 谁在用
Manager/员工发起。需要**审批**。会员可在门户*申请*。

### 流程
```
申请（门户或员工）→ 审批 → 执行
```
1. **申请**换房，选目标房间和**生效日期**。
2. 系统显示**钱**：新月租 + **换房费** − 旧租未用部分 credit
   = 一张**调整账单**（delta 精确）。另加押金差额。
   计费快照先跑，使 credit 成为真实账本分录。
3. **审批**后**执行**：
   - 旧租约终止，新租约开始。
   - **两个房间状态变化**（旧 → cleaning，新 → occupied）。
   - **押金按会员流转**。
   - 一张调整账单承载净 delta。
   - 完整换房历史显示在会员时间线。
4. 可选挂接退房/入住**检查**（§15）。
5. 执行前可**撤销**申请。

### 常见错误
- 选过去的生效日期却不期望计费快照。
- 忘了旧房间会进 *cleaning*（不是直接 vacant）。

## 19. 库存与采购单（M15, M29）

### 目标
物料管理，带**移动平均成本**和 **append-only 移动台账**。

### 谁在用
员工/Manager 做运营库存。会计看估值。PO 走 M29。

### 黄金规则
**绝不直接改数量。** On-hand 只通过**移动（movement）**变化：
`purchase · sale · consumption · maintenance_use · adjustment · transfer`。

### 库存部件与分类
- 部件按**分类**，带**单位**（单位目录可在
  Settings 配置）、**低库存阈值**和移动平均成本。
- 供应商被记录。采购可经**采购单（PO）**收货。

### 采购单（M29）
1. 创建 PO 给供应商（行 = 部件 + 数量）。
2. **下单（Place）**（只记应付 — 库存不变）。
3. **收货（Receive）** — 收货创建 purchase 移动并**改 on-hand**。
   **部分收货** 使 PO 保持 placed 直到收齐。

### 其他移动
- **Sale**（经 POS）、**consumption**（内部）、**maintenance_use**（工单上的部件）、
  **transfer**（仓位间）、**adjustment**（经盘点）。
- **盘点（stock count）**：实数 vs 系统。差异走**adjustment**，带
   估值 delta。
- **低库存提醒** 触发（并可 Telegram 通知员工）。
- **估值报告** 给出 on-hand 价值（移动平均）。

### 数字例子
进 10 → POS 卖 3 → 工单用 1 → **on-hand = 6**，估值报告
显示 6 的移动平均成本。

### 常见错误
- 试图直接改数量（不允许 — 用移动/盘点）。
- PO 只 place 就标记已收货（place 不改任何东西）。

## 21. 短住 / 酒店式预订（M32）

### 目标
把房间按**小时或按天**租给客人（酒店式），与长租并存。

### 概念
- **租住模块（Rent modules）** 定义产品：如 "hourly" 带计价策略
  （**progressive** 阶梯表 或 **blended** = 阶梯 + 全天结转）、
  最短/最长时长、默认押金、最少/最多人数。模块可全局或按物业。
- **Rate rules** 定义每个模块/房间/时段的价格。

### 预订流程
1. 创建**预订**：模块、房间、入住/退房、客人 姓名/手机/证件
   （可选关联会员信息）、可选押金。方式 **direct** 或 **tab**。
2. **价格估算** 算出价格。确认时价格被**快照**
   （延长时可重算）。
3. 预订编号 `STY-2026-0001`，状态：
   `requested → confirmed → checked_in → checked_out`，另有 `no_show / cancelled / void`。
4. 预付押金在 **check-out 时冲抵**。

> 该模块按物业启用。如果短住是你的业务，请咨询你的管理员。
