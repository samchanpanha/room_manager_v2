# 第 10 部分 — 故障排除

常见问题、可能原因、如何检查、如何安全修复。拿不准时，
**用审计日志并联系管理员**，而不是编辑已入账数据。

每项格式：**问题 → 可能原因 → 如何检查 → 如何修复 → 何时
升级上报。**

---

## 10.1 登录与访问

### "登录不了"
- **原因：** 密码错误（区分大小写）、账户被禁用、多次尝试后被限流、需要 2FA。
- **检查：** 仔细重输；如果碰到限流等一分钟；确认账户是激活状态。
- **修复：** 用正确密码；如果是管理员设的，提示时改掉；丢了 2FA 就请管理员**重置你的 2FA**，然后重新注册。
- **上报：** 账户被禁用或反复被锁 → Admin。

### "看到 403 FORBIDDEN / 菜单项缺失"
- **原因：** 你的角色缺少该模块/操作，或没被分配到该物业。
- **检查：** 对照矩阵（第 8.1 节）；确认你的**物业分配**。
- **修复：** 不是 bug — 向 Admin 申请权限/分配。
- **上报：** 如果你认为应该有访问权，Admin 修改你的角色/分配。

### 会员 OTP 提示"尝试次数过多 / 已锁定"
- **修复：** 申请**新 OTP**（码一次性，5 次后锁定）。

## 10.2 计费与账单

### "本月账单少了水电/服务费"
- **原因：** 生成前没录表读数；服务未分配；收费挂到*下一期*。
- **检查：** **Utilities** — 该期间有读数吗？**Services** — 该租约的分配是激活的吗？
- **修复：** 录读数/登记使用；它们会在**下一次**生成时计费。本期可按政策加合适的一次性行/credit。
- **上报：** 需要更正已出账账单 → 会计（**credit note**）。

### "生成了账单但某个租约没有东西"
- **原因：** 租约不是 **active**（还是 draft）；该期已计费（每租约-期一张活账单 — 生成是幂等的）。
- **检查：** 租约状态 = active；查该租约的计账期。
- **修复：** 生效租约；如果已计费，按设计不会重复创建。
- **上报：** 会计。

### "已出账账单金额错了"
- **修复：** **不要**尝试编辑/删除（已出账账单不可变）。用 **credit note**（≤ 应付，自动在零处结平）或 Super Admin **void**（必须带原因）。
- **上报：** void = 仅 Super Admin。

### "滞纳金/催收没生效"
- **原因：** 还在**宽限天数**内；滞纳金模式是 `none`；每日计费任务没跑。
- **检查：** Settings → Billing（宽限）和 Late fee（模式）；运行/确认 **billing-daily** 任务。
- **上报：** 会计/Admin 管任务排程。

## 10.3 收款

### "租户付了但余额没变"
- **原因：** 收款还在 **pending**（QR/网关未确认）；收款记在**错的会员/账单**上；webhook 没收到。
- **检查：** 打开收款 — 状态 pending vs confirmed；查网关引用和 webhook 投递；查**分摊**。
- **修复：** 确认 pending 的现金/银行收款；QR 经网关 webhook 确认（重复 webhook 安全忽略）。如果记错了会员，别删 — 用**refund/冲销**并重新正确登记。
- **上报：** 会计（退款/冲销、网关 webhook 检查）。

### "一笔收款被记了两次"
- **原因：** 手工重复录入。网关重复会自动忽略（幂等键），所以这只发生在手工录入。
- **修复：** **refund/冲销**多记的收款（Accountant+），会记纠正性的账本分录。
- **上报：** 会计。

### "会员付多了"
- **行为（不是错误）：** 多出的钱留在 **member credit**（会计可退）— **不是**收入。

## 10.4 合同与租约

### "无法生效租约"
- **原因：** 房间没空（已有生效租约/满容量）；会员 KYC 不完整（未 verified）。
- **检查：** 房间状态（应是 vacant/reserved）；会员 KYC 清单完整。
- **修复：** 选空房；完成 KYC 上传；然后生效。

### "无法结束/终止租约"
- **原因：** **未清欠款**（或经审批核销）；没有已完成的**退房检查**；押金未结算。
- **检查：** 会员余额 = 0；退房检查已完成；押金账本轧零。
- **修复：** 收/清欠款、完成退房检查、结算/退押金（扣款需凭证）。
- **上报：** 核销审批找经理；押金退款找会计。

### "房间状态卡在 cleaning / maintenance"
- **修复：** 把房间恢复 **vacant**（或完成维修）才能再出租；maintenance 设置时需要原因。

## 10.5 押金

### "无法退/扣押金"
- **原因：** 扣款需要**凭证文件 + 原因代码**；退款需要**会计审批**和收款方式。
- **修复：** 上传凭证并选原因；确保业主/会员有收款方式；把退款路由给会计。

### "退房后押金还挂着"
- **修复：** 已结租约的 **2100 Deposit Liability** 必须轧零 — 完成所有扣款 + 退款。

---

## 10.6 报表与数字

### "报表数字和预期不一致"
- **检查：** 筛选器（日期范围、物业）；报表权限范围（PROPERTY vs GLOBAL）；记住报表读**账本/实时数据** — 数据录入时数字会变。
- **修复：** 清除/调整筛选；等相关过账落账（如收款确认）；下钻到源（账单/账本/工单）。
- **上报：** 真正不一致的合计 → Admin/会计 + 查审计日志。
- 注意：**没有专门的资产负债表报表** — 用 **Ledger → Trial balance**（第 5.6 节）。

## 10.7 Telegram

### "Bot 不发消息"
- **原因：** 没关联；逐用户开关关了；开发环境发送端**mock 到 outbox**；dispatch 任务没跑；会员关联被禁用。
- **检查：** Comms → Telegram — 已关联聊天、开关和 **outbox**（状态/正文）；Settings → Telegram（`allowMemberLinking`）；bot token 密封密钥在不在。
- **修复：** 用新码重新关联；开开关；演示环境从 outbox 读消息；确保生产跑 **telegram-dispatch** 任务。
- **上报：** Admin（bot token、任务）。

### "关联码不工作"
- **修复：** 码一次性/短时效 — 申请新码并向 bot 发送 `/link <code>`。

## 10.8 文件

### "下载链接过期 / 提示 forbidden"
- **原因：** 签名 URL 只有 **120 秒**；你可能没权限（跨物业/仅 own-scope）。
- **修复：** 从记录里打开文件（签发新的签名 URL）；其他物业的员工被正确拒绝。
- **上报：** 如果你应该有访问权，Admin 审查物业分配/权限。

---

## 10.9 会计

### "账看起来不对 / 试算平衡"
- **修复：** 系统拒绝不平衡过账，所以问题通常是时序或缺少确认。用 **Ledger 日记账**（按科目/凭证筛选）和 **Audit Log** 追踪。用正规冲销（credit note / void / refund）更正 — **绝不编辑账本行**（数据库拦截已入账行的更新/删除）。
- **上报：** 更正找会计；审计链验证找 Admin。

---

## 10.10 通知 / 告警

### "Rent dues/逾期不显示"
- **检查：** 你需要 **M33 read**；告警遵守 **ahead/overdue 天数**设置（默认 3/1）。
- **修复：** 运行/确认 **rent-alerts** 和 **telegram-dispatch** 任务；查功能开关。

## 快速上报矩阵
| 问题 | 上报给 |
|---|---|
| 密码重置 / 2FA 重置 / 被禁账户 | Admin |
| 菜单缺失 / 403 | Admin（角色/物业分配） |
| 账单更正、退款、押金退款、业主对账单 | 会计 |
| 账单 void | Super Admin |
| Bot token / 密钥 / 备份 / 审计链 | Super Admin / IT |
| 网关/支付 webhook 问题 | 会计 + IT |
| 疑似篡改 / 安全事件 | Super Admin — 立即验证审计链 |
