# 第 9 部分 — 安全指南

面向管理员、IT 以及任何为系统安全负责的人。
涵盖认证、权限、会话、密钥、数据访问、审计和安全操作实践。
系统自身的安全说明在 [`docs/SECURITY.md`](../SECURITY.md)。

---

## 9.1 认证安全

| 控制 | 如何工作 |
|---|---|
| **密码存储** | 密码用 **scrypt** 哈希（绝不存明文）。 |
| **会话（Sessions）** | 数据库支撑的、**可吊销**会话；cookie 是 **httpOnly** 和 **SameSite**。会话在 `SESSION_TTL_DAYS` 天后过期。 |
| **登录限流** | 登录限流（**10 次/分钟/IP**），拖慢暴力破解。 |
| **强制改密码** | 管理员创建/重置的账户带 `mustChangePassword`，首次登录必须设新密码（然后吊销其他会话）。 |
| **2FA（TOTP）** | **Admin 和 Super Admin 强制。** 通过验证器 App QR 注册；验证码带时钟偏差窗口校验；管理员可为被锁用户 **重置** 2FA。管理员**注册前不能使用其他模块**。 |
| **会员门户登录** | 会员用发到 email/手机的**一次性密码（OTP）** — 码**哈希、一次性**、**5 次后锁定**（然后重新申请）。登录会创建其 MEMBER 用户。 |
| **Kiosk PIN** | 考勤 kiosk 用 **scrypt 哈希 PIN** 打卡，无需浏览器会话。 |

### 建议
- 给**每个**特权账户开 2FA（Admin+ 强制；鼓励经理/会计）。
- 新员工用**临时密码 → 强制修改**流程；绝不共享永久密码。
- 怀疑被入侵后轮换密码并吊销会话。

## 9.2 授权（权限）安全

- **每个 endpoint 都 RBDC：** `can(user, action, module, resource?)` 在
  服务端、每个 API 路由上运行。UI 隐藏只是方便。
- **范围限定防跨物业访问：** PROPERTY 范围角色
  （Manager/Staff）只能到达所分配物业；OWN 范围角色
  （Owner/Member）只能到达自己的记录。跨物业/跨业主访问
  返回 **403**（负向测试验证，含 IDOR 尝试）。
- **权限分离：** Staff 不能 void 账单、改角色或开
  账本配置；只有 Super Admin 能 void 账单；只有 Accountant+
  能审批退款/对账单；角色/权限变更需要 M01。
- 权限矩阵被 **CI 快照/负向测试锁定**，意外扩权
  会被抓住。

### 安全实践
- 遵循**最小权限**：授予能完成工作的最小角色/范围
  （如只有收款写的 "Cashier" 角色）。
- **有意地**给 PROPERTY 范围用户分配**物业**。
- 定期审查角色；**删除/禁用不用的角色和用户**。使用中的
  角色不能删 — 先移除其中成员。
- 记住有效权限是用户所有角色的**并集**。

## 9.3 会话与设备
- 用户可在 **My Account / Security** 查看其**会话与设备**
  （设备/IP、创建/过期），并**吊销**任何会话。
- 管理员可为用户吊销会话；改密码会吊销其他会话。
- 会话自动过期；**retention** 任务按设置清理过期会话。

---

## 9.4 数据与文件安全
- **文件存储：** 文件进私有存储（按环境选择 S3 兼容 driver）；
  下载用**短时效（120 秒）HMAC 签名 URL**。
  猜路径访问不了文件，跨物业访问被拒。
- **密钥（Secrets）：** 支付凭证和 Telegram bot token 存储前
  **用 AES-256-GCM 密封**，显示永远**掩码**；环境变量是兜底。
  密钥存在 env/secret 存储里，绝不在代码或聊天里。
- **PII 掩码：** 审计日志内的个人数据被掩码。
- **加密密钥：** 密封密钥需要 `SETTINGS_ENC_KEY` — 保护并
  在带外备份该密钥；没有它，密封密钥无法打开。

---

## 9.5 应用加固
- 应用了**安全头 / CSP**；限流也覆盖 webhooks。
- **Webhook 完整性：**
  - 支付 webhook 需要**签名密钥**（`x-webhook-secret`），并
    用**唯一网关引用 + 幂等键**，使重复/伪造
    通知被拒，收款**恰好确认一次**。
  - Telegram webhook **验证签名** — 伪造更新被拒。
- **会员 QR / 公开支付页：** `/pay` **限流**、只允许
  **精确应付金额**、无需登录、用 **HMAC 签名**的会员 token。

### 渗透测试清单（来自安全验收）
系统按以下标准构建并通过：跨物业 IDOR（403）、
权限提升（角色门控）、webhook 伪造（签名拒绝）、文件 URL 猜测
（仅签名 URL）。

---

## 9.6 审计与问责
- **每次变更都留审计**，含操作者、时间、前后值和 IP。
- 审计日志**只追加、带防篡改哈希链**；管理员可以
  **验证链**（`/api/audit/verify`，在 Security 下）。
- **审计历史永不被** retention 任务**清理**。
- 用审计日志调查纠纷、更正交易（通过正规冲销）、
  展示问责。

---

## 9.7 备份与可用性
- **每夜备份任务**快照数据库（保留**最新 7 份**）；恢复
  runbook：[`docs/BACKUP.md`](../BACKUP.md)。
- 生产目标数据库是 **PostgreSQL**（开发用 SQLite）；迁移
  **只增不改**，绝不破坏性。
