# 第 13 部分 — 黄金路径与实操场景

学系统的 fastest 方式是走**黄金路径（golden path）** —
正常的端到端旅程。然后用 20 个场景处理具体任务。

---

## 13.1 用户黄金路径（新员工 / 日常业务）

> 新员工学系统的最易方式。

1. **登录**（改掉临时密码；提示时注册 2FA）。
2. **查看仪表板** — 入住率、已收 vs 已出账、欠款、现金、租金欠款。
3. **管理物业与房间** — 确认房间空置/有价。
4. **登记会员** — 4 步向导 + KYC 上传（prospect → verified）。
5. **创建租约** — 会员 + 房间 + 租金 + 押金 + 服务；生效（房间 occupied、会员 active）。
6. **添加月度服务** — WiFi/停车/洗衣（按需）。
7. **录入表读数** — 本期水电。
8. **生成月度费用** — 账单生成（幂等、无缺口编号）。
9. **出账** — 会员在门户看到 / 收到 Telegram 消息。
10. **收款** — 现金/QR/卡；出具收据；账单 partial_paid→paid。
11. **账本自动更新** — 平衡分录；会员对账单反映它。
12. **记录费用** — 带收据的供应商成本（超阈值需审批）。
13. **处理运营** — 维修/投诉/检查/换房（随发生随办）。
14. **查看利润表** — 收入 − 费用 = 净利。
15. **查看试算平衡** — 借方 = 贷方（经 Ledger）。
16. **生成业主对账单** — 会计生成；审批；付业主。
17. **发通知** — 催收/提醒/Telegram（任务或手动触发）。
18. **跑报表** — 入住率、收款/欠款、rent roll、P&L 等；导出。

如果你能不借助 2 → 10，你就能运营前台。

## 13.2 Admin 黄金路径（系统初始设置）

1. **配置公司/组织** — 名称、法定名称、logo、账单模板（Settings → Org）。
2. **配置 locale** — 货币、时区、默认语言（en/km/zh）。
3. **创建 properties → buildings → floors → rooms**（用批量建房向导）。
4. **入驻业主** — 业主记录 + 收款方式；分配楼宇；创建业主合同。
5. **配置角色** — 审查默认矩阵；创建自定义角色（如 "Cashier"）。
6. **配置用户** — 用临时密码创建员工；分配角色 + 物业。
7. **配置租金引擎** — 计划、计租日、折算基准、滞纳金、税、折扣。
8. **设计费与催收默认** — 宽限天数、催收阶梯、账单前缀；rent-alert 窗口。
9. **配置会计** — 期初余额（平衡过账，如迁入）；核对科目表。
10. **配置支付方式与 provider** — 密封的 provider 密钥；确认 QR/webhook 设置。
11. **配置通知** — Telegram bot token（密封）、模板、会员关联。
12. **设功能开关与报表** — 开/关模块；把报表分配给角色。
13. **落实安全** — Admin+ 的 2FA、会话策略、限流、备份。
14. **排程任务** — invoice-generation、billing-daily、rent-alerts、telegram-dispatch、sla-sweep、attendance-sweep、statement-generation、retention、backup。
15. **端到端测试黄金路径**（§13.4 的 12 场景验收）。
16. **审查审计日志**并运行 **verify audit chain**；确认备份在跑（恢复测试）。

## 13.3 二十个实操场景

### 场景 1 — 创建新物业
**Portfolio → Properties → New**。输入唯一代码、名称、地址、可选 geofence。保存。现在可以加楼宇。

### 场景 2 — 创建新单元（房间）
打开物业 → **加楼宇** → **加楼层** → **加房间**（或用**批量创建**：前缀/起始/数量/床/类型/价）。设基准价和容量。房间以 **vacant** 开始。

### 场景 3 — 创建租户（会员）
**Members → New member** → 向导：个人信息 → 物业/紧急联系人 → **KYC 上传**（所有必填证件类型）→ 确认。会员是 **prospect**；KYC 完成翻为 **verified**。

### 场景 4 — 创建租约
**Leases → New** → 选会员 + 空置房间/床位 → 设开始/结束、租金、计租日、折算基准、押金分期 → 加服务 → 存 **draft** → **Activate**。房间 → occupied；会员 → active；押金开票；第一张账单排定。

### 场景 5 — 创建合同
生效租约会**生成会员合同 PDF**（自动归档到证件）。对房东，创建**业主合同**（FIXED_RENT 或 REVENUE_SHARE %、管理费、付款日）并**生效** — 这同步楼宇所有权。

### 场景 6 — 添加月度服务
**Billing → Services** → 建目录项；在租约上**分配**固定月费服务（WiFi/车位），登记**按次**使用（洗衣/访客停车）。固定服务在下一张账单计费；月中停用折算。

### 场景 7 — 生成月度计费
先录表读数（**Utilities**），然后 **Invoices → Generate**。该次运行对每个生效租约计费（月中开始的折算补算、每租约-期一张账单、无缺口编号、PDF 归档）。然后 **Issue** 账单。

### 场景 8 — 收租户付款
**Payments → New** → 选会员 → 输金额 → 选方式（cash/bank/qr/card/cheque）→ 保存。现金/银行立即确认；收据 `RCP-…` 归档；账单翻 partial/paid；账本过账；可发 Telegram 收据。

### 场景 9 — 记部分收款
同场景 8，但输小于应付的金额。收款按旧到新分摊；账单变 **partial_paid**，剩余仍应付。之后付清翻 **paid**。

### 场景 10 — 处理逾期付款
宽限期后 **billing-daily** 任务把账单标 **overdue**、加滞纳金（如已配置）、催收提醒触发（+3/+7/+14）。用仪表板 **Rent dues** 卡 → **Overdue & not paid** 报表追款；收到后记收款。

### 场景 11 — 改租金
不编辑已出账账单。在租约/租金计划上把新价设向**未来**（续租/新条款）；系统经合适工作流折算期中变更（如换房生成调整账单）。设置只向前生效。

### 场景 12 — 续租
租约到期时，完成/终止旧租约（清账 + 检查 + 押金结算后），创建下一个租约/条款 — 或按设置用自动续租条款。业主合同在条款变化时重建/生效。

### 场景 13 — 终止租约
发 **notice** → 清欠款到 0（或经审批核销）→ 完成**退房检查** → **terminate/complete**。房间 → cleaning；会员 → moved_out；结算押金（带凭证扣款 + 退款）。房间恢复 vacant。

### 场景 14 — 记费用
**Finance → Expenses & P&L → New** → 供应商、分类（映射到 5000/5100）、金额、日期、支付方式、收据附件、物业。低于 $500 自动审批并过账；超过由会计/经理审批。费用错了？**Void**（冲销）。

### 场景 15 — 查看利润表
**Reports → Profit & Loss**（或 Expenses & P&L）。按物业/期间筛选。读收入行（租金/服务/水电/滞纳金/其他）减费用和业主分成 = 净利。配合 **Expense vs budget** 对比。

### 场景 16 — 生成业主对账单
**Finance → Owner Statements**（Accountant+）。为当月 **Generate** — 每合同+月幂等。看公式（实收 × 分成 或固定租金 − 费用 − 成本 ± 调整）→ **Approve**（计提）→ **Pay**（冲 Owner Payable）。PDF 归档并显示在业主门户。

### 场景 17 — 通过 Telegram 发文件
挂在事件上的生成文件自动投递 — 如 `payment.confirmed` 上的**支付收据**和审批时的**业主对账单**。确保用户**已关联**且开关打开。（演示环境看 Telegram 界面的 outbox。）

### 场景 18 — 创建新系统用户
**Admin → Users → New** → 姓名/email + 临时密码 → 分配角色 + 物业 → 保存。用户首次登录强制改密码；Admin+ 必须注册 2FA。同一界面可禁用/重置。

### 场景 19 — 配置角色权限
**Admin → Roles & Permissions → 新建/编辑角色** → 勾选 **模块 × 操作 × 范围** 网格 → 保存 → 分配给用户。例：只有 M09 收款写的 "Cashier"。变更留审计；使用中的角色不能删；Super Admin 受保护。

### 场景 20 — 调查错误交易
1. 打开 **Admin → Audit Log**；按操作者/日期/实体筛选。
2. 读**前后值**，记下关联记录。
3. 打开源（账单/收款/费用）及其 **Ledger 日记账**分录。
4. 应用正确冲销 — **credit note**（账单）、**refund**（收款，Accountant+）、**void**（费用）— 绝不手改已入账行。
5. 如怀疑篡改，运行 **verify audit chain**（Security）并上报。

## 13.4 端到端验收走查（"黄金场景"）

这是系统自身验收测试的镜像 — 在演示环境跑一遍，看所有东西如何连起来：

1. Super Admin 创建组织（货币、时区）、物业 + 楼宇 + 3 间房；角色/用户（PM、会计、Staff）。
2. 入驻一位业主，为该楼建 revenue-share（60%）业主合同。
3. 入驻会员：KYC 文件 → 某房间的租约（月中开始），租金 300/月，押金 600 分 2 期，WiFi 15/月。
4. 生成账单 #1：折算租金 + WiFi + 一笔电费（表读数）→ issued → PDF 归档 → Telegram/门户。
5. 会员 QR 付 50%（webhook 确认一次；重复忽略），其余现金由 Staff 收。出收据；账本平衡。
6. 会员申请换房 → 批准（+10 折算）→ 一张调整账单；两个房间翻状态。
7. 会员发起投诉 → 转为维修工单 → 消耗 1 件库存后解决 → 关闭 → 会员评分。
8. 月末：水电入账、费用入账、P&L 生成；业主对账单 draft → approved → 分成已付 → 业主在门户看到 PDF。
9. 验证：试算平衡轧零；欠款报表一致；审计轨迹完整；Staff 用户被拦截 void 账单（负向测试）。

> 当这个走查顺畅跑完，员工就看到了**整个**业务
> 循环 — 从一间空房到拿到钱的业主 — 并理解了
> 每个模块如何喂给下一个模块。
